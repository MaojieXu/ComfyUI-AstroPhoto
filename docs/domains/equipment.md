# 设备与设备组合

适用于 AstroPhoto Extension / MCP 0.0.1；设备模型和接口以当前工作树与本文所列规则为准。

## 操作入口和数据规则

五类设备共用名称、产品名和备注表单，名称与产品名必填；名称区分具体设备，产品名可以重复。其他类型可记录导星设备、软件等。设备组合可引用其他类型设备。

设备和光路的列表工具栏共用节点页的 `SearchField` 和 `SearchOptions`。交互适配 ComfyUI Frontend v1.59.1 的 `SidebarTopArea`、`SearchInput.vue` 和 `FilterDropdown.vue`。两页分别保留搜索值及单选筛选，并沿用各自的查询参数。

- **设置 → 设备管理 → 我的设备**提供搜索、筛选、类型选择、新增/编辑和详情。备注可空，焦距和倍率等信息可记录在备注。
- **设置 → 设备 → 设备组合**提供列表、编辑器及当前配置详情。一个组合包括最多一台相机、一个主光学设备、一个附件和多个滤镜及其他设备；可保存不完整配置。配置含相机与主光学设备时显示为已配置，滤镜表示可用集合。
- 设备和组合原位更新，设备详情和搜索使用当前资料，支持归档与恢复。素材保存绑定时的组合成员和所选滤镜快照。修改设备或组合资料不会回写已有素材，重新绑定时从当前资料生成快照。
- 设备和设备组合分别校验名称。比较去除首尾空白，并采用 Unicode NFC 和大小写折叠。归档记录继续占用名称。表单说明名称必须唯一，发生冲突时在名称字段显示明确提示。
- 组合可保留或移除已保存配置中的归档设备。移除并保存后重新加入属于新增引用，后端会拒绝并标出对应字段。
- 未保存编辑在侧栏注册实例中暂存，在宿主关闭并重新挂载侧栏时恢复；切换模块/主视图时确认是否丢弃，浏览器硬刷新依赖浏览器的离开提示。已保存配置可跨重启。语言和配色由宿主设置控制。
- 设备与 Storage 共用数据库。设备或光路写入不会修改文件、工作区或导入设置。素材库可引用相机和光路并显式分配校准 Master。Capture Profile 和自动校准推荐属于规划。

设备及光路详情使用摘要卡片和可折叠分组。

## SQLite 基线

设备与摄影素材库共用数据根下的 `database/assets.db`。启动时核验实例身份、已知结构、外键和完整性，SQLite 使用 WAL 和每连接 3 秒的忙等待。V1 由 SQLAlchemy metadata 初始化，SQLite `user_version` 标识 Schema 版本。旧开发库无需迁移或保护，不兼容时报告 `DEV_SCHEMA_RESET_REQUIRED`，使用新的 Data Root 启动。

| 表 | 主要结构 |
| --- | --- |
| `storage_identity`, `storage_locations` | 实例身份、工作区根及写入代际 |
| `assets`, `asset_locations`, `storage_operations` | 资产、受管/引用位置、现有导入/迁移操作 |
| `equipment` | 设备 ID、五类枚举、名称、产品名、备注、归档、版本及时间 |
| `optical_trains` | 组合名称、备注、相机、主光学及单附件 ID、滤镜和其他设备 ID 列表、状态、版本和时间 |

设备写入先获取 SQLite RESERVED 锁（BEGIN IMMEDIATE），以条件 UPDATE 检查并发。光路保存验证组件类型，并在同一事务中更新同一份配置。设备创建和初次光路创建无幂等键，出现网络不确定时先核对列表。

设备详情提供永久删除。删除设备时解除设备组合、素材登记属性和校准主帧的当前关联，保留已有素材历史快照。删除组合后，普通列表及新绑定选择不再显示该组合，原名称可以复用。记录保留，可按原 ID 查回。归档保留名称并支持恢复。设备写入不以旧版本阻断，未提交字段保持不变。

## HTTP 与 MCP

调用方法、分页、权限和错误分别见[设备 HTTP 契约](../api/http/contracts.md#设备与设备组合)与[MCP 设备工具](../api/mcp/contracts.md#设备与设备组合)。设备更新使用字段级提交；归档及删除的调用需要指定对象 ID，MCP 先按名称解析。

实现入口为 [设备与设备组合服务](../../astrophoto/equipment/) 和 [HTTP 路由](../../astrophoto/api/equipment.py)，隔离验证见 [设备接口测试](../../tests/integration/test_equipment_api.py)。
