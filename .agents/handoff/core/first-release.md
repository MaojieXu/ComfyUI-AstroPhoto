# 初版发布工程边界

当前软件版本是 0.0.1。以下按现有工程基线整理初版发布涉及的实现、前置依赖和待验收结果。首发版本号、平台矩阵和完整功能清单仍需确认。当前已实现能力列在 [当前能力](capabilities.md)，执行证据及限制列在 [验证与证据](verification.md)。

| 工程链路 | 当前起点 | 发版前要关闭的缺口 |
| --- | --- | --- |
| 宿主加载与兼容 | V3 原生扩展、状态路由、单一前端入口、现有绘图与科学节点 | 固定目标宿主版本与最低支持范围。复验加载、状态降级、历史工作流像素重开，明确处理绘图 IMAGE 的现有路径问题。 |
| 本地存储与资产 | 工作区、缓存、reference/copy、受控迁移、设备与光路 | 按首发承诺确认会话、帧型和校准关联的实现范围。验收导入重复、权限拒绝、设备引用、卷离线与恢复，核对原件指纹。 |
| Siril 科学链 | 版本探测、FITS Source、候选预览、正式 AutoStretch、工作区回执 | 定下支持的软件与输入样本。真实宿主跑通候选、队列、产物登记、重开复跑，以及依赖不可用和取消等分支。校准、配准、堆叠需要独立节点和样本证据后才进入支持清单。 |
| 工作流与 MCP | 原生画布与队列、MCP 诊断及本机设备只读 | 外部工作流提交和在线改图各自需要连接、授权、目标、失败处理和真实回执。现有侧栏建图不能证明这些 MCP 链路。产品 Skill 按已验证工具清单验收。 |
| 独立后续域 | 当前还未交付知识、持久用户记忆、实验及 PixInsight 适配 | 如果纳入某次发行，分别验收知识出处与重建、记忆授权与删除、实验预算与复跑、外部软件能力与兼容性。 |
| 安装与发行 | lockstep 版本、本地构件校验、分开的 Registry 与 PyPI 包 | 在目标宿主独立验证安装和升级。先验证 PyPI 同版本 MCP 再发布 Registry，核对包清单和独立运行。具体命令与恢复见 [双包发行](release.md)。 |

一条可复验的完整手动链应交付可安装构件、能用的本地配置、一组有授权的代表性 FITS、原生工作流、正式科学结果及源文件未变化的证据。若同版本承诺 Agent 执行，还需一条独立 Agent 链，验证工具发现、调用授权、指定输入和真实回执。通过一条链不替代另一条链的验证。

工程依赖顺序是宿主与发行基础 → 资产及外部软件 → 科学节点与工作流工具 → 对应 Skills；知识、记忆及实验各自依赖其数据、授权或结果契约。给新实现定状态时，同步更新对应 Module 和 [当前能力](capabilities.md)。

## 当前工程优先项：官方 Vue 前端迁移

2026-11-21 定稿的 v1.3 要求优先完成活跃前端退出 React，保留当前界面风格和本轮纳入范围的流程。它约束下一步工程，并未改变当前实现。正式验收目标为 ComfyUI v0.46.0 + Frontend 1.59.6，并分别验证经典画布与 Nodes 2.0。官方更新版本仅用于参考，不替代指定组合。当前历史宿主验收仍是 0.45.0 / 1.59.1。

| 交付要求 | 迁移后应见证据 |
| --- | --- |
| FR-01 单一 Vue 技术栈 | 活跃源码、依赖树、构件、测试和 CI 都无 React 旧入口、专用工具及跨框架包装；绘图采用作用域原生控件，最终依赖以锁定安装和构建为准。 |
| FR-02 宿主侧栏和画布 | 单一原生侧栏、目录搜索筛选排序、预览收藏、拖放/点击添加和撤销，经典与 Nodes 2.0 保存重开。 |
| FR-03 存储及环境 | 现有配置可读写和重开，操作失败清楚；素材页本轮不交付，但仍支持现有 FITS 来源。 |
| FR-04 资料库 | 设备/光路归入资料库，领域校验留在其页面，列表、筛选、详情、空态、错误可独立复用。检查版本冲突、未保存提示及实际选择器窄栏与键盘。 |
| FR-05 Siril | 软件验证、FITS、Inspector、候选和正式队列仍工作。Widget 原生更新尊重撤销/只读，正式路径和科学元数据受兼容保护。 |
| FR-06 绘图 | 保存字段、键、像素、临时 PNG 引用及已有工作流不回归。该 Feature 验收到提交带 `[temp]` 的引用，后端 LoadImage 故障独立跟踪。 |
| FR-07 风格对照 | 保持导航、信息层次与主要操作顺序。相同主题、语言、宽度和业务状态逐模块对照；明显差异需确认。 |
| FR-08 处理 Bundle | Siril 专属实现归 `extension/siril/`。产品入口选择参与发布的 Bundle，公共层只消费通用接口。无 Bundle 或软件未验证时公共功能仍可加载。 |
| FR-09 复用依据 | 对每项提交上游版本、源码、许可与本地适配。宿主能力、可复用源码与需要自实现的差异分别解释。 |

### 草案中的实施顺序和待决事项

实施计划先建立可对照工作流、样本、视觉基线和复用清单，再接入空 Bundle 的 Vue 公共层，然后迁移侧栏/节点目录/绘图。存储环境设置与设备光路资料库可在公共层后分别迁移。接通 Siril 软件配置与节点生命周期后，将真实处理接线归 Bundle。最后切唯一生产入口、删除 React 及旧测试工具，迁移有效断言并审查发行构件。独立候选入口可用于迁移前后对照，同一宿主会话只启用一套侧栏和 Widget。

Q-01 已保留 Assets 标签和默认落点。现行 Registry 仅将 Bundle Python 运行代码与统一 JS/CSS、翻译一起交付。依赖和宿主脚本见 [开发](development.md)。

现行 Vue 构建和 Siril Bundle 已落地。Assets 保留标签和默认落点，以无请求占位交付。测量和剩余验收见 [验证](verification.md)。
