# Backend 需求、现行流程与验收边界

设备契约更新：设备使用类型、名称、产品名、备注和系统字段，支持相机、主光学、附件、滤镜及其他；组合使用单记录，单附件及多个滤镜、其他设备。设备旧规格和组合旧配置表已裁切，v0.0.1 旧数据库不迁移。独立 MCP 已适配名称操作，详见 `docs/mcp.md`。以下历史字段和测试细节以 `docs/equipment.md` 及当前源码为准。

## 需求与责任

天文摄影用户需要在不改动原始观测文件的情况下管理素材、设备和光路，并能把可复现的科学处理接进 ComfyUI 工作流。ComfyUI 持有工作流、节点注册和队列。AstroPhoto 后端持有资产身份、存储路径、配置、设备关系、操作状态和科学产物。底层以 `~/.astrophoto/` 为默认数据根，SQLite `assets.db` 保存身份、关系和回执，大图、FITS 和缓存留在文件系统。资产 ID 与根目录位置分离。

## 基础实现流程

### 宿主启动与降级

根 V3 入口的 `on_load` 装配扩展并注册宿主原生路由。初始配置根的 `config/roots.json` 记录有效根和入口路径，`root-catalog.lock` 协调记录访问，`<实例 ID>.lock` 防止重复打开实例。搬迁后的根以 `config/root-link.json` 定位同一记录。首建生成 `config/` 及两份配置 JSON、`database/assets.db`、`storage/Local/` 和 `runtime/locks/`。已初始化数据根在配置有效时，持实例锁补齐缺失的 `database/`、`storage/`、`runtime/`，随后打开根锁并继续业务装配。缓存按需建立，启动恢复允许跨会话的任务。启动失败时保留基础状态路由和节点注册。客户端读 `GET /astrophoto/v1/status` 判断能力，软件配置可访问与 Siril 已验证可运行分别报告。写入请求受可信本机部署和来源检查约束。 [跨端架构](architecture.md)

受信本机 `POST /astrophoto/v1/storage/init` 接收 `{}`，在当前有效根核对配置、数据库、存储和运行目录。按已登记的实际路径核对启用工作区，安全补齐必需子目录后复核并返回本次清单。位置记录与当前目录身份冲突时返回错误。外置工作区离线时保留登记，接回后可重试。 [MCP 概览](mcp-overview.md)

### 资产导入与原件保护

1. 用户在 Assets 选择服务器可访问的路径。POST `/astrophoto/v1/assets/import/preview` 预检在授权根内解析文件和目录，返回枚举文件数、失败数、字节估计，以及 copy 目标的空间信息。确认提交时校验来源、解析有效模式及 copy 的可写目标。后台开始复制前重新检查空间。预检只说明预检时的观察结果，实际执行会再次检查。
2. POST `/astrophoto/v1/assets/import` 以幂等键登记操作，返回 HTTP 202 和 operation ID。相同键与相同请求数据复用已有操作，内容冲突会拒绝。前端经 GET `/astrophoto/v1/assets/imports/{id}` 轮询阶段、回执和错误。reference 保留原位置，登记时记录来源身份，源不可用时可按外部引用规则重新定位。
3. copy 先租用工作区，逐文件暂存并核对大小、文件身份和源状态。发布前记录检查点，以无覆盖方式把暂存副本发布至工作区，再在同一数据库事务登记该副本及单项回执。发现未获本操作认可的目标时拒绝覆盖。看到已发布文件时仍需核实数据库登记。批次可保留先前成功的文件，并记录后续项的失败或跳过。
4. 发布后、数据库提交前崩溃时，恢复按已知检查点核对并补登已发布副本。资产与单项回执已提交但批次尚未写终态时，恢复按已处理数继续，避免再次登记该项。用户通过回执区分已完成、失败、取消与可继续恢复的操作。取消在检查点生效。单项进入 publishing 时继续核对发布和资产登记，再在后续文件边界处理取消。按阶段与终态共同判断状态，暂时 I/O 错误可能保留原阶段。导入复制和恢复都应保全原件。

工作区迁移另有权威切换点。目标核实后，在同一事务切换登记位置并记录 `committed`，再按 D-15 清理已迁受管副本。旧目录消失时仍校验目标。目标缺失或内容不符时回执保持待核验，可重试。工作区复检和快照报告缺件，活动迁移的两端均禁止解除登记。

工作区默认值以稳定 ID 保存。已登记的默认目录离线时保留记录，无自动备用卷。素材 copy 在受理时确定目标，Siril 正式处理在开始时读取默认 ID，设备目录只依赖 Data Root 内的数据库。外置卷拔插、重映射及设备、素材与 Siril 的组合验收仍待完成。

Windows Data Root 默认为宿主账号用户目录下的 `.astrophoto`，`ASTROPHOTO_HOME` 可显式选根。整库预检和停机执行共用库与文件校验，预检输出阻断详情，执行持锁复检。catalog 写入前中断时原入口恢复旧根，写入后原入口打开新根，旧根保留为快照。

存储 v1.1 已实现。正常启动读取有效根，整库搬家停机后执行并保留旧快照，旧根禁止继续写入。Workspace 完整或按量迁移冻结方案，校验并提交后自动清除已迁移受管源文件。空不足计划只提供显式最小可行超额。未设配额使用全部实际可用空间，配额设定后同物理卷共享额度与预留，目标不足手动切换。身份有效但缺件时允许确认降级重绑。本机存储无需旧启用变量或白名单。正常退出清空受管 Cache，正式资产与必要回执持久保存。目标宿主已验证自动切根和非空 Cache 退出清空，同卷/故障注入另有后端证据，真实双卷与拔插、压力验证延期。

### 设备、光路与正式处理

设备和光路写入由业务服务处理，包含字段校验、版本保护、引用约束和短事务。前端失败后可显示字段错误或重新读取版本，同一事务内的删除失败应回滚。MCP 经同一服务的授权 GET 读取 DTO。[MCP 概览](mcp-overview.md)

通用科学节点与路由独立解析现有资产或本机 FITS 路径。`extension/siril/` 经根入口可选装配，提供官方命令目录、CLI 节点、配置、比较预览和正式处理。通用命令按需加载、保存或发布目录；迁移保留同一会话的文件归组。候选任务供 Inspector 比较，PNG 放在可重建缓存。正式运行由 ComfyUI 队列调用 V3 AutoStretch，检查 Siril 可用性和受支持的 FITS 输入，在独立工作目录处理，核对输出后发布至工作区并登记。回执关联输入、参数、软件版本、哈希和资产 ID。异常或取消清理本次受控中间产物，已登记的旧结果和原件应保全。

正式输出按宽、高、通道数校验，并在回执记录实际 BITPIX。当前 Inspector 的分割依据是已知行序与部分坐标关键字比较，完整 WCS 和辅助 HDU 需独立验收。最终 Registry 的两种画布实测覆盖无 WCS 的 RGB 单节点；工作区迁移后的路径恢复和目标宿主双节点仍待复验。通过保存的资产 ID 可重新解析迁移后的路径，手工路径需要用户更新或重新执行上游。

## 证据与补发定位

- 临时真实文件、SQLite 和 aiohttp 测试覆盖授权拒绝、幂等、源变化、发布后登记前故障、迁移切换两侧故障及设备删除回滚。历史隔离宿主有跨卷迁移和 Siril 1.4.5 串联证据。本轮交接编辑沿用这些证据，目标宿主、真实 ACL、拔插、复杂工作流和大文件仍需各自复验。[验证](verification.md) · [初版工程边界](first-release.md)
- 审查事务、锁、检查点、导入回执及失败注入时，补发 `module/backend/implementation.md` 和 `module/backend/source-index-runtime.md`。涉及节点、HTTP、设备和科学处理函数时，补发 `module/backend/source-index-services.md`。测试代码和构建节点见 `module/backend/source-index-tests-build.md`。


两种导入方式都写入目录表，浏览器复制可按文件恢复。校准用途主帧使用相同资产身份写入图像与校准参数记录，校准绑定保护引用；目录汇总提供子帧组和单文件格式及位置供筛选。项目树的公开路由在 /catalog/projects，文件身份和位置由存储层维护。SQLite 0006 已清理旧集合、项目及校准关系。

项目目录支持 children 与 descendants 分页视图；后者返回逻辑父路径供 MCP 递归读取，目前会先枚举子树。

SQLite 0008 为普通主帧保存拍摄参数和来源组；校准用途继续从校准记录读取，类型切换事务内转移字段并保护来源引用。

SQLite 0009 的 asset_names 对四类素材登记全局唯一名称键；导入发布和重命名事务原子保留，删除触发器释放名称，单张子帧不占用名称。

SQLite 0010 将受管子帧组目录归属独立登记。空组可继续追加，目录改名和工作区迁移使用同一归属。可确定的发布前冲突写入逐项失败回执，可能已发布的文件继续走持久恢复。

受信本机 GET /astrophoto/v1/storage/operations 返回所有进行中及最近 16 个暂停或结束的导入、复制直传和迁移任务回执，供侧栏任务框轮询。删除位置迁移的完成响应附 operation_id，原同步迁移和事务语义保持。

设备组合删除通过 0004_deleted_trains 保存删除标记和历史引用。素材绑定失败可在新子帧组详情补绑。

目录 API 先分页摘要，再补齐当页文件位置及子帧统计。项目引用兼容只有校准记录的历史主帧，继续使用原资产 ID。

目录注销按详情版本校验，整组注销集中清理反向引用并分批删除登记。永久删除设备时检查校准主帧的直接相机引用。

项目删除重验影响令牌，浏览器直传按持久化目录身份恢复。0011 补齐旧导入组目录成员。子帧详情联表读取。
