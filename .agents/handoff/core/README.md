## 按当前问题加入上下文

- **与仓库无法互查时。** 只发送 Core 时，从本入口、项目概览和相关端概览入手。需求边界看初版工程范围，历史实测与待核实项看验证页，定位源码职责时查仓库树。
- **判断变更影响时。** 给出当前问题、涉及的一条真实调用链、提供方和调用方契约、相应测试与最近证据。用 [仓库地图](repository-map.md) 确认还涉及配置、迁移、构件、翻译或 CI 哪一侧。
- **提决策或审查具体代码时。** 同时给出当前行为、失败分支和预期差异。若本包没有能区分选项的源码、DTO 样例或测试断言，指出需要提供的文件、符号、环境和证据。结论标明是实现事实、历史验证、设计草案还是未核实。
- **延续长讨论时。** 保留已接受决定、仍影响本任务的约束和待补证据。下轮按新问题加入相关内容；整份交接可持续访问，单轮只加载会改变判断的信息。

## 本包怎样处理新旧材料

| 证据类型 | 使用方式 |
| --- | --- |
| 当前工作树和发行配置 | 判定实现、请求参数、权限和编译/发版入口。旧概述与源码有冲突时，采用当前可观察行为。 |
| 最新已定稿 Feature | 判定已确认的目标、验收和范围排除。当前优先项为 Vue 前端迁移 v1.3，目标和实际状态见 [初版工程边界](first-release.md)。 |
| 技术及实现草案 | 保存候选接线、顺序、依赖、待决事项及受影响范围。变更未进入源码或构件时保留草案身份。 |
| 项目文档和开发记录 | 接收仍有效的工程决定、约束、失败边界和可复用证据。记录来源的环境与适用范围，淘汰被后续决定覆盖的描述。 |

本轮对账涵盖现有架构、开发、发行、MCP、侧栏、存储、设备光路和 Siril 文档，以及 Feature 和工程任务记录。接手时以 [决策与交互风格](decisions.md) 判断必须保留的约束，用 [当前能力](capabilities.md) 避免把旧缺口或未来目标误当现状，使用 [验证与证据](verification.md) 确认真正执行过的范围。
