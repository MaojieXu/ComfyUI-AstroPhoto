## FR-10 全量 Siril CLI 节点

全部 Siril 1.4.5 可在 headless 脚本执行的命令各有一个可搜索、可原生排队的 ComfyUI 节点。目录附命令语法、输入前提和构建条件，GUI 专用命令提供说明。图像在节点间使用文件路径。需要当前图像的命令接收路径并执行 load → 命令 → save。文件和序列命令接收暂存文件或目录，产出文件路径、目录或日志。需共享状态时可组合同一 CLI 会话。此项扩展原单帧范围，AutoStretch 工作流保持兼容，以下科学输出待评审项继续追踪。

## 背景、目标与使用者

操作者需要在 ComfyUI 中验证专业软件可用、比较拉伸候选并将得到的科学 FITS 接给后续节点。成功信号是变更参数时比较的确为当前输入，正式输出可追溯、输入未改动且能串联与复查。

操作者安装并选择本机可信 Siril、维护工作流和决定是否提交。ComfyUI 管队列与节点编辑权限，Extension 验证文件和软件、生成候选及正式产物。外部 Agent 无 CLI 运行权限。

## 业务对象及集成边界

Siril 配置包含服务器 OS、选中 CLI、验证版本与状态。FITS 来源可为 Asset ID、合规服务器绝对路径或已有下游 `IMAGE_PATH` 输出。候选任务绑定输入版本与节点参数，产出显示 PNG；正式执行有运行 ID、FITS、Workspace 位置和结果回执。候选与正式产物有不同生命周期和证据。

## FITS 保真的评审边界

| 层 | 已有承诺与当前能力 | 待评审 |
| --- | --- | --- |
| 原始输入 | 只读原件。正式执行核对输入版本和 SHA-256，通过工作副本处理。处理前后原始文件的字节和标记应保持。 | 候选与正式队列之间是否要求锁定同一输入版本，见 Q-02。 |
| 正式科学像素 | AutoStretch 有意改变像素，正式文件仍为科学 FITS，宽、高与通道数须与输入一致。回执记录实际 BITPIX、选定头字段、源和结果的摘要。 | 位深或物理缩放可接受的变化、非有限像素的规整和披露、辅助 HDU 处理，见 Q-01。 |
| 天球坐标与成像元数据 | 当前选定字段写入回执，分割使用行序规则和一组坐标关键字比较。两者均缺 WCS 时仍可能可分割，现有比较不能证明天球坐标一致。 | 确认哪些字段缺失或变化应拒绝登记、提示或仅影响分割。尤其区分无 WCS、等价写法及真实坐标偏移。 |
| 屏幕代理 | 最长边和 8-bit PNG 仅用于显示。可查看前图，后图失败不改变输入；代理像素不能用于声明正式 FITS 的位深、数值或科学元数据。 | 对齐判据和正式结果标签按 Q-01、Q-02 验收。 |

## 主要场景

- S-01 进入 Software 查本机安装指引、探测或输入完整路径；经真实能力验证后保存，失败保持当前配置。
- S-02 添加 FITS Source 或 Image Path，再连 AutoStretch。修改阴影裁剪、目标背景、RGB 联动，按当前输入更新候选。
- S-03 打开 Inspector，比较并排、分割或单图，平移和缩放；参数写回当前节点，可重置，尊重只读和单色限制。
- S-04 经原生队列生成正式 FITS，在活动 Workspace 查询回执和资产。工作流保存重开，来源和参数可重新解析，正式输出可接下一节点。
- S-05 用户打开含多个可读图像、缩放头或无效像素的 FITS，确认处理的是哪一幅图，理解结果是否仍适合下游分析。
- S-06 用户在 Queue 等待期间改默认工作区，或前一个节点成功、后一个节点失败。需要看清每个结果的去向，决定重试范围和先前产物的用途。
- S-07 用户重启宿主后追查历史结果，核对资产、回执和文件，处理失败残留或缺失产物，并在确认引用关系后释放空间。
- S-08 用户通过多个页面编辑 Siril 设置、禁用能力或更新二进制，预期看到最终生效配置和已有任务的处理结果。

## 状态、权限与异常规则

首期支持可读取的二维单色或三通道 RGB 单帧 FITS，默认阴影裁剪 -2.8 σ、目标背景 0.25、RGB 联动开启（单色不适用）。仅当对齐可证实才启用分割；无把握时保留并排或单图。折叠、聚焦、仅查看 Inspector、平移和缩放本身不触发重算。候选缓存和正式 FITS 分离，旧任务迟到不得替代最新候选。当前全局 PNG 最长边可选 512、1024、2048、4096 或原尺寸，默认 1024；画布展示参考上限 480×320，PNG 与布局均不定义科学输出精度。可信本机绝对 FITS 可位于导入根之外，素材导入仍受其自身授权根。原图保全。尺寸、位深和关键元数据以实际导出检查及回执为准，不能承诺 Siril 原样保留全部 Header。

**Verified · FITS 读取边界。** 当前工作树选取首个符合条件的图像 HDU；处理副本可把所选图像放入主 HDU，非有限像素在显示及处理副本中被处理。输出科学数据、被处理像素与 Header 的可接受损失尚需 Q-01 确定。候选自动跟随目前只覆盖明确支持的来源或已经执行且参数未改的直接上游；不能因正式路径可串联就承诺任意路径生产者及子图均有自动候选。

## 交付范围与非目标

Siril CLI 1.4.5、单帧 FITS、画布与 Inspector、Native queue、正式资产和回执。保留其他科学格式、丰富类型、PixInsight、自动校准或序列、跨子图自动候选与 Trial 管理为未来事项。Windows 以历史样本为证，当前工作树与其他平台需单独验证。MCP 诊断与原生 ComfyUI 队列归各自宿主能力，Siril 发现和处理没有外部 Agent Tool。

## 功能需求与验收

### FR-01 Siril 探测、校验与配置

**状态、必要性及场景** Confirmed · 首版必要 · S-01。

可查适配当前服务器 OS 的安装信息，自动探测或手工提供 CLI，实际能力验证成功才启用；清除或失败有清晰反馈。

**验收** 实际 Siril 1.4.5 探针通过；GUI 路径、错误版本、取消或超时无法覆盖原有效配置。 [CASE-01](05_TEST_PLAN.md)

### FR-02 FITS 来源、候选与 Inspector

**状态、必要性及场景** Confirmed · 首版必要 · S-02/03 · FR-01。

已登记或合法手工路径可形成候选，入口绑定当前参数。Inspector 支持三视图、缩放、平移、参数同步和重置；只读和单色约束贯穿节点及面板。

**验收** 参数改变仅展示最新输入的候选；单色禁用联动，WCS/方向不确定时禁用分割；只读不修改 Widget；开面板和查看本身不重算。 [CASE-02](05_TEST_PLAN.md)

### FR-03 正式 FITS 处理、持久化与串联

**状态、必要性及场景** Confirmed · 首版必要 · S-04 · FR-01。

正式队列消费原尺寸 FITS，保护输入，产出正式 FITS 和运行回执。仅在结果有效时公开并登记，输出路径可被下游消费。

**验收** 两节点串联，第二输入等于首节点结果；输入 SHA-256 不变；输出尺寸、位深及可核对元数据有记录。故障不能覆盖已发布结果。 [CASE-03](05_TEST_PLAN.md)

### FR-04 FITS 输入可解析性与持久兼容

**状态、必要性及场景** Inferred · 首版必要 · S-02/04。

清楚区分 Asset ID、临时路径与工作流保存值。重开时识别已登记文件的位置与可用性、支持受控本机路径，缺失/损坏/不适用时给明确反馈。

**验收** Asset 移位后用同一 ID 恢复时可处理，丢失时不静默取同名图；损坏及不兼容数据拒绝。旧 `ASTRO_FRAME`/普通 STRING 连线需显式处理。 [CASE-04](05_TEST_PLAN.md)

### FR-05 全局显示配置与任务恢复

**状态、必要性及场景** Inferred · 首版必要 · S-03/04。

画布和 Inspector 共享 PNG 显示设置。用户可查看候选申领、失败、取消和重试结果，正式任务使用可追查回执与登记。资源不足应显示反馈。

**验收** 改变长边只影响显示代理；并发改参时旧候选不会覆盖，删除缓存可重新生成。中断后可核查已登记成功项与孤立失败项，原件不变。 [CASE-06、07、08、11、12、13](05_TEST_PLAN.md)

### FR-06 输入语义与比较可信度

**状态、优先级及场景** Proposed · 建议作为首版验收门 · S-02、S-03、S-05 · FR-02、FR-04。

用户应能了解实际处理的图像 HDU、通道解释、失效像素处理及适用的对齐等级。欠缺空间对齐证据时保留可用的并排或单图。显示拉伸范围、更改像素的 AutoStretch 参数和正式产物的科学含义分别呈现。

**验收提案** 多图像 FITS 走所选策略并记录实际 HDU。整数 BLANK、浮点非有限值和超出显示范围的样本给出明确结果。用无 WCS、等价 WCS、坐标偏移和未知行序分别验证分割开关。 [Q-07～09、Q-17](#本轮待决问题) · [CASE-10](05_TEST_PLAN.md)

### FR-07 运行身份、提交与恢复

**状态、优先级及场景** Proposed · 建议作为首版验收门 · S-04、S-06、S-07 · FR-03、FR-04。

**验收提案** 在受理前、结果发布后登记前、登记后响应前分别中断。按选定策略核对运行、文件和登记三方，确认旧结果和源哈希。 [Q-10、Q-11、Q-15、Q-18](#本轮待决问题) · [CASE-03、CASE-07、CASE-14](05_TEST_PLAN.md)

### FR-08 结果找回、管理与诊断

## 源码边界与架构评审

以下为当前 `4c0cf4d` 加工作树的静态走查。表中只把可直接从代码判断的行为记为「现行」。竞态后果、平台能力及资源极值仍需实测。优先级为评审建议，P0 表示影响结果正确性、可追溯性或可恢复性，P1 表示体验、规模或支持范围。

| 编号 | 现行实现与具体边界 | 产品影响、建议和验收入口 |
| --- | --- | --- |
| E-01 · P0 · 选错图也可能成功 | `image_hdu` 取第一个可用二维图像或首维为 3 的图像，按形状判定三通道。回执的 `FitsInfo` 缺少选中 HDU 的索引和名称。扩展图升为主 HDU 时，工作副本可只带所选图。 | 多个可处理 HDU、非 RGB 的三平面和二维 CFA 都需要明确口径。用多个图像和不同头部语义测试实际选择。Q-07、Q-10。 |
| E-02 · P0 · 可读形状不等于预期科学结果 | `prepare_fits` 会在副本规整非有限物理值。非零 BZERO 的特定分支会改用 float64 并移除缩放和 BLANK 字段。当前没有单独记录无效像素计数或掩模。常规处理的 `check_output` 只校验形状，探针另会检查样本像素是否被改变。 | 正式结果需区分拒绝、规整并披露、保留有效性信息。全无效、常量、缩放和混合有效样本分别验收。正常的无变化结果也需独立定义判断口径。Q-01、Q-08。 |
| E-03 · P0 · 分割可能被误读为已证实对齐 | `_aligned` 比较一组坐标键的文本，两边均无键也可相等。已知行序有归一转换，未知行序的 PNG 仍可能显示。形状校验与 Header 文本比较无法验证完整坐标映射。 | 首版需决定何种证据允许分割，单独标记方向未知或仅像素对齐。用无 WCS、等价 WCS、真实坐标偏移和未知行序测试。Q-09。 |
| E-04 · P1 · 显示差异可能被误判为处理差异 | `render_png` 将物理值映射为 8-bit 并裁剪；浮点显示按 0～1 裁剪，整数按 BITPIX 推出的除数归一。它先分配原尺寸字节数组，再生成缩略图。 | 负值、值大于 1、不同编码和高动态范围需验证明暗表现。设置更小 PNG 不能直接推断峰值内存下降。Q-03、Q-17。 |
| E-05 · P0 · 三种身份有不同寿命 | `resolve_input` 解析 Asset ID 或路径，候选和缓存复用用文件 stat 指纹，正式执行处理时用 SHA-256 核对原件。当前接口没有把候选版本带入 Queue。正式结果展示再次校验输出摘要，后续媒体读取检查源和结果文件的 stat。 | Asset ID 可以保持稳定，路径会迁移，文件内容可以变化。要能区分路径变化且字节相同、身份不变但内容已换、路径或登记不可用。Q-02、Q-06、Q-10。 |
| E-06 · P1 · 预览可用范围小于正式 Queue | `sourceId` 识别直接 FITS Source、Image Path 或经过前端校验的上游 AutoStretch；后者缓存在节点 WeakMap。正式节点消费 `IMAGE_PATH`，并不依赖上述前端识别。选择器当前逐页取完全部 FITS 资产，再填充原生下拉。 | 第三方节点、子图、重载、已登记同名资产和大目录需要分别确认交互与支持范围。Q-16、Q-19。 |
| E-07 · P1 · 预览的取消与资源占用不同步 | `PreviewService` 为每次请求开线程，同 owner 新作业通知旧作业停止。任务回收阈值针对终态记录，未构成全局并发硬限制。只用设置或折叠状态不足以描述浏览器断线、迟到响应和 Cache 清理后的行为。 | 将前端中止、工作线程退出、PNG 回收和正式任务取消分别验收。用多 owner、掉线、清理中 Cache 和源切换覆盖。Q-03、Q-16。 |
| E-08 · P0 · 软件操作顺序可能与点击顺序不同 | `save` 先探针，后锁内读取当前设置并写入，同时开启 Siril。请求不携带用户开始编辑时的 revision。清除配置只移除验证记录，独立启用标志可保留。 | 较慢的保存在较新的禁用或清除之后完成时，可能恢复启用。需要定义冲突、验证与启用，以及哪个动作优先。Q-05、Q-13、Q-20。 |
| E-09 · P0 · 禁用和更新可能影响新旧任务不同 | 新任务读启用或配置状态，正式 `stretch` 的运行检查点核对已捕获的程序指纹。禁用或清除配置没有在同一检查点重新读取。历史正式文件的存储读取和当前 Siril 预览新请求也走不同入口。 | 决定禁用拦截新任务、对运行中任务的影响以及历史输出继续可见的方式。二进制被替换需单独测重验。Q-13、Q-14、Q-20。 |
| E-10 · P0 · 队列整体状态不代表各结果 | `formal_run` 在每个节点执行时读取默认工作区，租约覆盖该次写入。前一个节点已登记的结果与后一个节点失败没有当前的整图回滚契约。 | 排队中切换默认位置及串联跨根时，需记录每个节点的真实目标根、部分成功和后续重试范围。Q-15、Q-18。 |
| E-11 · P0 · 文件、回执和登记之间存在提交窗口 | 写 running manifest 后处理，随后发布 FITS、写 completed manifest，再事务写 Asset 和 Location。启动恢复跳过已有 Asset，仅对有归属的未登记目录清理。离线或忙卷可跳过当次扫描。 | 需要区分发布后未登记、已登记但响应丢失、已登记结果缺失等状态。须明确恢复再触发、时间点与保留证据。Q-11、Q-18。 |
| E-12 · P0 · 成功产物的管理入口有限 | 当前 Asset ID 和 manifest 可追踪结果，但 Assets 页仍为占位，Siril 没有正式运行台账。Cache 清理独立于工作区输出。现行恢复检查有无 Asset 登记，未形成已登记结果的完整性审计。 | 重启后要能找回、诊断或导出回执。删除需判定正式输出、失败残留和受引用数据的边界。Q-11、Q-12、Q-19。 |
| E-13 · P1 · 支持范围与诊断披露需有口径 | 能力探针验证固定版本和小 RGB 样本。程序路径、运行环境、退出状态、FITS 选定元数据及回执所在层不同。已核实的真实运行主要是 Windows。 | 宿主、平台、版本、正式队列、科学样本需要独立证据；对外诊断包须明确路径、元数据和日志披露。Q-10、Q-14、Q-19。 |
| E-14 · P0 · 受信根与用户操作需保留原约束 | 当前处理走可信本机、受控 CLI 和工作副本。直接科学路径与素材导入根使用不同契约。正式发布及清理分别消费 Workspace 与 Cache 的所有权规则。 | 保留本机单用户、原件保护、无备用卷静默写入及按归属清理。把受信素材解析、无 Siril Bundle、只读宿主和移除网页分别纳入回归。此处沿用既定边界。 |

### Q-01 科学输出有效性

**当结果 FITS 的位深、WCS 或辅助 HDU 发生变化时，何时允许它登记为正式资产？** 所有选项都要求源字节保持、输出可读且尺寸和通道数匹配。当前代码用形状和通道作为输出校验，回执记录实际 BITPIX 和选定头字段。

| 选项 | 选择后的行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 关键项失败即拒绝（推荐）** | 列出必保科学属性并逐项验证。例如输入存在可用 WCS 时要求坐标映射在约定容差内。其他差异写入回执，对齐无法确认时限制分割。 | 保护影响后续定位和分析的关键信息，也容许可解释的头字段改写。 | 需要进一步确认必保字段、WCS 容差以及位深、辅助 HDU 和非有限值的规则。新增校验也会阻止一部分当前可用输出。 |
| **B · 严格保留头字段、位深和辅助 HDU** | 除像素变化所需的校验和与运行历史字段外，只要已定义的 Header、位深或辅助 HDU 结构有差异，就拒绝登记。 | 验收标准容易理解，适合依赖既定文件结构的下游流程。 | 等价 WCS 写法或常规格式整理也可能触发拒绝。部分真实样本可能需要额外适配或无法通过。 |
| **C · 基础校验通过即登记** | 通过可读性、尺寸和通道校验后登记。把检测到的位深、坐标和 HDU 差异作为提示与回执内容。 | 允许更多 Siril 输出进入后续处理，与当前登记行为最接近。 | 使用者需要自行判断差异。下游如果忽略提示，可能继续使用坐标或辅助数据已改变的结果。 |

**验收影响** FR-02～04，CASE-10。用完整 Horsehead 和仅主 HDU 的版本、浮点、缩放、非有限值与多 HDU 样本，逐项记录哪些情况登记、拒绝、警告或禁用分割。 [样本与断言](05_TEST_PLAN.md)

### Q-02 预览与队列使用的输入版本

**候选完成后，同一个路径或 Asset ID 指向的内容被替换，正式队列该处理哪一版？** 这里讨论的是处理前的变化。复制和正式处理期间检测到源变化仍应失败。

| 选项 | 选择后的行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 拦截变化，确认新版本后重提（推荐）** | 有可关联候选且文件内容已变化时，本次队列停止并提示。浏览器刷新候选，用户重新提交。无候选的独立 Queue 继续按执行时输入处理。 | 与用户刚看过的预览保持一致，同时保留无需预览的原生队列用法。 | 需要把可验证的候选身份带入队列。输入频繁更新时可能多次提示和重提。 |
| **B · 执行当前版本并提示差异** | 队列重新解析并处理当前输入。有可关联候选且输入版本不同，显示变化提示，回执写入预览版本和正式使用版本。 | 减少阻塞，适合文件不断更新的自动化流程。 | 用户可能在看到提示前已生成不同于所审候选的产物。无关联候选时只能记录实际处理版本。 |
| **C · 保留候选使用的内容快照** | 为可提交的候选保存输入快照，正式队列按快照执行。快照失效时提示重新生成候选。 | 可复现已预览的版本，适合处理期间可能被外部程序更新的文件。 | 大 FITS 需要额外空间和读写，还需定义快照保留期、授权变化和 Cache 清理后的行为。 |

**验收影响** FR-02～05，CASE-06/11。测试候选后同路径换内容、同 Asset ID 重绑和独立 Queue。并发变更场景需验证成功回执记录的是实际使用的源摘要。 [测试计划](05_TEST_PLAN.md) · [素材 PRD](../04-equipment-optical-trains/01_PRD.md#06-assets)

### Q-03 资源与并发反馈

**遇到大 FITS、空间不足或多任务争用时，何时等待、取消或拒绝？** 当前处理受实际 Cache 和磁盘容量约束。已确认范围撤销过固定资源和并发硬上限。

| 选项 | 选择后的行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 按实际资源运行并提供反馈（推荐）** | 按可用空间和资源检查启动处理，显示等待、运行、取消或资源不足。正式队列沿用宿主取消。 | 适配不同主机，可保留大图能力，沿用现有决定。 | 高峰时的吞吐和等待时间难预测。需要为资源失败与取消补齐反馈和实测。 |
| **B · 允许管理员配置资源上限** | 提供本机可调的并发及资源上限。并发已满则等待，单个任务超出配置预算则拒绝，并显示触发原因。 | 可保护共享工作站资源，管理员能为具体设备选阈值。 | 增加配置、排队和超限恢复成本。配置过紧会阻止可处理任务，需验证不同主机和级别。 |
| **C · 首版采用实测后的统一上限** | 对受支持环境设置统一上限，达到上限时明确拒绝。上限由代表性样本测试后确定。 | 支持与复验范围清晰，故障较易复现。 | 需要重新评审 D-03。统一阈值会限制资源充足的主机，也可能无法保护较弱设备。 |

**验收影响** FR-05，CASE-12。测磁盘耗尽、并发抢占、等待和取消，再分平台确认子进程清理。若选 B/C，另测上限上下边界和持续提交。 [测试计划](05_TEST_PLAN.md)

### Q-04 画布尺寸配置

**除 PNG 最长边外，用户是否还需要单独设置画布上预览的显示宽高？** 当前读取固定默认 480×320，API 可校验传入尺寸但未持久化。

| 选项 | 选择后的行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 固定默认布局并保留自适应（推荐）** | Environment 只保留 PNG 最长边设置。明确收敛旧画布尺寸写入契约，控件继续按可用空间适配。 | 设置少，两种画布表现更一致，布局和接口复验范围较小。 | 高分辨率屏幕、窄画布或有个人排版需求的用户无法设定独立尺寸。若旧尺寸配置确为正式承诺，需记录兼容处置。 |
| **B · 恢复可配置的画布宽高** | 在 Environment 提供独立宽度和最大高度，持久化设置并支持重置。PNG 长边仍独立配置。 | 用户可按工作空间和显示器定布局，恢复旧文档描述的能力。 | 增加设置迁移、修订冲突与窄画布适配。需要同时验证经典画布、Nodes 2.0、重开及默认值兼容。 |

**验收影响** FR-05，CASE-08/13。检查合法与非法尺寸写入、重新加载、两种画布及短边不足时的视觉结果。无论选项，正式 FITS 尺寸均按输入校验。 [测试计划](05_TEST_PLAN.md)

### Q-05 配置提交的取消边界

**服务器正在验证新 CLI 路径时，用户能否取消并保证旧配置保留？** 当前离开页面只结束客户端等待，服务器仍可能完成已提交的保存。

| 选项 | 选择后的行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 提交前可撤销，提交由服务端完成** | 提交前可以放弃编辑。提交后离开页面时明确告知验证仍可能完成，再次进入读取服务器状态。验证失败保留旧配置。 | 延续现有同步接口，操作成本和实现改动较小。 | 用户提交后无法撤回。需要复审现有 FR-01 关于取消后旧配置保留的验收语义。 |

### Q-08 无效像素、参数边界与退化结果

### Q-09 分割视图的对齐标准

| **B · 分开声明像素对齐与天球坐标对齐（推荐）** | 有 WCS 时验证坐标映射；无 WCS 且明确证明栅格与方向未变，可标记「像素对齐」并分割。仅一方有 WCS、映射失败或方向未知时默认并排。 | 需要可验证的栅格证据、容差和清楚文案。两种对齐级别都需测试。 |
| **C · 默认并排，用户可手动开启实验分割** | 显示未证实对齐的提示并由用户决定。适合肉眼研究有位置偏差的结果。 | 用户仍可能把界面效果当科学结论。该选项需要明确调整 D-02 中的对齐约束。 |

**验收影响** FR-02、06，CASE-02/10。分别验证等价坐标写法、中心与四角真实偏移、两边无 WCS、单边 WCS 丢失、未知行序和单图回退。Q-01 决定能否登记，本题决定如何比较。

| 选项 | 行为与优点 | 缺点与代价 |
| --- | --- | --- |
| **A · 每次显式 Queue 都是新运行（推荐首版）** | 运行 ID 唯一，给出原有结果查找或确认方式。参数一致也可独立对照；兼容当前行为。 | 用户遇到响应丢失后重试可能产生副本。需先能查回已提交结果，并与保留策略配合。 |
| **B · 仅相同提交令牌的重试找回原运行** | 重传同一提交使用同一身份；明确发起新的 Queue 仍生成独立结果。减少网络异常后的重复。 | 需要可靠区分重传和真正重新提交，并定义令牌寿命、跨宿主重启和多节点身份。 |
| **C · 相同输入、参数和环境默认复用** | 减少重复处理和磁盘使用。 | 需要证明源内容、HDU、软件和记录的等价，且目标工作区、既有结果完整性及用户期望都需参与规则。与当前独立运行语义差异最大。 |

**验收影响** FR-03、07，CASE-03/07/14。覆盖同参数重复、故障后重试、登记后响应丢失、清理后重试、先成功后下游失败和部分产物找回。A 不推断宿主自带跨重启结果查找。

### Q-19 历史产物、错误和诊断从哪里查看

**首版应在哪个入口复查正式结果、失败原因和脱敏诊断？**

| 选项 | 行为与优点 | 缺点与代价 |
| --- | --- | --- |
| **A · 复用原生 Queue/History，给出本地回执定位** | 利用现有宿主入口展示运行 ID 和错误提示，按需查本地 manifest。实现较小，适合已熟悉宿主的用户。 | 跨重启保留取决于宿主及本地文件的实际状态。失败产物查找和脱敏支持需额外操作。 |
| **B · 增加按运行 ID 查询的轻量详情（推荐）** | 按 ID 显示状态、资产定位、摘要和可操作错误。提供主动导出的脱敏摘要，删除权限按 Q-12 决定。 | 需稳定的读取契约、索引与旧回执兼容。真实文件隐私、可见字段及访问权限须定义。 |
| **C · 纳入完整 Assets/运行管理界面** | 可搜索和筛选来源、参数、时间、输出和失效状态，适合规模化使用。 | 需要与素材能力同步建设和验收。Assets 仍占位时会扩大首版依赖，可能延后其它核心验收。 |

**验收影响** FR-01、04、07、08，CASE-05/07/14。覆盖坏路径、权限、损坏 FITS、版本、磁盘、取消、工作区离线和结果缺失。面向共享的诊断默认评审绝对路径、文件名、头字段和 CLI 输出是否需要遮盖。批量访问的大目录性能需另测。

### Q-20 禁用与历史读取的生效边界

**禁用 Siril 时，已排队、运行中和历史正式结果分别如何处理？**

| 选项 | 行为与优点 | 缺点与代价 |
| --- | --- | --- |
| **A · 拦截新处理，已开始的任务完成（推荐）** | 新候选及未开工正式节点被拦截。已经取得配置快照的处理可完成，历史正式产物仍可读；重新启用先复核配置。 | 禁用后短时间内仍可能消耗资源并发布结果，界面需明确展示任务还在运行。 |
| **B · 禁用时也请求取消运行中处理** | 工作负载更快停止，适合管理员需要立即停用。已登记产物继续保留。 | 需协调候选线程、原生队列和提交边界。取消迟到时可能已经成功，不能保证立即停止。 |
| **C · 区分暂停接单与主动停止** | 提供暂停新处理和取消现有作业两种操作，操作者可按目标选择。 | 需要清楚的多状态反馈和权限。可见交互、跨页面同步和验收范围最大。 |

**验收影响** FR-01、02、08、09，CASE-01/06/07/09。验证排队节点、运行中候选、运行中正式结果、已提交结果、配置移除与重新验证。历史 FITS 读取及是否可在禁用时由通用显示入口查看应分别验收。

### 首版验收建议与依赖

| 验收组 | 最少应看到的可核对结果 | 依赖与当前证据 |

### 决定如何写回

1. **R1 回溯，已完成。** 将历史交付和已采纳规则写入 FR，分别记录当前事实、相反的早期方案和缺失证据。v0.1 的三个 FR 保留；新增 FR-04、FR-05 让之前埋在正文或跨 Feature 的行为能单独验收。
2. **R2 场景质询，已形成待决项。** Q-01～20 和源码边界 E-01～14 相互追溯，新增 FR-06～09 保持 Proposed。历史产品决定继续作为验收来源。若选项改变 D-01～03，决定记录标明替代范围、生效版本和历史兼容。
3. **R3 决策和传播，待进入。** 每个 Q 以场景、证据和产品取舍复审。记录采纳选项或延期理由、确认来源、负责人及日期，将对应 Q 更新为已决定或带影响的延期，必要时新增 D 并保留替代关系。随后递增 PRD 版本，同步受影响的 UI/UX、技术、开发规格和测试计划。
4. **R4 验收和回流，待进入。** 以确认后的 FR 和场景执行，测试报告保留目标版本、数据和结果。结果偏离承诺时回到对应 Q 或 FR 再评审。保留原历史结果，待 Close 对照实测后判定完成度。

现有 CASE-01～14 用于定位证据和验收影响。新选项的独立断言在决定确认后写入测试计划。涉及 Inspector 和校验的决定传播到交互、技术与实现规格；涉及目标根、资产身份、回执或删除的决定同步存储和素材契约；版本与适配范围传播到开发与验收说明。 [Feature 索引](00_FEATURE_INDEX.md) · [现有测试计划](05_TEST_PLAN.md) · [跨 Feature 评审顺序](../INDEX.md)
