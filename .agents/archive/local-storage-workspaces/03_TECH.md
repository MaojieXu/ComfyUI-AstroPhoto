# 本地存储与工作区 · 技术设计

**版本** v1.1 · 2026-11-21 · 技术设计草案与既有源码披露。代码基线见[索引](00_FEATURE_INDEX.md)。目标宿主 ComfyUI 0.46.0 / Frontend 1.59.6，独立开发 Python 3.12，发布下限 3.11。服务使用 aiohttp、SQLAlchemy/SQLite、Alembic、filelock，宿主契约复用 ComfyUI V3 `on_load` 和原生路由。 [开发环境](../../../docs/development.md)

## 模块、所有权与生命周期

- FR-01。扩展入口调用 `host_runtime`，在 `StorageRuntime.initialize` 中规范化数据根、获取实例锁、校验或生成 manifest/settings、打开 `databases/assets.db`。初始化标志在数据库、默认 Workspace 与 Cache 就绪后写入。可选处理 Bundle 的准备钩子在锁外、业务 operation 恢复前运行。失败时持有诊断码，Core 状态路由仍可报告降级。 [扩展入口](../../../__init__.py) · [Runtime](../../../astrophoto/storage/runtime.py) · [数据库管理](../../../astrophoto/database/manager.py)
- FR-02、FR-05。SQLite 保存位置 ID、绝对路径、规范键、启用与行 revision。工作区身份标记匹配实例和 ID；受管资产持久化 `workspace_id + relative_key`。默认切换只改设置；同身份重绑要求原位置标记不可用，迁移完成通过事务切换路径而保持 ID。路径要求本机绝对路径，限制重叠和重新解析点，禁止把任何数据目录登记到另一条管理边界。 [locations.py](../../../astrophoto/storage/locations.py) · [paths.py](../../../astrophoto/storage/paths.py) · [models.py](../../../astrophoto/database/models.py)
- FR-03。默认 `~/.astrophoto`，可由 `ASTROPHOTO_HOME` 指定；settings 默认 reference、活动 Cache 20 GB。全局 revision 保护默认值和 Cache 修改，行 revision 用于工作区改名、启停和删除。Cache 仅由本实例管理，切换不删除旧 Cache，清理凭实例标记、条目所有权和租约，文件仍在 Workspace 或用户原目录。 [initializer.py](../../../astrophoto/storage/initializer.py) · [cache.py](../../../astrophoto/storage/cache.py)
- FR-02、FR-04。operation 保存原始请求、固定计划、阶段与回执；两线程池配合跨进程 operation 锁和 workspace 租约。迁移先盘点受管目录、确认空间、按持久化清单暂存并校验文件，再写目标工作区标记并事务性切换。原根保留。可恢复阶段持久化错误，在重试或启动时继续；终态不重跑，查询无副作用。 [operations.py](../../../astrophoto/storage/operations.py) · [migration.py](../../../astrophoto/storage/migration.py)

## 当前 HTTP 契约

前缀 `/astrophoto/v1`。存储和资产路由使用 `ASTROPHOTO_LOCAL_STORAGE=1`，单用户监听 loopback、无 CORS，直连请求带 `X-AstroPhoto-Local: 1`；同源或无 Origin 的直连调用可通过，拒绝跨来源与代理头。Core `/status` 提供独立诊断。JSON 请求限 65,536 字节，UUID 采用规范表示。授信快照含 data_root、database、imports/revision、default_workspace_id、workspaces、cache、capabilities、recent operations；无权快照以 200 返回 unavailable，存储未初始化以 503 返回 error。普通错误是 `{error:{code,message,details?},request_id}`，常见为 403、404、409、423、507、503；其余无效请求通常为 422。

| 操作 | 输入与结果 |
| --- | --- |
| `GET /storage`；`PATCH /storage/settings` | 读快照；写传整数 expected_revision 和至少一项 imports.default_mode、workspace.default_workspace_id、cache.max_size_gb，返回更新设置。 |
| `POST /storage/locations` | path、name，201 返回工作区视图。 |
| `PATCH/DELETE /storage/locations/{id}` | PATCH 带 expected_revision、name/enabled 或单独 default:true；DELETE 带行 revision，返回 removed，不删除目录。 |
| `POST /storage/locations/{id}/validate`；`POST .../relocate` | 验证返回状态视图；重绑 body 带 new_path，返回同 ID 的位置。 |
| `POST /storage/cache/{configure,clear}` | configure 接 path、max_size_gb、expected_revision；clear 接 scope，返回 removed、removed_bytes、skipped、failed。 |
| `POST /storage/migrations` | workspace_id、target_path、idempotency_key，202 仅返回 operation_id 与请求 ID。 |
| `GET /storage/migrations/{id}`；`POST .../{cancel,retry}` | 按 ID 查询，或提交取消/重试；返回 phase、receipt、cancel_requested、error 等。 |

## 历史取舍和已知实现差距

**D-15 目标与现行实现差异。** 工作区迁移当前保留源。目标设计在目标校验、登记事务提交后，基于已提交的持久清单及源身份逐项清理；不得以整个源路径做无条件递归删除。源文件变化、其他引用或身份不符时保留对应项目并反馈。对清理部分失败、提交后中断和重复调用，保留新位置权威，继续剩余清理而不重新复制。整库 Data Root 仍用 D-08 的切换规则。 [PRD 决策](01_PRD.md)

**v0.8 产品基线与架构差距。** 继续区分实例 manifest 格式、工作区标记格式和 SQLite schema。现有 `format_version` 与 schema 检查可作为升级入口基线；工作区/正式库升级、单写宿主锁、停机搬家、部分资产切换与每盘配额当时尚待设计。目标宿主已提供临时目录及生命周期；接入扩展专属会话目录时，需要验证正常退出的 worker 排空与异常退出回收。导入目标卷的未提交暂存需按作业归属核对，保留已经登记的对象；现行启动重调度与新规则不同。写入默认启用与来源授权仍是两个接口边界。 [v0.8 PRD](01_PRD.md)

**v0.5 补充。** 启动路径由 `core/paths.py:data_home` 解析，`ASTROPHOTO_HOME` 优先且必须是绝对路径；无覆盖则使用 `Path.home() / ".astrophoto"`。解析不创建目录，创建由宿主初始化负责。现行工作区 migration 改 SQLite 中一个工作区的根，整库搬家还须处理目标根的实例配置、SQLite 一致性、根内外的路径分类和回到旧根的启动切换。建议停机版本先明确哪些可重建数据可跳过，并验证旧根在目标可用前一直可启动。相关机制留待 FR-06 技术评审。 [PRD](01_PRD.md) · [路径解析](../../../astrophoto/core/paths.py)

默认工作区离线时没有代码级自动改写目标的策略。数据库按现行 Alembic 基线、实例身份、WAL 和外键要求打开，不兼容库保留原件。真实盘符转换、访问权限和原始断电仍需实机验证。迁移首次受理只核对目标路径、目录状态及既有 operation；后续工作线程盘点、容量估算并复制。应按典型大图测量清单遍历、读写/哈希耗时和复制期间额外磁盘开销，当前无基准指标。文件系统与 SQLite 跨边界遇到故障依靠 marker、receipt 与回载校验，提交窗口保留分支。 [实现规格](04_DEV.md) · [用例](05_TEST_PLAN.md)

### 按量计划、容量精度与确认（T-03/T-04）

1. 预检输入为模式、源 Workspace ID、目标 Workspace ID、数量和单位。完整模式继续使用目标绝对路径；整库模式使用独立的停机计划。服务器以整数 bytes 持久化和比较。拟定技术口径为 1 GB = 1,000,000,000 bytes，十进制解析后向下取整到字节；百分比必须大于 0 且不超过 100，固定 GB 必须大于 0。拒绝空、非有限值和换算后为 0 的请求。百分比以源 Workspace 快照的全部已登记受管字节数计算，每个物理文件在清单只计一次。排除外部 reference、会话暂存和其它工作区。录入信息或文件不能核验时报告差异并阻断，不能缩减基数。
2. 按组 bytes 降序、规范化稳定组 ID 升序一次遍历。能放入剩余目标量的候选进入不超量方案，过大的跳过。若存在差额，从未入选组中按追加后的超额 bytes、稳定组 ID 升序评估，只暴露首个能够通过目标预留与路径检查的候选。非空基础方案先检查可执行性；为空时仅允许明确选中最小可行超额。基础方案因容量、所有权或路径冲突被阻断时，不能用追加组绕过该冲突。两者都不可执行则返回阻断。保存固定清单、版本与参与校验的文件标识、配额/预算快照、差额、清源范围和两个方案各自的可行状态。演算法在已选贪心清单基础上最多追加一组。
3. 确认请求提交冻结计划 ID、所选结果 ID 和幂等键。服务端先找既有键，匹配同一计划和结果则返回原 operation ID，异输入拒绝。新请求锁定源与目标，在锁内复核登记版本、路径/卷身份、文件标识及容量，原计划失效要求重做预检。执行期间复核实际文件及 SHA-256，遇变化停止后续组，保留先前已提交组。后台不重新选组、增加超额或换盘。计划的持久期和对收据的保留规则在发布前按现有 operation 候选策略核实。
4. 预算记录卷身份、配置额度、受管已用、在途预留、剩余额度和 OS 可用 bytes。预留记录关联作业步骤和卷，登记和预留转换在事务内执行，失败/未提交释放对应预留。跨卷目标增长与源清理分开结算。同卷复制只将同一已登记逻辑数据计入额度一次；复制在真正删除源之前需要额外的物理空间。物理预算只扣尚没写入磁盘的承诺，已落盘暂存和残留已包含于 OS 的实际消耗，避免双扣。Siril 输出未知精确尺寸时以可证明的预算在执行时预留，发布前按实际值复核，不足则失败回执并保留既有结果。额度调低不移动或删除数据，后续增长按新额度判断。
5. 所有需要双方锁的任务按固定 ID 顺序取租约，再在同一容量协调边界完成检查与预留。作业结束、失败与重启时根据持久记录对账，区分已落盘、已登记和仅预留。遇同卷余额不足、物理空间不足、离线、忙碌、目录身份不符分别返回原因，并给出用户可手动重选的在线目标；状态变化后再次检查。展示同卷物理空间在复制期间的峰值；以小夹具与注入验证正确性，性能阈值尚无运行证据。

### 文件发布、恢复与停机切换（T-01/T-03/T-05）

| 检查点 | 权威位置与恢复 |
| --- | --- |
| 预检或等待租约 | 源权威。重复点击归同一操作；受理前/等待时取消无源清理。仅暂停参与迁移的 Workspace，底层卷状态与作业状态独立呈现。 |
| 目标暂存、发布、内容验证 | 源权威。将归属与校验信息持久化后以无覆盖方式发布；验证目标 SHA-256 和身份后才进入 SQLite 提交；事务前再次检查取消。源变化、目标无空间或中断时保留原登记。作业残留按 D-11 预览并显式处理。 |
| 数据库提交 | 完整搬迁同时提交 Workspace 路径和回执；按量同时提交当组所有相对键、Workspace 关系及组回执。各已提交组目标权威，之后取消仅影响尚未提交的组。旧数据保护和目标已提交检查按组独立。 |
| 提交后清源 | 依据已提交清单按文件处理，逐条检查当前源标记/卷、受管边界、文件指纹与其它使用关系以及有效目标。成功删除或认定先前已删除后记账；源替换、锁定、路径危险或目标失效时保留源并记录残留。若删除后未记账而崩溃，确认源位置身份及有效目标后将缺失的已提交项视为已清理；离线造成的不可读不能当作缺失。只删除可证本作业专属且空的目录，未知内容保留。同一 operation 只重试剩余清理。 |
| Data Root 停机复制与激活 | 宿主停止写入并释放实例锁；外部工具独占锁核对停止状态与计划。复制一致的数据库（按停机 checkpoint 与可回读验证处理 WAL）、配置、根内受管文件及持久回执，在新根重映射根内绝对登记，根外路径与 reference 保持原位。完成摘要、数据库完整性、身份一致和回读检查后记录仅新根可激活，启动前协调记录原子切换。旧根保留。 |
| 新根启动与回退 | 目标验证失败且肯定没有目标写入，外部工具持同一实例锁恢复旧根。守卫在新根有任何写入之前持久化开始写入的标志，写入状态不明时按已经写入处理；此后旧快照不得直接激活，改用当前实例重新搬回或有效备份恢复。移动前中断保留旧根权威，切换中断先读取独立协调记录恢复，不依据两个根的修改日期猜测。 |

### 作业重新提交与恢复契约

| 触发 | 目标行为 |
| --- | --- |
| 租约忙碌 | 现有零等待租约会返回 STORAGE_BUSY，作业可保留在原阶段并记录错误，未自动重排。拟议设计将该情况展示为等待，执行有限退避；超过预算显式提示恢复，避免持续显示复制中。次数/时长待实现设计验证。 |
| 同一提交响应丢失 | 同计划、同选项、同键找回原作业，即使已终态也返回原 ID。 |
| 用户明确重做已失败或取消的迁移 | 返回表单并重新预检，生成新计划和新幂等键。若目标遗留仍阻断，则提供归属确认和处理指引。 |
| 仍可恢复的活动作业 | 继续同 ID；安全检查点可取消。完整迁移提交后禁止取消；按量可请求停止尚未提交的组。 |
| 已提交但源清理失败 | 仅重试原作业的清源步骤。查询、重复确认和清理重试均不重新复制或改回旧位置。 |

Workspace 标记生命周期独立于登记：合法解除只移除数据库记录，当前磁盘 marker 仍在；已有标记只在同实例、ID 未登记且布局满足空目录规则时接续。重新登记与离线重绑使用各自 guard。资产缺失可用 `GET /assets/{id}/availability` 查询；工作区级缺失汇总属于新增。

## v1.3 评审后的现行契约

- **整库生效点。** 账号协调目录的 `roots.json` 决定有效根。停机搬家先验证和发布目标，再写源快照标记，最后原子切换 catalog。若切换前中断，启动在 manifest 身份通过且持有效根、实例锁时清除有效根遗留的标记；目标副本不自动激活。切换后原启动入口转到新根，旧根保留快照。回退也是先标记再写 catalog，恢复路径相同。目标首次开启可写前先只读验证并持久化 `opened`，然后交给 Runtime。无法确认目标未开始写入时，恢复应从当前有效实例搬回或使用备份。
- **预检与执行。** `POST /storage/data-root/preflight` 和 CLI `plan` 与 `move` 共用目录、登记、SQLite、暂存及容量检查。预检允许在宿主运行时查看结果，`move` 需要独占锁并复检。缺件错误为 `409 WORKSPACE_FILES_MISSING`，详情含 `workspace_id`、`path`、`missing_count` 及最多 100 个 `missing` 项，每项含 `asset_id` 和 `relative_key`。活动作业为 `423 STORAGE_BUSY`，详情含作业 ID、类型、阶段。身份不符、脏暂存或目标非空按既有错误码返回对应位置或条目。
- **清源与解绑。** 完整迁移保存受管文件 SHA-256 供提交后重试，旧源已缺失时也逐项核对目标。受信工作区快照及复检返回 `missing_count` 和有界 `missing`，部分可用时仍按文件访问。`DELETE /storage/locations/{id}` 对非终态迁移的源和目标使用相同作业保护，合法解除保留磁盘目录。
