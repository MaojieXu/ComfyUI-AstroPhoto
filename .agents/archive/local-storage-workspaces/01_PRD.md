## 当前需求基线

**目标**是让 Windows 本机用户首次打开即可使用，能看见文件在哪里、能选择新文件写到哪块盘，并能在目录失联时找回已有数据。Feature 2 管理 AstroPhoto 数据库、工作区和会话临时文件。工作流、普通节点的输入和输出目录仍由 ComfyUI 管理。Siril 正式结果及必要回执继续由 Workspace 持久存放，素材库负责导入及其作业反馈。

范围依据为用户于 2026-11-22 明确取消整库和 `objects/` 文件迁移，并确认采用精简方案。目录配置沿用 ComfyUI v0.46.0 对新写入选择位置的思路。临时文件沿用宿主会话的生命周期。 [官方目录参数](https://github.com/Comfy-Org/ComfyUI/blob/a277b5bf213e8a44fa34817b7770b54f86ef4cea/comfy/cli_args.py) · [官方临时文件生命周期](https://github.com/Comfy-Org/ComfyUI/blob/a277b5bf213e8a44fa34817b7770b54f86ef4cea/app/assets/lifecycle.py)

## 1. 产品背景与目标

### 1.1 背景与问题

AstroPhoto 运行于 ComfyUI 内，天文摄影数据可包含大型 FITS 原件、受管理副本、正式科学输出、设备与光路记录、候选预览和临时处理文件。使用者可能把系统盘、内置数据盘与外置存储用于不同数据。现有存储能力虽已覆盖多工作区、文件导入和工作区迁移，但首启配置、整库搬家、临时文件归属、容量分配、异常恢复与 UI 可见性尚不完整。

用户需要明确回答：数据现在存在哪里；什么位置是权威；磁盘不可用时会发生什么；搬迁或中断后能否找回同一份数据；哪些文件会自动清理，哪些原件和正式结果绝不能受影响。

### 1.2 目标与成功标准

1. **开箱即用：** 在受信本机单用户条件下，Windows 正常首次启动可创建同一实例，默认目录可预测，不需要手动初始化数据库或另配内容级写入权限。
2. **身份稳定：** Data Root、Workspace 和 Asset 各有独立身份。改路径、重新绑定、切换默认位置和迁移，不得默默创建替代身份或破坏引用。
3. **数据安全：** 原始观测文件、已提交资产和正式科学结果在失败、取消、迁移、清缓存与正常退出时得到明确保护；系统不得未经授权覆盖未知文件。
4. **位置可管理：** 支持多个工作区、默认写入位置、同卷可验证的完整工作区迁移、同机整库搬家，以及以百分比或 GB 指定数量、由系统生成接近目标容量计划的自动部分迁移。
5. **容量可控：** 每块纳入管理的物理卷可配置共享配额，区分配置额度、受管用量、在途预留和物理剩余；默认盘容量不足时由用户手动切换。
6. **操作可追溯：** 用户能看到预检、执行状态、取消、失败原因、恢复动作及最终结果。HTTP 已受理不等于业务完成，清理失败也不应掩盖已完成的权威切换。
7. **减少系统负担：** 可重建预览与临时数据以 ComfyUI 会话为生命周期，正式输出由 Workspace 持久管理。

成功判定以**同一身份可继续读取、源文件摘要可核查、迁移的权威位置唯一、失败有可执行恢复动作**为主，不以“页面显示成功”代替文件和数据库的实际验证。

### 1.3 用户与责任边界

- **本机操作者：** 查看工作区、导入素材、设定默认位置、配置容量、发起或取消迁移、处理离线与错误。
- **ComfyUI 宿主：** 加载扩展、拥有会话与队列、提供临时目录及退出生命周期。
- **AstroPhoto Extension：** 拥有实例身份、业务数据库、工作区登记、存储操作、授权校验和持久结果。
- **素材库：** 拥有素材导入批次、失败重试、正式资产删除和素材侧的交互。
- **Siril 等处理 Bundle：** 使用经过选择和租用的工作区产生正式结果，不拥有 Workspace 目录注册规则。
- **外部 Agent/MCP：** 当前没有本 Feature 的存储写权限，不得将未来工具能力当作既有授权。

## 2. 范围、优先级与非目标

### 2.1 本 Feature 首版范围

- Windows 本机首次启动、实例身份和版本识别；默认 Data Root 与 `Local` Workspace。
- 多工作区创建/登记、检查、改名、启停、默认位置、迁移、重新绑定与有条件解除登记。
- 工作区迁移后的**自动清理已成功迁走的受管源副本**（D-15），并保留可恢复回执。
- 设置版本冲突、动作级能力与错误展示；迁移预检、进度、取消、恢复、幂等与清理。
- 停机整库 Data Root 搬家，以及输入百分比或 GB 后按大资产组优先、尽量不超额的自动按量迁移，支持用户选择接受不足或批准最小超额。
- 真实 FITS 等文件的 reference / copy 业务契约与受管副本的稳定定位；素材库承接 UI。
- 同一物理卷共享容量配额、受管空间展示、默认位置不足时提示手动切换；不自动换盘。
- ComfyUI 会话临时文件及未提交导入暂存的安全清理。
- 同卷小样本、真实文件哈希、重启和故障注入的首版证据。

### 2.2 本轮不承诺

- 多宿主或多用户对同一 Data Root 并发写入；网络共享写入；云端同步与跨机器可移植。
- 对任何历史开发库无条件自动升级；正式支持的旧版由独立版本支持矩阵界定。
- 独立常驻且跨日自动淘汰的 Cache 服务、不可证明归属文件的自动删除。
- 资产删除全规则、导入批次完整 UI 和拍摄会话管理（归素材库）。
- 真实外置卷拔插、真实跨卷迁移、真实 ACL/断电、macOS/Linux 及大数据性能承诺；这些属于后续单独验收，不得用模拟结果替代。

**范围区别：** “产品要求已确认”不代表“当前代码已实现”；“延期实测”也不等于可以把未验证场景写进发行支持范围。

## 3. 术语与不可变业务规则

| 对象                  | 含义与权威信息                                                      | 生命周期与边界                                                                 |
| --------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Data Root**         | AstroPhoto 单实例的数据根；拥有实例标记、配置、数据库和根内受管数据 | 默认 Windows 宿主运行账号的 `<用户目录>\.astrophoto`；整库搬家必须保持实例身份 |
| **Workspace**         | 带持久 ID、位置记录和状态的受管文件空间                             | 可多目录/多卷；目录路径可变，ID 不变；承载受管副本、正式输出和必要暂存         |
| **Default Workspace** | 保存稳定工作区 ID 的未来默认写入选择                                | 切换只影响尚未确定目标的新写入，不移动存量，也不重定向已受理任务               |
| **Asset**             | 资产 ID、所属工作区及相对键等业务登记                               | 文件位置可因迁移更新，资产 ID 不改变；外部 reference 不变成受管副本            |
| **reference**         | 登记用户原始文件路径，不复制摄影原件                                | 默认导入模式；受信本机直接按功能读取，无额外来源白名单；来源可用性单独检查     |
| **copy**              | 在受管目录发布已验证的独立副本                                      | 保留原件；受理时锁定目标，只有发布及登记成功后成为已提交资产                   |
| **正式科学产物**      | Siril 等处理后的 FITS 和必要回执                                    | 必须在 Workspace 持久管理；不得以预览 PNG/Cache 替代                           |
| **会话临时文件**      | 可重建预览和临时计算数据                                            | 优先位于 ComfyUI 临时根的扩展专属子目录；退出后按归属清理                      |
| **持久作业回执**      | 记录迁移等操作的目标、阶段、错误与提交结果                          | 支持跨刷新、断连和重启查询；与浏览器的一次响应分离                             |

贯穿所有需求的产品不变量：

1. **原件不改写。** reference 原件、copy 源、未选中的文件和未知内容均不得因迁移或清理被顺带删除。
2. **提交决定权威。** Workspace 迁移在目标校验通过、数据库位置切换提交前，原位置仍为权威；提交后新位置为权威。清理是后续可重试的收尾动作。
3. **身份与路径分离。** Data Root 实例 ID、Workspace ID、Asset ID 不由当前绝对路径生成；改默认、重绑和搬迁按各自语义执行。
4. **一根一写宿主。** 同一 Data Root 同时只允许一个 ComfyUI 写入实例，可以有多个浏览器窗口；整库搬家必须避免旧根/新根并行写入。
5. **受信入口与文件可用性分开判断。** 不设额外本地内容级授权或导入根白名单；仍检查请求是否来自受信本机、OS 权限、路径安全、磁盘状态、容量和目标身份。
6. **无危险隐式行为。** 离线、只读、容量不足、身份不匹配和未知目录内容均展示原因；默认工作区空间不足时不自动换盘，提示手动切换；按量迁移不足时不自动超量，必须让用户确认；不得覆盖陌生数据。
7. **提交结果不可误回滚。** 已登记的资产和正式输出应保全；执行失败和取消须按检查点解释残留并避免重复发布。

| **S-01 首次启动/打开实例** | 正常启动或打开已有位置                    | 创建/识别唯一实例、稳定 ID、诊断错误或版本不兼容     | FR-01               |

三种常见“移动/复制”动作必须在文案和实现边界上分清：

- **导入 → 复制到 AstroPhoto（FR-07）：** 新增一份受管副本，原件保持原处；默认 `Local` 情况下对应受管目录为 `.astrophoto/workspace/objects/`。
- **迁移工作区（FR-02）：** 可迁移完整 Workspace，或按用户指定百分比/GB 自动迁移一部分受管数据；Data Root、设备/光路数据库和未选中的受管对象保留，已提交清单的源副本自动清理。
- **搬家 AstroPhoto（FR-06）：** 在同一台机器停机迁走整个 Data Root 实例；其数据库、配置和根内受管数据随行，根外 Workspace 与 reference 按原登记位置保留。旧 Data Root 的处理不同于工作区自动清源。

## 5. 功能需求与验收条件

> 以下为 v1.1 的逐条原文。当前 FR-01～08 的验收见[当前 FR 与验收](#当前-fr-与验收)。

### FR-01 首次启动、实例身份、版本与诊断

**状态：Confirmed；优先级：首版必要；场景：S-01；依赖：无。**

**需求**

1. 在 ComfyUI 加载 Extension 的生命周期初始化，而不是依赖用户打开侧栏或某个页面才创建业务状态。
2. Windows 未覆盖时，使用宿主运行账号的 `Path.home() / '.astrophoto'`。按当前 Python 环境解析 Windows 用户目录（常见为 `USERPROFILE`，缺失时可能由 `HOMEDRIVE`/`HOMEPATH` 提供）；用户名含空格、中文、非系统盘或服务账号时均以宿主实际账号为准。
3. 允许通过经过验证的绝对 `ASTROPHOTO_HOME` 显式选根，必须区分**创建新实例**与**打开已有实例**。目标原有数据不完整、属于另一实例或版本不兼容时，应诊断，不得悄悄生成一个替代空实例。整库搬家后，普通启动自动打开已激活的新根，沿用原启动方式和实例 ID。
4. 空实例首次启动创建实例标记、配置、数据库、`Local` Workspace；重启或重复加载保持同一实例/工作区 ID。
5. 实例、Workspace 布局和数据库 Schema 均具版本识别能力。为**正式支持**的旧版预留自动升级入口，升级范围/回滚按发行支持矩阵；可丢弃的 V1 测试旧库无需兼容，不得将普通非测试数据当作可丢弃数据。
6. 每个 Data Root 只允许一个写入宿主；第二个写进程、不可解析 home、不可写路径、损坏配置、冲突标记和不兼容库均以可读状态及可执行下一步呈现，禁止静默写入 cwd、仓库或另一个用户目录。

**验收（CASE-01）**

- 干净 Windows 隔离目录连续启动两次，实例 ID、`Local` ID 和已有资产不变化；默认路径确属宿主运行账号。
- 显式绝对路径的“新建/打开”可区分；坏配置、错误实例、数据库不兼容和初始化中断保持原数据不变并报告原因。
- 第二个宿主尝试同根写入被安全处理；服务账号、中文/空格目录及失败路径的行为有明确结果。不得因为初始化失败而自动降级为另一写入根。

### FR-02 工作区登记、默认位置、验证与迁移

**状态：Confirmed（D-06、D-08、D-13、D-15、D-19）；优先级：首版必要；场景：S-02/S-03；依赖：FR-01。**

**需求**

1. 支持多个 Workspace 的登记、创建/选择、改名、启停、状态检查和默认 ID 设置。默认位置必须在线且满足可写要求；改默认不移动已存在资产，不改已经锁定目标的任务。
2. 在用户确认前，迁移预检展示源/目标位置、工作区身份、受管资产范围、目标空间与共享配额、影响中的任务、预计复制字节和源端自动清理范围；部分迁移还展示源 Workspace 受管数据基数、用户指定的百分比/GB、目标字节数、按大组优先得到的**不超量计划**、当前不足量及（如存在）需另行确认的**最小超量方案**。遇未知顶层文件、无法归属的暂存、身份冲突、路径重叠、缺失的受管资产时列出阻断项。若源、目标在同一物理卷，明确告知调整所属 Workspace 不等于释放该磁盘的物理容量。
3. 迁移期间暂停**受影响 Workspace** 的受管读写并协调活动租约，其他 Workspace 继续可用；禁止边复制边发生未受控的新写入。
4. 迁移按“源和目标清单 → 复制 → 内容与身份校验 → 数据库权威位置提交 → 后续清源/回执”推进。完整迁移切换 Workspace 根位置；按量迁移逐资产或关联资产组更新所属位置。**源、目标 Workspace 自身的 ID 均不改变，迁移的 Asset ID 不改变；按量迁移项目的所属 Workspace 可以更新为目标 Workspace ID。**
5. **D-15 已确认：** 完整 Workspace 或单项资产位置已验证并提交后，自动删除对应清单中**已成功迁走**的原位置受管副本，不二次确认。只清理受管理、已提交和可证明归属的文件；未迁移文件、未知文件、其它作业文件和 reference 原件必须保留。
6. 清理失败不撤销已成功的切换；新根仍可读取，回执给出残留及重新清理的入口；重复调用不得重复复制或误清理。
7. **按量自动迁移（D-19～22）。** 用户指定源 Workspace、目标 Workspace 与百分比或 GB，无需手工勾选资产。百分比按**预检时源 Workspace 已登记的受管数据总字节数**计算（如 200 GB 的 25% 为 50 GB）；不含外部 reference 原件与会话临时数据。候选以不可拆分的完整资产组为单位，按**组字节数降序**处理，同大小按稳定 ID 排序；优先挑选不超过当前剩余目标量的最大组，跳过过大的组。若无法凑满，则展示“接受当前不足量”和“追加一组以产生最小可行超额量”两种可行结果，由用户明确选择；不得自动超额。预检冻结清单，用户确认所选结果后逐项复制、校验、提交和清理。已提交项目的 Asset ID 不变，未选项目不变；预检、执行及回执均显示请求量、实际量及差额。

**验收（CASE-02、CASE-04）**

- 改默认不搬文件。错误标记、重叠路径、陌生内容和缺失资产能阻断预检并指出问题。
- 同卷小样本迁移后，旧资产 ID 从新根解析，文件摘要一致、数据库目标已切换，本次成功迁移的旧受管副本自动消失；按量迁移预检明确源 Workspace 百分比基数、目标字节、按大小排序的候选组、尽量不超量的计划、不足量和可选最小超量结果。未选择超量时不得搬走超额资产。
- 提交前取消/失败，原权威位置和源文件完整；提交后清理失败，新位置仍有效且只重试剩余清理；其它工作区不受影响。

### FR-03 设置、动作级可用性、临时文件与本地权限

**状态：Confirmed（D-10、D-12、D-16、D-27）；优先级：首版必要；场景：S-04；依赖：FR-01。**

**需求**

1. 受信的单用户、回环直连和同源本机部署下，**不再要求额外启用本地读写开关、访问令牌或设置导入来源白名单**，操作者可按已有业务功能读取和修改其 OS 权限允许的数据。移除 `ASTROPHOTO_LOCAL_STORAGE=1` 作为受信本机使用前置，以及 `ASTROPHOTO_IMPORT_ROOTS` 作为本机素材导入前置。仍保留请求来源/Host/转发头安全检查、OS 权限、路径合法性、受管边界与摄影原件保护；不因此放开远程 API 或改变独立 MCP 工具授权。
2. 不以一个总的 `ready/degraded` 简单判断所有按钮；应分别呈现**目录浏览、reference、copy、候选预览、正式输出**是否可用及失败原因。只读、离线、限额不足和未授权需能被区分。
3. 设置保存带版本；旧修订拒绝覆盖。用户刷新后应能查看最新服务状态，同时保留未提交的本地草稿以便重新处理。
4. 可重建预览和临时计算优先置于 ComfyUI `folder_paths.get_temp_directory()` 下可证明归属的 AstroPhoto 专用目录；会话内保留、不设置跨天 TTL、不自动淘汰。达到临时容量预算时拒绝新增并提示处理。
5. ComfyUI 正常退出时自动清空 AstroPhoto 管理的 Cache，无需确认或手动清理。失败或中断且未提交为资产的处理日志、回执与可重建中间文件作为 Cache，在退出时一并清空，不计入按量迁移基数。正式结果及必要回执、外部原件和非 Cache 文件受保护。强制退出时下次启动自动回收可证明归属的残留。历史目录中无法识别为 AstroPhoto Cache 的内容保留。
6. 因文件发布可能要求与目标同卷，未提交导入暂存允许位于 Workspace 下，但依然必须按作业归属和已提交状态清理，不能单纯依赖宿主临时根。

**验收（CASE-03）**

- 在未设置上述两个环境变量的干净本机环境中，可从实际本机目录直接导入或执行合法业务读写；不符合来源信任、OS 权限、路径安全或修订版本条件的请求仍被拒绝并反馈原因。
- 运行中预览可使用、超限拒绝新增。带非空 Cache 正常退出后，在再次启动前验证缓存和未提交诊断已清空；强杀后另测启动回收。正式 FITS、其必要回执、已登记资产、未知文件与 reference 原件的摘要保持一致。
- 两窗口发生旧修订冲突时不会静默覆盖；用户草稿仍可恢复。

### FR-04 作业回执、取消、幂等与失败恢复

**状态：Confirmed（D-11、D-12）；优先级：首版必要；场景：S-03/S-04；依赖：FR-02。**

**需求**

1. 对迁移和搬家提供**预检、等待、执行中、需用户处理、可重试、成功、失败、取消**等可理解的阶段与最终回执；区分占用执行资源的活动作业、等待作业和历史回执。实际状态枚举在技术设计中规范，不在 PRD 锁死内部字段。
2. HTTP 受理、开始执行、权威提交和清理完成必须分开解释；操作 ID、目标、阶段、影响项和错误原因可查询。刷新、双击或丢失 HTTP 响应后应找回同一次提交；用户也可以明确发起新任务。
3. 同一幂等键及相同请求复用原作业，冲突参数不能冒用该作业。查询回执不触发复制、重新发布或删除。
4. 取消先记录请求并在安全检查点生效，最终以服务回执为准，不把“已请求取消”误当“已回滚”。提交前失败保留源；提交后只做一致性核对和剩余清理。
5. 暂时忙碌可以有限重试；离线、容量不足、权限/身份冲突、文件内容变化等不可直接重试的原因需提示下一步。失败或取消的迁移残留，经用户确认，仅按该作业的可证明归属清理。
6. **导入与迁移的跨会话策略不同：** 迁移回执及必要恢复可以跨进程；素材导入只在当前宿主会话运行，退出后未提交导入项终止并清理，已提交资产和必要终态摘要保留，重启不自动续跑未完成导入。

**验收（CASE-04）**

- 分别在复制、发布、权威提交前和提交后收尾处注入错误/中断，重新打开仍能取得对应回执，权威路径与文件状态符合阶段。
- 断网、重复提交、页面刷新和再次查询不会生成重复副本；取消请求和实际终态可区分；提交后不得把旧根当成当前权威。
- 导入在宿主关闭后不存在自动续跑的未提交项，但不会删除已经正式提交的资产。

### FR-05 离线位置、重绑与解除登记

**状态：Confirmed（D-06、D-26）；优先级：首版必要；场景：S-02；依赖：FR-02。**

**需求**

1. 区分在线、离线、只读、身份不匹配、禁用、迁移中和检查失败。不要让“迁移中”覆盖用户需知道的底层缺盘/只读错误。
2. 默认目标离线、丢失、只读或空间不足时，保留原工作区 ID，不静默选其它位置或创建新实例；提示恢复原盘、重绑、手动切换或配置新工作区。**Q-34 已确认：容量不足也不得自动换盘。**
3. 重绑核对实例、Workspace 标记和卷或合法换址证据。身份有效但登记文件缺失时，显示差异并允许用户确认重绑为「部分可用」。保留 Workspace ID 与缺失资产的登记。可访问的资产按现有权限使用；只依赖缺失文件的操作受影响，允许向在线可写且有容量的工作区继续新增数据。补回后复检并更新状态。避免因单个缺件冻结整个工作区。已确认的迁移完整性、身份校验与原件保护仍适用。
4. 解除登记与文件删除分离。默认工作区、仍被资产引用或有活动作业的工作区不得直接解除；符合条件的解除登记不触碰原目录文件。

**验收（CASE-05；相关联动 CASE-06）**

- 模拟目录改址/盘符变化后，以匹配标记重绑能保留工作区 ID；无法证明身份的目标、错误实例和仅凭复制标记的目标拒绝重绑。身份有效且 100 个登记文件少两个时，可确认重绑；98 个可用，两个保留登记并明确标缺，补齐后复检恢复。
- 解除仍在使用的位置被阻止；合法解绑只改变登记，不删除文件。离线时原默认目标保留且给出恢复选项。

### FR-06 整库 Data Root 搬家与按量部分迁移

**状态：Confirmed（D-05、D-08、D-15、D-19～24）；优先级：首版必要；场景：S-03；依赖：FR-01、FR-02、FR-04；Q-36 A、Q-37 A、Q-38 B 已全部定稿。**

**需求**

1. 入口分为**整库搬家、完整 Workspace 迁移、按量部分迁移**，避免把三者的数据作用范围混为一谈。每条路径至少提供预检、目标及范围确认、进度、结果和最近一笔回执。
2. **整库搬家必须停机。** 宿主可以先生成计划，外部搬家工具必须确认 ComfyUI 已停止写入，再复制一致的 SQLite、实例配置、根内受管数据与正式输出。根外 Workspace 和 reference 登记路径保留原位；会话临时文件可重建，不作为必迁内容。
3. 整库搬家保留实例 ID、设备/光路、素材登记、Workspace ID 以及业务关系。目标已有其它实例或未知内容时拒绝覆盖。复制与校验成功后，激活并持久记录新的有效根。用户用原方式启动即打开新根；旧根保留快照且禁止继续写入。有效根不可访问或配置冲突时显示当前有效位置和恢复指引。
4. 新根验证失败且尚未写入时，旧根可恢复启动；新根已经产生新写入时，旧根只是旧时间点的副本，返回旧位置应从当前有效实例重新搬回或按有效备份恢复。整库旧 Data Root **不执行** D-15 的自动清源。
5. **按量部分迁移不要求逐项选择 Asset。** 用户选择来源 Workspace、目标 Workspace，并输入要腾出的受管数据数量：百分比或 GB。**Q-36 A：** 百分比以预检快照中的**来源 Workspace 已登记受管数据总字节数**为分母，例如 200 GB 的 25% 对应 50 GB；固定 GB 则直接转换为目标字节数。reference 原件、会话临时文件和其它 Workspace 数据不计入基数。系统冻结清单与对应目标空间预算，展示预期搬迁字节数及偏差；计划经用户确认后执行。
6. 迁移单位必须可独立校验并保持完整：单个 FITS 不拆字节，正式结果需要的关联文件与回执成组处理。对每项先校验目标、发布并提交位置，再根据 D-15 自动删除已迁移的旧受管副本。没有进入已提交清单的资产及 reference 原件保持原处；资产 ID 不变。取消、容量不足或中断时，回执说明已完成量、尚未迁移量、当前权威位置和残留。
7. **Q-37 A + Q-38 B：大文件优先，但不默认超量。** 以可完整迁移的资产及其必要关联文件组成候选组，按组总字节数降序排列；同样大小按稳定组 ID 排序。按此顺序逐组检查，只有**当前组不超过剩余目标字节数**时才纳入不超量计划，过大则跳过，继续尝试后续较小组；达到目标即停止。若所有剩余组都大于剩余目标量，不再自动追加：在预检中提供 **① 接受不足（保持当前计划）；② 允许超额（仅追加可使超出字节数最小的一组）**。并列时按稳定 ID 确定；仅对满足目标空间及共享配额的组提供超额选项。用户必须明确选定其中一个结果并确认最终清单，执行中不得自动更换模式。不超量清单为空时，不提供「接受不足」；若存在可行超额组，只提供由用户明确确认的最小可行超额方案，否则报告无法完成。若非空的基础清单因容量、归属或路径冲突无法执行，追加组不能绕过阻断。计划源数据变化时拒绝旧计划并重新预检。
8. 备份方案提供停机、隔离、回读和恢复指引。按量迁移的目标空间和共享配额必须通过 FR-08 的检查；容量不足时中止并让用户手动调整目标，不自动换盘。**源与目标位于同一物理卷时，迁移不能作为释放该卷物理空间的方案**，还须考虑复制尚未清理前产生的暂时额外占用。

**验收（CASE-07、CASE-02、CASE-04）**

- 隔离用户目录的整库搬家后，同一实例 ID、设备与光路、素材、Workspace ID、正式结果均能回读，源/目标受管文件摘要一致；根外 reference 与 Workspace 按原登记位置可访问。
- 搬家后沿用原启动入口，无需修改环境变量，打开同实例的新根；旧根不可写。整库目标冲突、仍有写宿主、文件/数据库不一致时拒绝；目标验证失败旧根仍可使用；新根已写入后，不得将旧根当作最新版。
- 用同卷受管样本分别输入固定 GB 和百分比。预检显示计算基数、目标字节数、拟迁清单与预计实际量，确认后自动迁移，无须逐项勾选；完成量、未完成量、超出量（如有）均有回执。已完成项 Asset ID 不变且原受管副本清理，未纳入项和原件保持不变。**示例：目标 10 GB，候选组 100、8、4 GB，应先列 8 GB 不足方案，另列追加 4 GB 后的 12 GB 超额方案；不可直接默认搬 100 GB。**
- 完整迁移与部分迁移分别注入复制、提交、清理阶段失败，重复进入同一作业不会重复搬动或丢失资产。验证 Q-38 B 下接受不足、明确允许最小超额、候选组大小相同的稳定排序、目标盘空间不足时禁止超额，以及预检后数据变化必须重新预检；同一物理卷迁移不得被报告为释放该卷物理空间。

### FR-07 真实文件导入、reference / copy 与受管资产定位

**状态：Confirmed（D-05、D-13、D-16）；优先级：首版必要的跨 Feature 契约；场景：S-02/S-04；依赖：FR-01、FR-02、FR-03；素材侧 UI 属素材库 Feature。**

**需求**

1. 用户可以选择真实 FITS 等本机来源：默认 **reference** 只登记原路径；显式选择 **copy** 时把源文件复制为 AstroPhoto 自己管理的副本，原件保留。
2. 默认 `Local` Workspace 时，copy 副本进入 Data Root 下的受管目录（当前约定 `.astrophoto/workspace/objects/`）。数据库以 Asset ID、Workspace ID 和相对键定位，不把某一时刻的绝对路径当作资产身份。
3. copy 在**受理**时确认并锁定目标 Workspace；对来源大小、文件身份和源状态执行校验，并在真正发布/登记前检查目标与足够空间；不覆盖未经本作业认可的已存在内容。
4. 已提交文件与结果继续保留。失败、跳过、取消及重试的批次交互归素材库；本 Feature 负责副本所在工作区与受管文件的完整性和生命周期。
5. 复制批次仅在当前会话运行。用户可在会话内找回作业；退出清理未提交副本，保留已提交资产及必要摘要。**Q-10 已确认取消额外来源白名单**，受信本机按 OS 权限、源状态和安全路径规则直接读取 reference 或 copy 来源。
6. 工作区迁移/重绑后，既有资产 ID 解析至有效目录。旧 ComfyUI Workflow 中手填的绝对路径不自动改写，必要时提示用户重新选择或重新运行上游。
7. **Siril 与 copy 选址时点不同：** Siril 正式作业在**开始执行时**读取当时默认 Workspace，再持租约写入正式 FITS 并记录真实输出目标。切换默认不会改变已经选定位置的 copy 任务，也不会迁移现有资产。

**验收（CASE-08；兼容联动 CASE-06）**

- 使用隔离真实 FITS 文件，copy 后原件与副本摘要一致；宿主重启仍能按 Asset ID 访问。
- 迁移该资产所在 Workspace 后，同一个 Asset ID 能读取新位置。默认工作区切换前后，copy 与 Siril 按各自正确时点选择落点。
- 源离线、容量不足、文件变化、发布失败时原件不变，回执明确哪些文件已提交、哪些未提交；完整素材页面验收在素材库 Feature。

### FR-08 同卷共享受管容量与手动写入选址

**状态：Confirmed（D-14、D-17、D-18、D-25）；优先级：首版必要；场景：S-05；依赖：FR-02、FR-05。**

**需求**

1. 为每个加入管理的**物理卷**配置一个 AstroPhoto 共享受管容量额度，同一卷上多个 Workspace 共用该额度。界面分别显示**配额、受管已用、在途预留、剩余配额、物理卷剩余空间**。未设配额时显示「未设配额」，整个当前可用物理空间可供使用，无 AstroPhoto 额度上限；仍为在途作业保留所需物理容量，避免超额受理。
2. 同盘 Workspace 的受管副本和正式输出合计占用、在途预留共同计入共享配额；外部 reference 原件和宿主会话临时文件不计入该受管配额。物理剩余空间与共享额度均需足够，防止同卷多目录重复计数，并在执行前及提交前处理并发预留/复核。
3. **Q-34 已确认采用手动切换。** 新任务选中的默认 Workspace 空间/配额不足时停止受理或执行，并显示所需与可用空间、可用的其他 Workspace；用户手动切换后重新操作。不得按照顺序或占用比例自动换盘。显式选定目标和已受理任务均保持其固定目标。
4. 手动切换只影响新任务，不自动迁移存量。用户需要释放空间时可发起 FR-02/FR-06 的完整或按量迁移，仍由用户确认源与目标。
5. 配额不足、实际空间不足、目标离线和其它写入限制应采用不同的提示及恢复建议。

**验收（CASE-09；关联 CASE-02/04）**

- 未设额度的卷可直接使用全部实际可用空间；设置额度后同时校验实际空间与剩余配额。已有受管占用超过新设额度时保留数据，后续新增受额度约束。
- 在同一卷用两个受管目录和模拟配额验证读写、重复计数、容量预留、失败释放与不足反馈。
- 切换配额或默认位置后，已受理任务目标不变；新任务在默认空间不足时明确停止、提示并等待用户手动切换，无自动跨盘改选。
- 实际双卷与资源压力性能仍为延期验收，不能由同卷测试推断通过。

## 6. 跨模块契约与生命周期

### 6.1 数据存放与移动的权威规则

| 业务链路                 | 何时确定目标                                                             | 允许改变什么                             | 不允许改变什么                                      |
| ------------------------ | ------------------------------------------------------------------------ | ---------------------------------------- | --------------------------------------------------- |
| 切换默认 Workspace       | 用户确认设置时                                                           | 后续默认位置选择                         | 已登记资产、已受理作业的目标                        |
| reference 导入           | 素材按其规则登记时                                                       | 外部路径的受控登记、离线恢复             | 外部原件字节、工作区受管副本                        |
| copy 导入                | 导入被受理时                                                             | 创建独立副本与资产登记                   | 原件、已锁定目标、其它资产                          |
| Siril 正式运行           | 作业开始执行时                                                           | 在选定 Workspace 创建正式输出与回执      | 输入原件、其它已有正式输出                          |
| Workspace 完整或按量迁移 | 完整迁移以 Workspace 根位置提交为准；按量迁移以各资产/资产组位置提交为准 | 已提交的受管对象与位置；清理其旧受管副本 | 实例 ID、Workspace/Asset ID、未迁移文件与 reference |
| Data Root 整库搬家       | 确认停机、复制并验证后切换有效实例位置                                   | 根内实例文件与启动选址                   | 实例身份、根外 Workspace/reference 路径             |
| 重绑 Workspace           | 新位置身份与内容核对后                                                   | 同一 Workspace 的目录登记                | Workspace ID 与未经确认的受管文件                   |
| 清理会话临时文件         | 正常退出或下次安全回收时                                                 | 可证明归属的可重建临时文件               | 正式资产、未知文件、外部来源                        |

### 6.2 权限和可用性不是同一件事

- **部署信任：** 首版面向单用户本机、直接回环和同源的受信调用；取消内容级授权不等于取消调用来源、Host、转发头安全或放开外部 Agent API。
- **文件权限：** OS 读写许可和路径安全始终生效，产品默认可写不意味着绕过 OS。
- **导入来源：** Q-10 已决定退出 `ASTROPHOTO_IMPORT_ROOTS` 额外来源白名单。用户在受信本机业务界面可直接指定本地来源；仍校验 OS 可读性、合法路径与受管数据保护。
- **目标可用性：** Workspace 在线且标记正确，仍可能因目录不可写、活动租约、未知暂存或空间不足而无法迁移/输出。
- **动作可用性：** reference、copy、候选、正式输出按 OS 权限、磁盘、配置及业务状态分别反馈，不额外要求内容级授权；状态页展示具体缺口和下一步。

### 6.3 会话临时数据与持久结果

- 目标会话临时数据：候选预览 PNG、可重建处理缓存和相应专属临时目录；不中断使用中的资源、不依赖跨天 TTL。
- 目标持久数据：实例配置、SQLite、工作区位置、受管副本、正式 FITS、必要的处理清单和持久回执；不得作为缓存自动清理。
- 特殊在途数据：同卷 staging 可能在 Workspace 内，但不意味着已成为正式资产。清理须先按已提交登记对账，再只回收未提交且可证明归属的项目。
- 现有旧 Cache 独立目录与跨启动导入恢复属于**当前实现**，不等同于 D-12 的最终会话生命周期。

## 7. 状态展示、操作反馈与安全约束

### 7.1 Workspace 与操作状态

Workspace 至少对用户呈现：**在线、部分可用、离线、只读、身份不匹配、已禁用、迁移中、检查失败**。迁移中的底层异常（卷离线、容量不足、文件损坏）应同时能从详情/回执中得知，不得被“迁移中”覆盖。

对每次持久操作，用户至少能看到：目标、当前阶段、已处理范围、失败/取消原因、是否发生权威提交、是否残留未清理文件、下一步可选动作及可重新找到的回执。进度条应与真实操作阶段对应；不能单凭 HTTP 202 显示完成。

### 7.2 必须保护或拒绝的情形

- 路径越界、危险符号链接、根目录重叠、目标属于其他实例、未知文件会被覆盖。
- 源/目标标记不符、迁移所需数据缺失、未知 staging、源文件在复制期间变化、权限或空间不足。重绑缺件按 FR-05 处理。
- 两个宿主对同一根写入、正在使用的 Workspace 被解除登记、活动操作与迁移冲突。
- 工作区迁移尚未提交却删除原件；已经提交却因清源故障谎称原位置仍为权威。
- 由于目录缺失而静默创建空数据库，或因临时文件清理删除可疑、未知、正式或外部数据。
- 设置发生版本冲突后覆盖其它窗口的新值。

若操作需要用户恢复，界面应说明“**发生了什么 / 哪些数据仍安全 / 当前权威位置 / 下一步能做什么**”。

### 10.2 按量迁移的最终用户规则

1. **指定来源与目标。** 选择源 Workspace、目标 Workspace，以及迁移百分比或 GB 数。操作对象仅包括可管理且可完整迁移的受管资产组，不包含外部 reference 原件、会话临时内容或其他 Workspace 数据。
2. **冻结统计基数。** 百分比乘以预检时源 Workspace 已登记的受管总字节数，例如 200 GB × 25% = 50 GB。GB 采用统一的界面单位并换算成目标字节数；展示实际换算值和来源快照。支持的输入精度、单位标注与取整规则在 UI/TECH 中固定并测试。
3. **大文件优先且不超额。** 候选完整资产组按字节数降序、同字节数按稳定 ID 排序。先依次选取能**完整放入当前剩余请求量**的组，过大的组跳过，再检查后面的较小组；不把单个 FITS 切开迁移。
4. **无法凑满时由用户选结果。** 如没有候选组可继续放入剩余请求量，显示当前不足计划，并给出在其基础上**仅追加一个完整资产组、使总超额最小**的可行计划（如存在）。有可执行的非空不足清单时才提供“接受不足”。清单为空且有可行组时，只提供“允许此超额”。用户在最终预检确认；**未明确选择时不得执行超额计划**。超额组还必须满足目标卷真实可用空间和共享配额。
5. **执行前核对并冻结计划。** 显示来源、目标、候选组与关联文件、请求量、实际计划量、差额、空间与清源范围。源数据或登记在确认后发生影响结果的变化时拒绝旧计划并重新预检。不得由后台擅自替换资产组或调整目的地。
6. **按组提交与清理。** 每组复制并核验，提交位置后才自动清理该组旧受管副本。取消和失败以已提交组为准保留结果，未提交组保持原位置；回执可查询已完成量、未完成量、权威位置和残留。

**例 1（优先贴近请求）：** 目标 10 GB，候选组为 100 GB、8 GB、4 GB。先跳过 100 GB、选 8 GB；剩余 2 GB 时 4 GB 放不下，预检展示两个可选结果：**搬 8 GB（不足 2 GB）** 或 **搬 12 GB（超出 2 GB）**。不得默认搬 100 GB。

**例 2（能够精确达到目标）：** 目标 50 GB，候选组为 40 GB、25 GB、10 GB、5 GB。先选 40 GB，跳过 25 GB，选 10 GB，最终正好 50 GB，不需要额外选择。

**例 3（无法执行超额方案）：** 目标 10 GB，候选仅一个 100 GB 完整资产组。若目标磁盘没有足够空间容纳该组，则不能提供不可执行的超额结果；界面应显示无法达到目标和原因，允许用户改变目标量或 Workspace。

**同卷提醒。** 源与目标 Workspace 若落在**同一物理卷**，上述迁移主要改变资产的受管位置/归属，不会凭空增加该物理卷的空闲容量；过程中还可能因先复制、后清源暂时需要额外空间，必须在预检中说明。

### 11.2 产品评审特别关注的技术风险

这些问题需要在 **03_TECH / 04_DEV** 设计和验证，但不应在 PRD 中提前强制某个函数或实现路径：

1. 现有整体存储 `ready` 可能受单独 Cache 故障影响，导致 UI 无法显示各动作真正的可用性。
2. 工作区可以写入却不能迁移，常见于未知顶层文件、未清 staging 或已经登记的文件缺失；预检和错误反馈需明确。
3. 迁移作业状态可能遮盖卷离线等底层原因；显示和恢复动作需解耦。
4. 迁移前后恢复的文件核验强度不同；必须明示何时完成内容校验，不能以仅尺寸正确替代权威切换前的核对。
5. 现有启动锁、Workspace lease 和作业锁不能直接证明**整库搬家后两个不同 Data Root 不会并行写入同一逻辑实例**。
6. Cache 的记账量可能小于处理暂存和孤儿文件实际占盘；用户看到的可用空间必须反映产品定义的范围。
7. 手填的旧绝对路径不会因 Asset ID 迁移自动重写；要区分工作流输入类型和用户修复动作。
8. ComfyUI 临时根由宿主生命周期管理，但强杀无法触发退出回调；发布暂存还可能需要目标同卷目录。
