## 1. 产品概述

### 1.1 功能定位

AstroPhoto Sidebar 是集成在 ComfyUI 原生侧栏中的天文摄影工作入口。

本 Feature 负责其中的**侧栏导航、节点发现、节点浏览、节点收藏，以及向当前 ComfyUI 工作流添加节点**。

用户不需要离开 AstroPhoto 即可寻找已安装的天文摄影节点、了解其用途，并将节点放入正在编辑的工作流。

侧栏不是独立工作流编辑器，也不重新实现 ComfyUI 的节点注册、画布、撤销、保存或执行机制。

### 1.2 核心产品原则

1. **宿主优先。** ComfyUI 管理工作流与画布生命周期，AstroPhoto 只提供自己的入口和交互。
2. **真实能力优先。** 侧栏仅展示按照产品范围筛选、且宿主实际注册的节点，不把尚未交付的节点或能力显示为可用。
3. **节点发现与节点执行分离。** 能在目录中浏览某种节点，并不等于相关软件、模型或处理环境已经就绪。
4. **共享用户设置。** 收藏、主题、语言等宿主已有能力优先复用，不另建平行状态。
5. **浏览操作与写入操作分离。** 查看详情、搜索、筛选和预览不应改变工作流；添加和拖放必须遵守宿主编辑权限。
6. **兼容既有工作流。** 保留稳定节点 ID、输入输出契约、Widget 标识和宿主工作流保存行为。
7. **明确生命周期。** 页面临时状态、宿主用户设置、设备编辑草稿及工作流状态拥有不同的持久化边界。
8. **经过验证才承诺兼容。** 宿主版本支持范围以实际验证矩阵为依据，不因接口存在或版本更新而自动扩大。

### 1.3 成功标准

用户能够：

- 从一个 AstroPhoto 侧栏入口访问 Nodes、Assets 和 Settings。
- 准确找到实际安装的 AstroPhoto 节点。
- 通过分类、搜索、筛选和排序缩小节点范围。
- 通过悬停或详情了解节点用途及输入输出。
- 使用 ComfyUI 共享收藏管理常用节点。
- 通过点击添加或拖放，将节点加入当前可编辑的主图或子图。
- 使用宿主原生撤销、重做、保存和重新打开操作。
- 在加载失败、节点缺失或画布不可编辑时得到明确反馈，不破坏现有工作流。

本 Feature 的成功不以新增独立工作流管理、Agent 操作画布或扩展整个素材业务为前提。

## 2. 背景与现状

### 2.1 用户问题

天文摄影处理涉及多类专业节点。随着 Siril、后续软件适配及处理能力增加，节点数量、类别和依赖关系将持续增长。

如果完全依赖通用节点搜索，用户可能需要记忆节点名称、分类或具体处理软件。

AstroPhoto 需要提供一个面向本产品的节点浏览入口，同时保持与 ComfyUI 原生操作一致。

本 Feature 重点解决：

- 节点搜索和浏览上下文如何保持。
- 节点分类与宿主注册信息如何对应。
- 收藏如何与宿主原生收藏同步。
- 节点详情和预览提供哪些信息。
- 在经典画布及 Nodes 2.0 中如何稳定添加节点。
- 目录刷新、节点卸载、版本变化和操作失败如何处理。
- AstroPhoto 的 UI 状态与宿主工作流状态如何划分所有权。

### 2.3 当前需要关闭的工程差距

**G-01 目录刷新规则：** 产品已确认刷新期间隐藏旧目录，失败后只显示错误和重试。现有行为基本符合该方向，仍需核对快速重复刷新、过期响应及交互清理。

**G-02 节点归属与展示：** 继续使用模块标识及必要兼容例外，但节点目录、详情、收藏操作与自有拖放必须共享同一可发现集合，不能允许用户拖入隐藏的示例节点。

**G-03 收藏条目语义：** 顶层快捷收藏与具体收藏文件夹路径分别管理。现有按钮状态和移除行为需要按精确路径规则复核。

**G-04 复杂画布操作：** 拖放期间切换工作流、覆盖层、只读状态、子图撤销和失败后的历史一致性仍需针对目标版本验证。

**G-05 草稿生命周期：** 已确认仅保留会话内草稿。需核验侧栏重挂载、主动切换页面和不可拦截退出的实际行为与提示。

**G-06 宿主支持矩阵：** 正式支持只覆盖已经完成目标验收的版本组合。目标版本之外的行为不能仅凭运行时能力检测宣布兼容。

## 3. 目标用户与使用场景

### 3.1 目标用户

| 用户类型                   | 主要需求                         |
| -------------------------- | -------------------------------- |
| 初次使用 AstroPhoto 的用户 | 通过分类理解处理节点和用途       |
| 普通工作流作者             | 快速搜索、预览并添加节点         |
| 高级天文摄影用户           | 重复使用收藏节点、复杂主图及子图 |
| 已配置大量自定义节点的用户 | 保持收藏及宿主原有设置不受破坏   |
| 只读或仅选择状态下的用户   | 正常浏览，但不能意外修改工作流   |

外部 Agent 不是本 Feature 的画布操作主体。Agent 若需要读取或编辑工作流，应由独立 MCP Feature 定义权限和执行契约。

### 3.2 核心使用场景

#### S-01 进入 AstroPhoto

用户从 ComfyUI 原生侧栏打开 AstroPhoto。

预期：

- 只有一个 AstroPhoto 宿主入口。
- 展示 Nodes、Assets、Settings。
- 首次默认视图为 Assets。
- 如果存在符合现行恢复规则的设备编辑草稿，优先返回 Settings。
- 切换主视图不改变 ComfyUI 工作流。
- 同一页面实例内保留 Nodes 的浏览上下文。

#### S-02 搜索和浏览节点

用户进入 Nodes，选择分类或输入节点名称。

预期：

- 仅展示按 AstroPhoto 模块归属规则识别、且实际注册的节点。
- 示例节点按统一可发现规则排除。
- 用户能够搜索名称、ID 和已有可用别名。
- 能够展开分类并查看匹配结果。
- 搜索、过滤和排序相互协作。
- 悬停节点显示只读预览。
- 用户可打开节点详情。
- 目录刷新期间旧结果隐藏。
- 刷新失败后显示错误与重试入口。

#### S-03 收藏常用节点

用户希望快速再次访问某个处理节点。

预期：

- 收藏写入 ComfyUI 已有收藏设置。
- 目录中的快捷收藏仅管理顶层引用。
- 收藏树中移除条目时，仅操作用户明确选择的路径。
- 保留同一节点在其他文件夹中的引用。
- 保留非 AstroPhoto 的收藏和文件夹。
- 节点卸载后不直接删除历史收藏引用。
- 节点恢复并保持相同 ID 时，历史收藏重新可见。

#### S-04 向当前工作流添加节点

用户通过节点详情的添加入口或拖放，将节点放入当前画布。

预期：

- 添加目标遵循当前 ComfyUI 工作流及活动子图。
- 点击添加的位置遵循宿主原生规则。
- 拖放位置遵循宿主的目标判断及坐标转换。
- 成功后节点进入正常工作流。
- 可以通过原生撤销、重做恢复。
- 无效拖放、只读、仅选择或目标未就绪时不破坏原图。
- 仅在已验证的宿主组合上作出完整交互支持承诺。

#### S-05 查看相关模块状态

用户进入 Settings。

预期：

- 可访问已经交付的设置和业务页面。
- 未实现的模块不伪装为已就绪。
- 各领域的加载、保存和错误状态由对应业务 Feature 管理。
- 设备编辑草稿在当前侧栏会话内受到保护。
- 返回 Nodes 后不丢失当前页面实例应保留的浏览上下文。

## 4. 业务对象与所有权

### 4.1 业务对象

| 对象            | 含义                           | 权威来源                           |
| --------------- | ------------------------------ | ---------------------------------- |
| Node Definition | 某种已注册节点的类型定义       | ComfyUI                            |
| Node ID         | 节点类型的稳定标识             | 节点注册契约                       |
| Node Instance   | 工作流中的一个具体节点实例     | ComfyUI Graph                      |
| Category        | 节点定义的分类信息             | 宿主节点定义及 AstroPhoto 展示规则 |
| Bookmark        | 指向节点类型的收藏引用         | ComfyUI 用户设置                   |
| Browser State   | 当前搜索、筛选、展开和滚动状态 | AstroPhoto UI                      |
| Graph State     | 当前图、子图、节点、连线与历史 | ComfyUI                            |
| Equipment Draft | 尚未提交的设备表单输入         | 对应设备编辑页面                   |
| Software Status | 软件配置和处理可用性           | 对应 Software Bundle 及服务状态    |

### 4.2 节点类型与实例的区别

同一种节点类型可以在多个工作流或同一工作流中创建多个实例。

因此：

- 收藏指向节点类型，不指向具体实例。
- 搜索与目录展示节点类型。
- 添加操作创建节点实例。
- 模型缺失、参数错误和实际执行失败通常属于特定实例或运行环境。
- 收藏中的节点引用不能代替缺失模型诊断。
- 节点包缺失与节点实例缺少模型是两种不同状态。

### 4.3 生命周期所有权

| 行为          | 主要所有者        | AstroPhoto 职责    |
| ------------- | ----------------- | ------------------ |
| 节点注册      | ComfyUI           | 使用实际注册结果   |
| 节点搜索      | AstroPhoto        | 提供本域目录交互   |
| 书签持久化    | ComfyUI           | 复用宿主设置       |
| 当前工作流    | ComfyUI           | 识别当前操作环境   |
| 主图及子图    | ComfyUI           | 接入宿主已有行为   |
| 节点创建      | ComfyUI           | 提供意图与输入校验 |
| 节点撤销/重做 | ComfyUI           | 不自建平行历史     |
| 工作流保存    | ComfyUI           | 不改变既有保存协议 |
| 主题和语言    | ComfyUI           | 继承并渲染         |
| 临时浏览状态  | AstroPhoto        | 按页面生命周期维护 |
| 设备编辑草稿  | Equipment Feature | 由领域页面维护     |

## 5. 范围定义

### 5.1 本 Feature 包含

- AstroPhoto 原生单侧栏。
- Nodes、Assets、Settings 主导航。
- 宿主主题、语言和键盘交互。
- AstroPhoto 节点发现。
- 模块标识驱动的节点归属筛选。
- 分类树和展开状态。
- 节点搜索、过滤与排序。
- ComfyUI 共享节点收藏。
- 顶层快捷收藏与文件夹条目精确管理。
- 节点详情及只读预览。
- 点击添加与拖放添加。
- 当前主图和子图的宿主交互适配。
- 加载、空结果、失败及重试状态。
- 侧栏挂载、重挂载和销毁时的交互清理。
- 与现有其他模块的导航衔接。

### 5.2 本 Feature 不包含

- Assets 素材导入和素材列表业务。
- 拍摄会话与校准素材管理。
- 设备及光路业务字段的重新设计。
- 设备草稿跨浏览器重启的持久化。
- 完整工作流文件管理。
- 自建工作流撤销/重做系统。
- 独立工作流运行队列。
- Siril 节点执行逻辑。
- PixInsight 节点适配。
- Agent 远程画布控制。
- MCP 节点执行和工作流编辑工具。
- 自建 ComfyUI 全量节点市场或通用节点库。
- Knowledge、Memory、Experiment 的业务实现。
- 未经验证的 ComfyUI 宿主版本兼容承诺。

这些能力属于对应独立 Feature，不能因本侧栏提供入口而视为已交付。

## 6. 信息架构与导航

### 6.1 导航结构

当前保留一个 AstroPhoto 原生宿主入口，其内部结构为：

- **Nodes**
    - 搜索与过滤
    - 分类目录
    - 收藏
    - 节点预览
    - 节点详情
    - 添加节点
- **Assets**
    - 默认 Projects，可切换 All Assets
    - 素材业务遵循摄影素材库现行基线
- **Settings**
    - Storage
    - Environment
    - Software
    - Equipment & Optics
    - Knowledge
    - Memory
    - Agent
    - System

Settings 的实际信息架构可根据业务页面呈现，但不因此新增多个宿主级常驻标签。

### 6.2 主导航规则

- 同一时刻只有一个 AstroPhoto 宿主入口。
- 三个主视图处于同一导航层级。
- 不创建独立的语言和主题切换入口。
- 不恢复历史设计中的观测地占位。
- 主导航切换不能修改工作流。
- 当前设备草稿的离开保护继续适用。
- **首次默认进入 Assets。**
- **当前有效设备草稿恢复优先进入 Settings。**
- 不增加记忆最后访问主标签的持久化规则。

### 6.3 浏览上下文

依据已确认的 D-08：

- 在同一个页面实例内保留 Nodes 的搜索、筛选、展开和滚动等浏览状态。
- 页面实例被重建时，普通浏览条件恢复默认。
- 已保存的排序设置继续读取。
- 宿主收藏始终从共享用户设置读取。
- 不把普通浏览状态写进 ComfyUI Workflow JSON。
- 工作流切换不应造成已经失效的节点选择仍可执行。

## 7. 功能需求

## FR-01 单侧栏、导航与宿主同步

**优先级：** P0
**状态：** Confirmed
**关联场景：** S-01、S-05

### FR-01.1 单一宿主入口

AstroPhoto 在 ComfyUI 侧栏中只提供一个注册入口。

应满足：

- 重复渲染不产生重复标签。
- 同一容器重复调用时不重复创建业务 UI。
- 挂载容器变化时释放旧挂载。
- 侧栏关闭后重新打开能正常使用。
- 页面销毁时释放该页面拥有的监听、临时预览和异步资源。

### FR-01.2 主视图切换

提供 Nodes、Assets、Settings 三个同级入口。

应满足：

- 支持鼠标和键盘切换。
- 有明确选中态和焦点态。
- 主导航不占据过多侧栏宽度。
- 同一实例内保留应保留的业务状态。
- 未保存的设备编辑状态不能被静默丢弃。
- 切换导航不产生工作流历史记录。

### FR-01.3 宿主主题和语言

- 跟随 ComfyUI 当前主题。
- 跟随宿主语言设置，至少覆盖项目现有中文、英文。
- 不提供独立的语言覆盖设置。
- 使用适合宿主的语义颜色和焦点反馈。
- 语言变化后，导航和节点描述不应进入错误状态。
- 节点名称优先使用宿主提供的有效显示名。没有有效显示名时以稳定节点 ID 回退。

### FR-01.4 默认落点

依据 Q-12 A：

- 首次打开 AstroPhoto 时，默认进入 Assets。
- Assets 默认显示摄影素材库的 Projects，可切换 All Assets。进入页面按需加载，浏览与导航不主动发起变更请求。
- 如果侧栏注册实例中存在符合恢复条件的设备编辑草稿，则优先进入 Settings。
- 不依据上一次访问的主标签改变默认值。
- 不新增浏览器持久化的主标签记录。

### FR-01.5 状态恢复

- 普通节点浏览状态遵循 D-08。
- 设备草稿的保留范围遵循 Q-13 A。
- 不保存无必要的临时悬停状态。
- 重挂载不能重复执行同一次节点添加。
- 已销毁页面的异步结果不得更新新的页面实例。

### 验收标准

**AC-01.1** 目标宿主仅出现一个 AstroPhoto 原生入口。

**AC-01.2** 重复挂载、关闭、重开及切换容器无重复界面和重复监听。

**AC-01.3** 中英及明暗切换正常，窄栏仍可操作。

**AC-01.4** 三视图鼠标、键盘导航正常。

**AC-01.5** 首次默认进入 Assets；设备有效草稿恢复时进入 Settings。

**AC-01.6** 主导航操作前后，工作流节点与连线保持不变。

**AC-01.7** 同一页面实例内浏览上下文按 D-08 保留；重建后按规则恢复。

**AC-01.8** 点击或键盘激活「节点」「素材」「设置」时进入该标签首页，包括再次激活当前标签。节点回目录并保留查询和筛选，素材回「项目」，设置回模块列表。未保存的设备、设备组合和素材编辑继续使用现有离开确认。素材导入页的专用入口直接打开「设置 → 存储」。见 D-19。

## FR-02 节点目录、搜索、分类与收藏

**优先级：** P0
**状态：** Confirmed
**关联场景：** S-02、S-03

### FR-02.1 真实节点发现

Nodes 页面必须以当前 ComfyUI 宿主实际注册的节点定义为依据。

依据 Q-10 A，采用以下规则：

1. 继续通过节点的模块标识识别 AstroPhoto 节点。
2. 保留已确认的历史节点兼容例外。
3. 不通过完整的独立节点声明清单替代宿主注册结果。
4. 仅展示符合归属规则、且实际已注册的节点。
5. 示例节点按统一规则从可发现集合中排除。
6. 节点目录、详情、收藏操作和自有拖放使用同一个可发现集合。
7. 不得允许用户通过自有拖放载荷添加目录中明确排除的节点。
8. 不将整个 ComfyUI 节点库纳入 AstroPhoto Sidebar。

其他要求：

- 以稳定节点 ID 识别节点类型。
- 允许展示适合用户阅读的名称。
- 不能因为显示名称相同而合并不同 ID 的节点。
- 可选 Bundle 缺席时不显示未实际注册的 Bundle 节点。
- 节点卸载或注册失败时不能继续假定其可添加。
- 对模块名、部署目录及 Bundle 结构变化进行兼容测试。

### FR-02.2 分类树

节点按真实分类信息构建目录树。

应满足：

- 可以展开与收起分类。
- 支持多级分类。
- 在展示层适当简化 AstroPhoto 分类前缀。
- 不改变实际节点 ID 和分类契约。
- 分类名称与节点名称不能互相替代。
- 分类改变后，当前筛选状态必须能恢复到可理解的界面。

目录结构由实际节点定义驱动，不采用旧原型中的虚构节点数量。

### FR-02.3 搜索

支持通过以下可获得的信息查询：

- 显示名称。
- 稳定节点 ID。
- 已有别名或有效翻译名称。
- 产品当前支持的分类文本。

要求：

- 中文输入法组合期间不误触发未完成查询。
- 输入完成后更新结果。
- 清空查询可恢复当前筛选范围。
- 搜索不能创建或执行节点。
- 对不存在的结果给出明确空状态。
- 重复请求或异步响应交错不得覆盖更新结果。

本 Feature 不要求新增语义搜索、AI 推荐或远程搜索索引。

### FR-02.4 过滤与排序

支持现有的：

- 按类别过滤。
- 默认或原顺序排序。
- 名称排序。
- 与收藏浏览状态协作。

应满足：

- 筛选和搜索可组合。
- 排序不改变节点 ID。
- 排序不修改节点定义。
- 有效的持久化排序选择可在页面重建后恢复。
- 分类或筛选条件失效时，显示可解释的状态或回退到有效条件。
- 不将视觉排序误写为节点执行顺序。

### FR-02.5 共享收藏

收藏使用 ComfyUI 原有用户设置，不建立独立的 AstroPhoto 收藏数据库。

依据 Q-11 A，采用以下语义：

**目录快捷收藏：**

- 节点目录中的收藏按钮只管理该节点的顶层快捷收藏引用。
- 按钮状态反映顶层引用是否存在。
- 添加快捷收藏不应改变既有文件夹中的同一节点引用。
- 取消快捷收藏只删除对应顶层引用。
- 即使节点存在于某个文件夹中，也不能据此认为其顶层快捷收藏已存在。

**收藏树条目：**

- 当收藏树提供移除入口时，移除对象是用户明确选择的条目路径。
- 不以节点 ID 为单位批量删除所有文件夹引用。
- 相同节点 ID 可以同时存在于多个文件夹。
- 不修改不相关的文件夹或外域节点引用。

**共享设置与失败处理：**

- 收藏变更以实际宿主保存结果为准。
- 保存失败时回读真实状态并提供反馈。
- 不以本地乐观显示代替实际保存成功。
- 不承诺宿主尚未提供的多窗口原子并发保证。
- 快速连续操作和外部同时修改时需要验证并记录实际行为。

**失效收藏：**

- 采用 D-07：隐藏无法解析为当前节点定义的收藏条目。
- 不删除其宿主原始引用。
- 相同节点 ID 恢复注册后，收藏重新显示。

### FR-02.6 节点目录刷新

依据 Q-09 A：

- 首次请求时显示 Loading。
- 已有目录刷新时，立即隐藏旧目录结果。
- 刷新成功后，以新结果替换目录。
- 刷新失败后只显示错误状态与重试入口。
- 不继续向用户展示旧目录作为可操作或只读结果。
- 刷新期间，旧节点详情中的添加操作不得继续依赖旧目录状态。
- 旧的请求响应不得覆盖较新的刷新结果。
- 重试成功后恢复正常浏览和添加。
- 当前页面的查询条件可按 D-08 保留，但只有新目录成功加载后才用于展示结果。

本 Feature 不引入旧目录的离线浏览模式，也不要求基于过时快照实时校验并继续添加节点。

### FR-02.7 节点目录状态

必须区分：

| 状态              | 用户应理解的含义             | 目录展示       |
| ----------------- | ---------------------------- | -------------- |
| Initial Loading   | 正在首次取得节点目录         | 不展示结果     |
| Ready             | 当前目录可正常浏览           | 展示当前结果   |
| Empty Catalog     | 没有符合归属规则的已注册节点 | 展示空目录     |
| No Search Results | 当前查询没有匹配项           | 展示空搜索结果 |
| Error             | 节点目录请求或解析失败       | 错误与重试     |
| Refreshing        | 正在重新取得目录             | 隐藏旧结果     |

Ready 区域可独立显示空收藏，表示当前没有可解析且匹配查询和筛选的收藏引用。宿主中的失效引用仍保留。目录在 Loading 或 Error 时不展示该收藏空态。

不额外提供 Stale 旧目录浏览状态。

空结果不能直接解释为节点安装失败，必须区分搜索条件、目录为空和读取异常。

### 验收标准

**AC-02.1** 节点显示范围与实际注册、模块归属和历史兼容规则一致。

**AC-02.2** 示例节点在可见目录、详情及自有拖放允许集合中按相同规则排除。

**AC-02.3** 同名不同 ID、深层分类、空分类和缺少可选字段时界面可解释。

**AC-02.4** 搜索、清空、中文 IME、筛选与排序符合预期。

**AC-02.5** 首次请求和刷新请求均有正确 Loading、Error、Ready 状态。

**AC-02.6** 刷新期间旧目录不展示；失败后仅出现错误与重试。

**AC-02.7** 过期请求不能覆盖较新的目录。

**AC-02.8** 快捷收藏只改变顶层引用；文件夹条目移除只影响明确路径。

**AC-02.9** 非 AstroPhoto 收藏和其他文件夹不被意外修改。

**AC-02.10** 失效收藏隐藏、相同 ID 恢复后重新显示。

**AC-02.11** 添加和拖放仅能使用当前允许发现且符合宿主注册条件的节点。

## FR-03 向当前工作流添加节点

**优先级：** P0
**状态：** Confirmed
**关联场景：** S-04

### FR-03.1 基础职责

AstroPhoto 负责：

- 选择节点类型。
- 呈现添加入口。
- 提供拖放交互。
- 校验自己生成的输入载荷。
- 校验目标节点是否属于当前可发现集合。
- 对成功、取消或失败作适当反馈。

ComfyUI 负责：

- 节点注册。
- 图与子图的选择。
- 创建节点实例。
- 坐标和有效投放目标。
- 图编辑权限。
- 工作流变更记录。
- 撤销和重做。
- 保存、重开及执行。

不得为本功能重新建立独立 Graph 生命周期。

### FR-03.2 点击添加

用户通过详情或当前已有的节点添加入口发起操作。

预期：

- 当前工作流已就绪时，可以创建一个对应类型的节点。
- 默认放置位置遵循宿主原生节点添加行为。
- 当前活动子图由宿主决定。
- 每次有效操作只创建预期数量的节点。
- 不因侧栏重复挂载出现重复创建。
- 不在仅选择或不可编辑模式下绕开宿主限制。
- 节点必须属于当前符合归属和展示规则的集合。

### FR-03.3 拖放添加

用户从 Nodes 将节点拖入当前画布。

预期：

- 使用明确的自有拖放数据。
- 不劫持普通文件或其他扩展的拖放。
- 有效目标和坐标依据宿主规则。
- 平移、缩放及子图场景按宿主表现。
- 拖动取消不产生节点。
- 非法落点不修改工作流。
- 拖放期间画布变化不应导致向错误工作流写入节点。
- 自有拖放不接受已被目录规则排除的节点。
- 交付效果与同版本宿主原生节点库一致。

### FR-03.4 画布模式

必须分别验证：

1. 经典 Canvas 主图。
2. 经典 Canvas 子图。
3. Nodes 2.0 主图。
4. Nodes 2.0 子图。

两个画布模式不能仅因共用节点定义或执行服务就视为交互等价。

### FR-03.5 添加失败和拒绝条件

以下情况不得破坏现有工作流：

- 当前图尚未准备好。
- 宿主处于只读状态。
- 宿主处于仅选择模式。
- 节点类型已失效或未注册。
- 节点被当前可发现集合排除。
- 自有拖放载荷无效。
- 投放坐标无效。
- 用户取消拖放。
- 创建入口不可用。
- 创建过程发生异常。
- 目标图在交互过程中变化，宿主不再接受该操作。

其中属于宿主既有行为的失败，优先使用宿主反馈机制。

### FR-03.6 失败收尾和撤销

- 扩展自己的载荷错误应在图修改前拒绝。
- 进入宿主创建流程后，应由宿主完成相应历史操作。
- 创建失败不得留下与本次失败操作不符的节点。
- 失败操作不得影响已有节点。
- 失败后下一次撤销和重做仍须有效。
- 主图及子图使用同一产品验收口径。
- 不能用“已经触发图变更通知”代替“工作流可以正确撤销”。

### FR-03.7 原生入口不可用时

按现有 D-11 方向：

1. 优先使用宿主已验证的公开能力。
2. 必要时允许经过兼容验证的薄适配。
3. 适配不能保证原生语义时，交由宿主原生节点库完成对应操作。
4. 无法可靠完成的动作不能伪装为成功。

### FR-03.8 宿主版本支持

依据 Q-16 A：

- 正式支持范围以已经通过验收的 Backend / Frontend 组合为准。
- 当前重点验收组合为 Backend 0.46.0 / Frontend 1.59.6。
- 该组合的各项测试完成后，才能根据结果确认对应支持范围。
- 其他宿主版本不因 API 存在而自动进入支持清单。
- 新版本必须通过必要的节点创建、主图、子图、拖放、撤销及工作流回归测试后才可加入。
- 未验证版本允许安全降级，但不得对外宣称完整兼容。
- 运行时能力检测只能帮助判断当前功能是否可以安全使用，不能代替支持矩阵。

### 验收标准

**AC-03.1** 正常点击和拖放创建正确的稳定节点类型。

**AC-03.2** 主图与子图目标正确，不发生跨图误加。

**AC-03.3** 两种画布的行为与同版本宿主原生入口对照。

**AC-03.4** 缩放、平移、投放位置和标题偏移符合宿主规则。

**AC-03.5** 取消、非法操作和排除节点的拖放不改变节点数与连线。

**AC-03.6** 原生撤销、重做正常，失败后历史仍一致。

**AC-03.7** 侧栏销毁或重新挂载不重复添加节点。

**AC-03.8** 创建后的节点可由正常工作流保存、重开及识别。

**AC-03.9** 正式支持的每个宿主组合都具有对应验证证据。

**AC-03.10** 未经验证的版本不自动列入支持范围。

## FR-04 节点详情与只读预览

**优先级：** P0
**状态：** Confirmed
**关联场景：** S-02

### FR-04.1 节点详情

用户可以进入节点详情，阅读：

- 节点名称。
- 稳定节点 ID。
- 可获得的节点说明。
- 可获得的输入信息。
- 可获得的输出信息。
- 当前已有的固定帮助说明。
- 当前已有的固定依赖说明。

依据 D-04：

- 类别主要通过分类树展示。
- 详情不需要另设类别字段。
- 现有帮助和依赖说明保持固定文案。
- 不要求本轮为每个节点新增独立的富文本教程。

缺少元数据时应使用可解释的缺省显示，不能捏造端口或节点用途。

### FR-04.2 悬停预览

鼠标悬停节点时可以展示简洁预览。

应满足：

- 展示与实际节点定义一致的信息。
- 不实例化节点。
- 不调用节点执行。
- 不修改工作流。
- 离开列表、切换标签或开始拖放时正确关闭。
- 在侧栏边缘和窄宽情况下保持可见或安全隐藏。
- 不因预览消失而影响当前图。

### FR-04.3 非鼠标访问

依据 D-10：

- 鼠标用户使用悬停快速预览。
- 键盘用户通过详情获取相同必要信息。
- 触屏用户通过详情获取信息。
- 不要求触屏通过模拟 Hover 访问重要内容。
- 详情提供可理解的返回或关闭操作。

### FR-04.4 详情与添加操作

- 查看详情是只读操作。
- 添加节点必须有明确的用户操作。
- 详情刷新或元数据缺失不能静默触发添加。
- 如果详情指向的节点已失效，添加动作应被拒绝或交由宿主处理。
- 如果目录进入刷新状态，旧详情不能继续作为可操作的节点添加入口。
- 详情与目录展示必须指向同一稳定节点 ID。

### 验收标准

**AC-04.1** 有完整元数据和缺少字段的节点均可查看。

**AC-04.2** ID、说明及端口与宿主实际定义一致。

**AC-04.3** 不单列类别字段，保留既有帮助与依赖说明。

**AC-04.4** 悬停、键盘和触屏均有可用的了解节点途径。

**AC-04.5** 窄栏、长文本和侧栏边缘不导致不可关闭界面。

**AC-04.6** 浏览详情和预览前后图节点数保持不变。

**AC-04.7** 目录刷新和节点失效后，旧详情不能绕过当前添加条件。

## FR-05 Assets 与 Settings 导航边界

**优先级：** P0
**状态：** Confirmed
**关联场景：** S-01、S-05

### FR-05.1 Assets

依据 D-15 保持 Assets 主标签及默认落点。根据 D-18，Assets 接入摄影素材库，默认 Projects，可切换 All Assets；支持从素材页进入 Settings 的 Storage。侧栏专题负责共享挂载、导航与工作流状态。查询、导入、登记、回执、虚拟放置、重绑及文件保护由摄影素材库与存储专题验收。

### FR-05.2 Settings

Settings 提供已有业务模块的导航。

不同模块必须明确区分：

- 可使用。
- 未配置。
- 依赖不可用。
- 正在加载。
- 请求失败。
- 尚未实现。

模块接入状态由既有能力接口提供。未配置和依赖不可用由能够提供可靠状态的业务模块区分，例如 Software 中的 Siril 配置状态。未知原因显示通用不可用。各模块拥有自己的业务保存和错误规则。

本 Feature 不负责修改它们的领域数据模型。

### FR-05.3 设备编辑与导航

依据 Q-13 A：

- 设备和光路未提交的 UI 草稿只在当前侧栏会话内保留。
- 同一 AstroPhoto 导航内离开需要遵守既有未保存提示。
- 保存进行中不得静默丢弃操作。
- 保存失败时保留输入供用户处理。
- 侧栏注册实例仍存活时，按既有机制恢复草稿。
- 浏览器刷新、强制退出或宿主完全销毁实例后，不保证恢复未提交输入。
- 不新增浏览器持久化 UI 草稿数据库。
- 不新增跨浏览器重启的恢复、过期和冲突机制。
- 已经正式保存的设备或光路数据仍由对应业务服务持久化，不受 UI 临时草稿生命周期限制。

### FR-05.4 Software 与 Bundle

- Software 页可显示实际安装的 Bundle 及软件状态。
- 无 Bundle 时公共侧栏保持可用。

## 8. 跨功能交互要求

### 8.1 主题与视觉

沿用 AstroPhoto 当前 Vue 迁移后的视觉基线。

要求：

- 主导航紧凑。
- 布局信息层次清晰。
- 搜索、筛选和排序形成一致的工具栏。
- 选中、悬停、焦点和禁用态可辨认。

- 在不同侧栏宽度下保持主要操作可达。
- 不为本次整理重新设计整体产品视觉语言。

实际像素、间距和交互原型由 `02_UI_UX.md` 负责。

### 8.2 键盘交互

至少保证：

- 主标签可通过键盘访问。
- 方向键、Home、End 能在相应标签组件内移动焦点。
- Enter 或空格按组件语义激活。
- 搜索框可正常使用中文输入法。
- 搜索选项弹层在 Escape 后关闭并返回触发按钮。节点悬停预览支持 Escape 收起，保留其他控件上已有的焦点。

- 不覆盖宿主已有的重要键盘快捷键。

所有目录加载和恢复交互必须遵守：

- 当前请求与响应对应。
- 旧响应不能覆盖新响应。
- 页面销毁后不能更新已经失效的挂载。
- 失败后能恢复到可解释的状态。
- 正常取消不应显示成业务执行失败。
- 目录刷新时隐藏旧内容。
- 目录刷新失败后仅显示错误和重试。
- 不增加旧目录的 Stale 浏览交互。

### 8.4 安全和权限

本侧栏不新增独立网络权限。

- 节点定义由 ComfyUI 提供。
- 收藏使用宿主用户设置。
- 画布操作只发生在当前浏览器已经拥有的宿主编辑权限内。
- 不提供任意文件读取或命令执行能力。
- 不通过 MCP 绕过宿主画布权限。
- 不将节点描述中的任意内容直接作为可信可执行指令。
- 不以 UI 中存在添加按钮推断当前 Graph 一定可写。
- 不允许通过自有拖放绕过节点可发现集合。
- 不把未验证宿主版本当成已兼容环境。

### 8.5 性能

本 Feature 必须在具有多个自定义节点包的实际 ComfyUI 宿主上保持可用。

当前没有经过确认的目录规模和性能 SLA，因此不虚构固定毫秒指标。

性能优化不得改变真实节点范围、搜索结果及添加权限。

## 13. 技术研究依据与产品限制

以下是用于支持产品判断的官方资料，并不代替本项目的真实运行验收。

### 13.1 ComfyUI 原生扩展机制

ComfyUI 提供 JavaScript Extension 与 Sidebar Tabs API，允许扩展在宿主侧栏注册独立入口。

官方资料：

- [JavaScript Extensions](https://docs.comfy.org/custom-nodes/js/javascript_overview)
- [Sidebar Tabs API](https://docs.comfy.org/custom-nodes/js/javascript_sidebar_tabs)
- [Settings API](https://docs.comfy.org/custom-nodes/js/javascript_settings)

**产品结论：** AstroPhoto 继续采用单一原生侧栏，不另建主应用 Shell。

### 13.2 原生节点库与画布行为

目标版本 Frontend 1.59.6 的源码包含：

- [NodeLibrarySidebarTab.vue](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.59.6/src/components/sidebar/tabs/NodeLibrarySidebarTab.vue)
- [useCanvasDrop.ts](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.59.6/src/composables/useCanvasDrop.ts)
- [litegraphService.ts](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.59.6/src/services/litegraphService.ts)

官方节点库通过宿主创建服务添加节点。拖放路径包含画布坐标转换，创建服务根据当前子图或主图进行操作。

**产品结论：** AstroPhoto 应对齐宿主的节点添加语义，不自行定义跨图编辑规则。

这些实现中的内部函数是否构成稳定公开 API，仍须以目标版本和适配方案核实。

### 13.3 收藏机制

- [nodeBookmarkStore.ts · v1.59.6](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.59.6/src/stores/nodeBookmarkStore.ts)

目标版本采用 `Comfy.NodeLibrary.Bookmarks.V2` 保存收藏引用，收藏树在解析节点定义时过滤无法找到的节点。

**产品结论：** 沿用共享收藏和失效引用恢复机制；AstroPhoto 的快捷操作采用已经确认的顶层与路径区分规则。

### 13.4 Nodes 2.0

- [ComfyUI Nodes 2.0 官方说明](https://docs.comfy.org/zh-CN/interface/nodes-2)

官方说明区分传统 Canvas 与 Nodes 2.0，并指出自定义节点兼容性和复杂场景可能存在差异。

**产品结论：** 两种画布必须分别验收，不把单一模式的通过结果外推到另一模式。

| 方案                                       | 优点                                   | 缺点                             | 结果     |
| ------------------------------------------ | -------------------------------------- | -------------------------------- | -------- |
| A · 刷新期间隐藏旧结果，失败显示错误与重试 | 状态简单；避免旧目录误导；写入边界清楚 | 短时故障会打断浏览               | **采用** |
| B · 保留旧目录，仅允许浏览                 | 保持阅读上下文；减少刷新中断           | 需管理旧快照、禁用操作和状态区别 | 不采用   |
| C · 保留旧目录并实时校验添加               | 降低网络故障对操作的影响               | 校验复杂；容易出现新旧定义不一致 | 不采用   |

**确定行为：**

- 每次刷新进入 Loading。
- 旧目录立即隐藏。
- 成功后展示新目录。
- 失败后只展示错误及重试。
- 不保留用户可浏览的旧目录快照。

**影响：** FR-02、FR-04、CASE-02、CASE-07。

### Q-10 AstroPhoto Sidebar 应展示哪些节点？

**最终决定：A · 沿用模块标识并统一允许范围**

| 方案                          | 优点                                        | 缺点                                     | 结果     |
| ----------------------------- | ------------------------------------------- | ---------------------------------------- | -------- |
| A · 模块标识与兼容例外        | 延续现有架构；改动小；以宿主注册为权威      | 依赖模块字段；需要验证目录及 Bundle 变化 | **采用** |
| B · Bundle 显式声明可发现节点 | 能表达正式、示例、弃用等状态；适合多 Bundle | 额外维护声明；可能出现声明和注册不同步   | 不采用   |
| C · 展示宿主所有节点          | 可在一处搜索全宿主节点                      | 与官方库重复；扩大维护和性能责任         | 不采用   |

**确定行为：**

- 继续使用模块标识及必要历史兼容例外。
- 仅展示符合归属规则且真实注册的节点。
- 示例节点按一致规则排除。
- 目录展示与自有拖放使用同一可发现集合。
- 不升级为通用 ComfyUI 全量节点浏览器。

**影响：** FR-02、FR-03、CASE-02、CASE-07。

### Q-11 收藏按节点还是具体条目操作？

**最终决定：A · 区分顶层快捷收藏和文件夹条目**

| 方案                             | 优点                                   | 缺点                       | 结果     |
| -------------------------------- | -------------------------------------- | -------------------------- | -------- |
| A · 顶层与具体路径独立操作       | 删除范围清楚；保护文件夹；适合高级用户 | 需区分按钮状态和具体路径   | **采用** |
| B · 按节点 ID 全局切换           | 概念简单                               | 可能同时删除多个文件夹引用 | 不采用   |
| C · 仅消费宿主收藏，不在侧栏修改 | 减少重复写入和同步问题                 | 用户需要切换界面操作       | 不采用   |

**确定行为：**

- 目录收藏按钮只增删顶层快捷引用。
- 收藏树操作对应当前指定路径。
- 同一节点在其他文件夹中的引用不变。
- 失效收藏依旧保留原引用并等待恢复。
- 其他节点及宿主文件夹不能被无关操作修改。

**影响：** FR-02、CASE-06。

### Q-12 Assets 尚未完成时，首次默认进入哪个页面？

**最终决定：A · 继续默认 Assets**

| 方案                   | 优点                           | 缺点                       | 结果     |
| ---------------------- | ------------------------------ | -------------------------- | -------- |
| A · 保持 Assets 默认   | 维持现行基线；无需新增入口状态 | 当前首屏为占位内容         | **采用** |
| B · 暂时默认 Nodes     | 用户打开就能使用节点目录       | 改变既有决定；未来需再评审 | 不采用   |
| C · 记住最后访问主标签 | 适应用户习惯                   | 增加持久化及恢复规则       | 不采用   |

**确定行为：**

- 首次进入 Assets。
- 迁移 P0 的历史实现曾为无业务请求的占位页面，现由 D-18 替代。
- 有效设备草稿恢复时优先进入 Settings。
- 不新增最后访问标签的持久化设置。

**影响：** FR-01、FR-05、CASE-01、CASE-05。

### Q-13 设备编辑草稿应该保存多久？

**最终决定：A · 仅保留当前侧栏会话内草稿**

| 方案                       | 优点                                 | 缺点                               | 结果     |
| -------------------------- | ------------------------------------ | ---------------------------------- | -------- |
| A · 会话内临时草稿         | 简单；与当前行为一致；无额外持久数据 | 强制退出可能丢失输入               | **采用** |
| B · 持久化未提交草稿       | 能恢复意外关闭前的输入               | 需要处理版本、过期、删除和数据冲突 | 不采用   |
| C · 强化所有可拦截离开操作 | 离开后果明确；无需草稿数据库         | 不能保证所有宿主销毁场景都可拦截   | 不采用   |

**确定行为：**

- 会话内切换页面仍执行未保存确认。
- 注册实例存活时可恢复临时草稿。
- 不保证浏览器刷新或强制销毁后恢复。
- 正式保存的业务数据仍由设备服务持久管理。
- 不新增跨会话草稿数据库。

**影响：** FR-01、FR-05、CASE-05。

### Q-16 哪些 ComfyUI 宿主版本可以被正式支持？

**最终决定：A · 仅承诺已验证的宿主组合**

| 方案                         | 优点                           | 缺点                                   | 结果     |
| ---------------------------- | ------------------------------ | -------------------------------------- | -------- |
| A · 验证后加入支持矩阵       | 证据可靠；问题易复现；适合首发 | 新版本支持可能滞后                     | **采用** |
| B · 运行时检测后尝试广泛兼容 | 覆盖更多宿主版本               | 接口存在不代表撤销、子图和坐标语义一致 | 不采用   |

**确定行为：**

- 当前目标验证组合为 Backend 0.46.0 / Frontend 1.59.6。
- 只有完成必要验收的组合才能进入正式支持清单。
- 新版宿主需要独立回归。
- 运行时能力检测不等于完整兼容。
- 未验证版本可以安全降级，但不能宣称完整支持。
- 不能凭借新版本发布消息自动扩大支持范围。

**影响：** FR-03、CASE-03、CASE-07、发行兼容说明。
