## 设备与设备组合


**v0.3 · 当前 Vue 交互静态回溯**。依据 [PRD](01_PRD.md#04-equipment) FR-01～05。实际页面是交互核对载体，本轮无新增原型或宿主截图。

### v0.4 已确认交互

产品文案使用「设备组合」。当前设置卡、页签、提示和关联入口用词需同步。重名时在名称字段提示更改，保留已编辑内容。已保存的归档引用可以保留或移除，选择控件不允许新增。两列表继续各用单选筛选，并在当前模块会话内独立记忆。组合表单不新增旋转、变更备注、光学状态配置说明或平场适用性控件。下表为当前 Vue 实现。 [D-04～08](01_PRD.md#04-equipment-已有决定与历史差异)

### 入口与页面

在 AstroPhoto Sidebar 打开 Settings，进入 Equipment & Optics。设备能力加载时显示等待，接口出错可重试，停用时显示原因。光路能力缺失时「光学链路」显示不可用。通用「资料库」组件服务这两个页面，Assets 顶层入口是占位。

| 页面 | 操作及返回 | 关键状态与反馈 |
| --- | --- | --- |
| 我的设备，光学链路（FR-01、02、04） | 分别搜索及单选筛选，展开条目详情，按加载更多取下一页，或发起创建。从列表 Back 回 Settings 卡片。 | 单独视图保留查询及筛选。设备查询名称、厂商、型号，光路查询名称和引用设备名称。默认仅活动记录；设备按类型或归档，光路按部分配置、已配置或归档。区分请求失败、真实空与筛选无命中，无命中可清除条件。 |
| 类型选择及设备表单（FR-01、04） | 从新建选相机、主光学、配件或滤镜；编辑由详情进入。填基本、专业和可选高级字段，再保存或取消。 | 稳定显示类型字段，未设值保持未知。无效字段反馈定位到输入并保留其他输入，保存中禁重复提交。提交成功显示回执并前往详情。新建取消回类型选择，编辑取消回原详情。 |
| 设备详情（FR-01、03） | 摘要、基本资料、专业规格、使用位置折叠分组。从关联名称打开光路。可编辑、归档/恢复、永久删除。 | 归档与永久删除有宿主确认；恢复直接发请求。已引用设备的删除先显示光路链接，无需确认且无 DELETE。服务器仍可因并发拒绝；冲突可重新加载。 |
| 光路表单（FR-02、04） | 填名称、备注，选相机、主光学；增删或上下调整配件，选择可用滤镜。允许缺一项或两项并保存。快速新增打开设备表单，保存后回光路并选用新设备。 | 归档设备不可供新选择，已选旧记录仍可显示及移除，字段会标记失效。有效焦距和焦比仅由可用标称参数估算。变更备注、旋转及平场字段尚无编辑控件。 |
| 光路详情（FR-02、03） | 当前组合摘要、部件名称及规格折叠、滤镜详情；可打开设备。活动光路可编辑，归档光路可恢复；永久删除由确认后发起。 | “已配置”要求相机和主光学；归档独立覆盖显示。历史发布、选择默认和历史时间线属于旧交互；兼容快照用于当前回读或授权接口。 |

### 当前编辑状态

输入有变化时显示未保存。离开模块、主视图或内部标签前确认；取消保留；确认丢弃回列表或上层。快速新增取消只处理设备子表单，光路输入仍在。快速新增后设备已经独立写入。保存中的表单 blocking 阻止内部离开；同一个宿主侧栏注册实例销毁后重挂载恢复未保存草稿。浏览器硬刷新依赖 `beforeunload`，页面内存草稿不具跨重载承诺。

409 保留表单和追踪 ID；刷新后需通过确认将本地编辑改用最新版本号，再手动提交，当前没有字段级合并。对创建超时，保存可能已完成，重新操作前可查列表；当前无独立恢复按钮。

### 无障碍、主题及原型边界

标签支持方向键/Home/End 移焦和 Enter/空格激活，编辑页变化聚焦当前区域；确认关闭后尝试回触发按钮。单选和多选经项目适配复用 ComfyUI 源组件，弹层可用键盘、Escape 退回，错误和未保存有文字提示。宿主主题与中英文沿用 Sidebar。Vue 在 280 px 的组件级样本见 `Library.test.ts`；真实宿主 280/420/650 px、200% 布局及弹层由宿主脚本复验。历史 React 原型和先前宿主验收保留版本边界。 [来源](../../../frontend/src/vendor/comfyui/README.md) · [历史交付](../../archive/equipment-optical-train.md) · [测试计划](05_TEST_PLAN.md#04-equipment)

## MCP 诊断与设备只读查询


**版本** v0.4 · 2026-11-21 · PH-02 宿主界面 N/A

本专题由第三方 MCP 客户端管理进程和工具界面。AstroPhoto 没有新增 UI、独立授权面板或专用原型。下面记录客户端可以呈现的状态和恢复路径。外观、语言、键盘和焦点由客户端负责。错误以协议中的工具错误和现有英文消息呈现。

| 场景 | 用户动作及反馈 | 下一步 |
| --- | --- | --- |
| FR-01/04 连接 | 客户端启动独立进程并 initialize。合法配置出现 version 和 connection_status；非法地址在启动时给出 CLI 配置错误。 | 修正进程配置后重启客户端连接。 |
| FR-01/04 诊断 | version 显示 MCP 安装版本。connection_status 在宿主可达时给出注册状态；未找到节点可正常返回未注册。断连、HTTP 或无效 JSON 是调用失败。 | 根据错误检查 URL、宿主状态或扩展加载；可再次发起诊断。 |
| FR-02/05 权限 | 合规本机配置可显示六项额外查询。枚举成功后仍可能因宿主未启用可信部署或 token 不匹配而出现 403 工具错误。 | 检查可信部署和两端进程配置；令牌更改后按 Q-01 的候选流程复验。 |
| FR-05 替换与撤销 | 宿主重启载入替换值后，旧 MCP 会话仍可能列工具，后续读请求被拒。以新值重启客户端进程后可恢复查询。 | 先通过 `connection_status` 检查宿主已恢复，再分别以旧、新会话检查权限。接入文档只记录结果，不写凭据值。 |
| FR-02 读取 | 查询返回列表、详情或历史；空列表是正常结果，空游标表示末页。无记录、无权、超时和坏响应走错误反馈。 | 分页时使用返回游标；历史列表为空时保留当前设备组合查询。 |
| FR-03 安装 | 用隔离安装和本地 version/握手确认独立构件；公开渠道结果单独记录。 | 分别诊断安装失败和宿主连接失败。 |

## 素材导入与资产登记


**版本** v0.4 · 2026-11-21 · 当前 Vue 行为回溯。证据为组件和测试源码。

### 当前入口

全新侧栏会话打开 AstroPhoto 默认落在 Assets。若现有设备会话要恢复，初始视图可进入 Settings。Assets tab 继承侧栏键盘导航、语义和宿主语言，唯一页面内容是中/英文说明“素材页将在后续版本提供。” 打开或返回该页不会请求资产列表或发起写入。占位页没有加载、空库、错误或导入状态，当前 FR-01～04 的界面验收待 Q-02 评审；后端仍有对应接口。 [Sidebar.tsx](../../../frontend/src/features/sidebar/Sidebar.tsx) · [AssetsPlaceholder.tsx](../../../frontend/src/features/assets/AssetsPlaceholder.tsx) · [中文词条](../../../frontend/src/i18n/locales/zh/sidebar.json)

FR-05 的科学消费从画布上的 AstroPhoto Load Image 开始。打开控件后读取已登记的 FITS 候选，候选显示名称与短 ID；用户选择资产或输入服务端 FITS 路径并保存到工作流。加载有占位文案，读取失败有重试，旧工作流保存但当前列表未返回的 UUID 作为“不可用资产”保留显示。实际能否读取以及 FITS 是否有效由节点执行校验，候选列表只按扩展名筛选。画布处于只读或 selectOnly 时不提交变更。键盘、窄画布、长名称与旧值回显仍需真实宿主复验。 [fitsSource.tsx](../../../frontend/src/host/fitsSource.tsx) · [科学处理规格](../07-siril-fits-autostretch/02_UI_UX.md)

### 历史界面与恢复设计范围

| 需求 | HEAD 中 React 界面、历史可见反馈或未来需定义的行为 |
| --- | --- |

### v0.4 评审补充

当前 Assets 保持占位。Q-02 若选择恢复，应覆盖来源路径、模式和目标、预检、提交、回执、分页、可用性及外部位置重绑，并为部分失败提供明确反馈。当前公开回执没有失败文件路径，也没有逐项资产 ID，页面无法仅靠现有回执提供完整失败项清单。错误详情、失败项重试和历史回执找回随 Q-04 确定。恢复后需更新实际原型并做宿主交互验收。 [产品问题](01_PRD.md#06-assets) · [技术契约](03_TECH.md#06-assets)
