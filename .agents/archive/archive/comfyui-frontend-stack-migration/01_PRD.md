# PRD v1.3｜AstroPhoto 前端迁移至 ComfyUI 官方技术栈

**状态**　已定稿 · 2026-11-21

**优先级**　P0，当前首要任务

## 1. 模块定位与目标

AstroPhoto 的绘图节点沿用 Vue，业务侧栏和科学节点界面使用 React，部分设置页由 React 包装从 ComfyUI 移植的 Vue 控件。本 Feature 将 AstroPhoto 的活跃前端统一到 ComfyUI 官方同款技术栈，彻底移除 React，同时保留现有界面风格和本次范围内的业务流程。 [当前前端依赖](../../../../frontend/package.json) · [侧栏实现记录](../../../../docs/react-sidebar.md)

**官方对齐方向。** 以 Vue 3、TypeScript、Vite、pnpm、Tailwind CSS、Reka UI、Pinia 和 Vue I18n 为参照。扩展通过 ComfyUI 现有扩展入口接入，延用宿主管理的侧栏和画布交互。绘图现用的 PrimeVue/Aura 按官方迁移方向替换。依赖版本及组件替换细节在技术设计阶段确定。 [官方前端依赖](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.61.5/pnpm-workspace.yaml) · [PrimeVue 迁移说明](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.59.1/docs/extensions/primevue-removal-migration.md) · [扩展钩子](https://docs.comfy.org/zh/custom-nodes/js/javascript_hooks)

**处理 Bundle 的归属。** Siril 是后续多个处理 Bundle 中的一个，目标目录为仓库根下的 `extension/siril/`。Siril 专属的界面、节点交互和处理接入由该 Bundle 负责。公共 `frontend/` 提供接入和呈现接口，从共享入口展示各 Bundle 提供的能力。

**资料库界面归属。** 设备与光路归入资料库前端，和后续素材库共用设计语言。设备管理在资料库内保留自己的业务规则和操作，前端源码按资料库组织，避免在 `features/` 下单设与资料库平级的 `equipment/`。这项组织原则适用于本次迁移的设备与光路界面，素材页仍由后续 Feature 实现。

## 2. 主要用户场景

1. **在官方发行版上加载扩展。** 用户从 ComfyUI 原生侧栏进入 AstroPhoto，继续查找节点、调整存储设置或维护设备与光路，常用入口和操作顺序保持熟悉。
2. **在两种画布模式中打开同一工作流。** 用户从经典画布切换到 Nodes 2.0 后，仍可操作旧工作流中的绘图与科学节点，并保存、重开工作流。
3. **通过共享入口使用处理 Bundle。** 用户从现有节点目录和通用软件设置找到 Siril 提供的能力，在画布上选择已有 FITS 来源，在 Inspector 中调参并比较候选预览，随后通过 ComfyUI 队列执行正式处理。正式 FITS 结果沿用现有业务契约。

## 4. 宿主兼容与验收口径

- **正式验收基线。** 使用 ComfyUI 官方稳定发行及其固定前端组合，定稿时的基线为 ComfyUI `v0.46.0` 与 Frontend `1.59.6`。验收记录注明实际使用的宿主及前端版本。此前的 `v1.59.1` 作为历史证据，独立前端发行标签用于技术参考。 [官方发行依赖](https://github.com/Comfy-Org/ComfyUI/blob/v0.46.0/requirements.txt) · [仓库历史验证](../../../../docs/development.md)
- **验收经典画布和 Nodes 2.0。** 宿主提供两种模式及切换能力。AstroPhoto 验证自己的 Widget、节点与交互在两种模式中可用，沿用现有挂载与工作流接口。 [官方 Nodes 2.0 说明](https://docs.comfy.org/zh/interface/nodes-2)
- **兼容契约。** ComfyUI 继续管理工作流、画布和队列。迁移前保存的工作流用于验证节点 ID、Widget 键、连线和 `IMAGE_PATH` 的兼容性。
- **验收记录。** 按 FR-01 至 FR-09 记录结果。界面变化以迁移前后同一模块的对照结果为准，参照 FR-07 处理明显变化。

## 5. 本次范围之外

- **素材页属于后续 Feature。** 预检、导入、素材列表、搜索、排序、重新定位和帧类型筛选均不作为本次功能交付或验收项。本次仅交付一个 Vue 占位页（见 Q-01），用于保留既有侧栏入口；存储与环境设置、科学节点读取已有 FITS 来源仍在范围内。
- **绘图 `IMAGE` 输出故障。** 本次绘图验收以 FR-06 的临时 PNG 引用提交为界。后端 `LoadImage` 路径故障修复及绘图节点到下游的 `IMAGE` 执行验收单独处理。 [历史宿主验收](../../../../docs/react-sidebar.md) · [绘图节点适配器](../../../../nodes/ComfyUIFEExampleVueBasic.py)
- **其他处理 Bundle。** 本次以 Siril 验证公共前端的接入边界，其他软件 Bundle 的开发单独安排。
- **其他工程变更。** 数据迁移、后端业务变更、Siril 算法和 MCP 独立处理。

## 7. 主要流程、状态与权限

| 流程 | 触发 → 主要步骤 | 用户可观察结果 | 状态与异常 |
| --- | --- | --- | --- |
| F-01 加载与导航 | 宿主加载扩展 → 注册侧栏 → 进入默认页 → 切页 | 侧栏可用，默认页符合 Q-01 决定 | 公共层加载失败不影响宿主其他扩展；设备草稿存在时恢复设置页 |
| F-02 搜索与添加节点 | 进入节点目录 → 搜索/筛选/排序 → 点击或拖放 | 节点出现在活动图，可撤销 | 空结果、只读或选择模式、非法拖放负载均不改变图 |
| F-03 设置往返 | 打开设置 → 编辑 → 保存 → 重开 | 保存值在重开后仍生效 | 保存中、失败可重试；失败保留输入；旧 revision 不回写新值 |
| F-04 设备与光路编辑 | 进入资料库 → 编辑 → 保存 → 归档/删除 | 记录与光路按规则持久化 | 字段错误、版本冲突、未保存离开、引用阻止删除 |
| F-05 候选与正式处理 | 配置软件 → 选 FITS 来源 → 调参 → 预览 → 队列 | 候选可比较；正式结果与回执可追溯 | 无 Bundle、软件不可用、预览失败、只读限制 |
| F-06 绘图保存与提交 | 绘制 → 撤销 → 保存/重开 → 提交 | 像素恢复；提交带 `[temp]` 的引用 | 空画布回退为空引用；上传失败保留可恢复像素 |

- **权限与信任边界。** 浏览器侧沿用现有本机授权（`ASTROPHOTO_LOCAL_STORAGE`）；只读画布与只读 Inspector 不得写工作流。本次不改变权限模型，MCP 授权不在范围内。
- **状态归属。** 用户可见状态至少包含加载中、空、错误、禁用/只读、保存中与冲突；具体文案与焦点行为见 [UI/UX 状态清单](02_UI_UX.md#状态清单)。
