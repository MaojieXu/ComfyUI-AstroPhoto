## 背景、目标与使用者

操作者需要在系统盘与外置卷之间安排素材、输出和可重建缓存。更换磁盘、重启或失败后，要能看清哪个位置仍可用、哪个位置仍有权威和操作是否可以恢复。成功信号是相同工作区身份持续可定位，迁移前后可核查，原内容可保全。

本机单用户配置、迁移、取消和查看回执。宿主在加载时安排初始化。素材与处理服务消费当前默认写入位置。管理员控制受信本机部署；外部 Agent 无本专题写权限。

## 业务对象及集成边界

Data Root 持有实例身份、状态、配置和资产目录索引，一个实例有多个 Workspace、一个默认写入位置和一个活动 Cache。Workspace 持久 ID 与目录分离；受管资产通过工作区身份定位。缓存条目可重建并可能被活跃任务租用。Operation 保存目标、阶段和回执，可跨页面及进程检查。

## 存储契约

| 对象 | 权威位置与生效规则 | 不可用时的保护 |
| --- | --- | --- |
| Data Root | 默认当前 Windows 宿主运行账号的 `<用户目录>\.astrophoto`，例如 `C:\Users\48008\.astrophoto`。宿主启动时读取显式的 `ASTROPHOTO_HOME` 覆盖。根保存实例标识、设置与数据库；首次创建 `Local` 工作区与 Cache。 | 配置或数据库不能安全打开时保留文件并给诊断。切换 `ASTROPHOTO_HOME` 只选择启动位置；完整搬家需执行 FR-06。 |
| 默认工作区 | 设置存稳定工作区 ID。只有可写且可用的工作区可以被设为默认。切换默认影响后续选择默认目标的写入，已经选定目标的作业和既有资产保持其工作区 ID。 | 缺盘、标记不匹配或权限不足时保留登记与默认 ID。当前选中目标不可写就拒绝或按作业状态等待恢复。自动回退由 Q-02 评审。 |
| 工作区目录 | 目录承载受管对象、正式输出和暂存。登记和目录身份匹配后才可使用。迁移是复制、校验、切换同一 ID；重绑是同一盘/目录已移动后，凭原有标记重新登记路径；解除登记仅移除位置记录，受默认、引用和活动作业保护。 | 原目录离线时不可凭路径名称、盘符或另一处空目录冒认。正确目录在原路径重新出现可恢复，移到新路径则走重绑。只读且身份有效时，受管读取可以继续，写入必须阻止。 |
| Cache | 只存可重建数据，活动路径和限额由独立设置控制。仅清理可证明归属本实例、且可取得租约的缓存；Cache 改址保留旧缓存，正式产物的去向由工作区决定。 | 缓存离线、只读或身份异常时保持配置可诊断。恢复 Cache 后可重新生成预览，既有正式输出仍按工作区身份读取。 |

| --- | --- | --- |
| 设备与设备组合 | 目录记录位于 Data Root 的资产数据库，由设备服务访问。 | 工作区默认切换、单卷离线或迁移应保持同一 Data Root 中的既有设备与组合可读。Data Root 初始化失败由设备 API 的可用性契约处理。 |

## Windows 首次启动与开箱即用

1. 本地用户正常启动 ComfyUI 时，AstroPhoto 在宿主加载阶段为当前运行账号自动选定并初始化 `.astrophoto`，默认同时准备 Local 工作区和 Cache。用户可以先用默认值，再进入 Storage 查看实际绝对路径。高级入口再展示工作区、缓存和搬家选项。现行存储写 API 仍要求显式开启可信本机能力，是否简化这一步单列 Q-06。
2. Windows 默认路径沿用现有 Python `Path.home() / ".astrophoto"`。Python 在 Windows 优先用 `USERPROFILE`，缺失时用 `HOMEDRIVE` 与 `HOMEPATH`。依据是宿主进程账号和实际绝对路径，支持用户名含空格、中文或用户目录位于其他盘。服务账号启动时用该服务账号的目录；管理员需要指定其他位置时，在启动环境设置明确的绝对 `ASTROPHOTO_HOME`。
3. 遇到无法解析用户目录、目录不可写、配置无效或已有数据无法打开时，期望 System Status 给出原因和实际选址信息，保护现有数据。不得改到当前工作目录、仓库或其他账号目录继续写。诊断文案、环境丢失的异常分支和非交互账号需要按 CASE-01 复核。

## 主要场景

- S-01 首次加载创建必需本地数据，重启核对相同身份；发现破损配置、旧开发库或不兼容数据给诊断并保留原件。
- S-02 登记、验证、改名、启停及选择默认；目录变动时用真实工作区身份重绑，合适时仅移除登记。
- S-03 迁移提交前让用户核对位置和影响；执行前检查路径、身份和容量，复制并校验后切换权威位置。取消、刷新或中断后重新查询原操作。
- S-04 调整默认导入模式或 Cache；清理前确认，显示移除、保留和失败结果。

## 状态、权限与异常规则

默认数据根 `~/.astrophoto/`，默认导入模式 reference。默认切换只影响后续默认写入，既有文件不会搬动。目标不接受危险重叠路径、越界链接或身份冲突。默认、被资产引用或有进行中操作的位置不能直接移除。迁移保护原目录与外部引用，提交前原根继续有效；取消和失败可能保留可供检查的目标数据。可重建 Cache 独立于科学输出，限额首启默认 20 GB，用户可调，切换 Cache 不自动删旧目录；只清理本实例拥有且无活动租约的条目。写入限显式开启、单用户本机同源直连并拒绝代理路径。陈旧配置须读最新状态后重试。

工作区状态分别识别在线、离线、只读、身份不匹配、禁用、迁移中和检查错误。可获取容量时报告总量与可用量，显式验证另做临时写探针。迁移受理回执只表示操作已创建，后台冻结清单、检查容量并按作业标记恢复。数据库提交是根切换的权威时点。提交前取消或失败保留源根的登记，提交后的重试只完成目标核对与回执收尾。当前操作进入终态后，同键查询原操作，不能把终态当作可续跑状态。

## 交付范围与非目标

覆盖初始化、健康、工作区迁移、整库搬家、真实素材纳管、缓存与信任边界。资产记录身份由素材专题掌管。商业代理、多用户、跨机器同步、复杂自动缓存淘汰和任意旧开发库自动升级不列入已确认范围。整库搬家已纳入需求，交付形态和首次可用版本待评审。

## 功能需求与验收

### FR-01 首次启动、身份与诊断

**状态、必要性及场景** Confirmed · 首版必要 · S-01。

仅加载宿主时初始化实例。Windows 首启默认在运行账号的用户目录创建 `.astrophoto`。重复加载保持登记及设置。数据库不兼容或配置错误时显示诊断并保护既有用户文件。

**验收** 无覆盖时解析当前 Windows 账号的绝对用户目录。覆盖时只选经过验证的绝对路径。隔离空目录启动两次后 ID 稳定；注入不兼容数据库或坏配置，状态可读且源文件摘要一致。 [CASE-01](05_TEST_PLAN.md)

### FR-02 工作区配置、验证和迁移

**状态、必要性及场景** Inferred · 首版必要 · S-02/S-03 · FR-01。

可登记和管理多个工作区，验证可写与容量，选择默认、重绑同一身份、发起整库工作区迁移；受保护位置不得被解除登记。

**验收** 默认切换不搬旧文件；错误标记或重叠目标被拒绝。同卷/跨卷校验受管文件摘要和件数后才切换，失败前原根可用。 [CASE-02](05_TEST_PLAN.md)

### FR-03 设置、缓存与权限

**状态、必要性及场景** Confirmed · 首版必要 · S-04 · FR-01。

设置保存有修订保护。活动 Cache 可配置并经确认清理；区分缓存与正式输出。越权时无写入，不改 ComfyUI 全局目录。

**验收** 旧修订或外部请求被拒绝；确认前库和文件不变；清理回执准确且保留活跃缓存、陌生文件和正式输出。 [CASE-03](05_TEST_PLAN.md)

### FR-04 持久回执、取消与恢复

**状态、必要性及场景** Inferred · 首版必要 · S-03 · FR-02。

可以查询进行中、成功、失败、取消和可重试操作；同一意图重试不重复启动，重启后恢复或给出可操作状态。

**验收** 在提交前及提交后分别中断，重开能查同一回执。执行中的取消先记录请求，最终状态以回执为准；重复查询不触发再次复制。[CASE-04](05_TEST_PLAN.md)

### FR-05 离线工作区与解除绑定

**状态、必要性及场景** Inferred · 首版必要 · S-02 · FR-02。

显示离线或恢复状态。重定位保留工作区身份和受管资产引用。只有符合条件时解除登记，解除不删除文件。

**验收** 模拟盘符变化后用匹配标记重绑，错误工作区拒绝；尝试解除一个仍被引用的位置被阻止。 [CASE-05](05_TEST_PLAN.md)

### FR-06 整个 AstroPhoto 数据根搬家

**状态与来源** Confirmed（整库迁移需求），来自用户对 Q-01 的批注；下列流程为 Proposed。当前代码支持启动时选根和单工作区迁移，整库搬家待实现。

建议第一版支持同一台电脑停机搬家。用户选目标并确认预检后，系统冻结写入、确认没有活动作业，取得一致的 SQLite 状态再复制校验。目标验证前保留源。验证后谁能写、如何启用目标以及写入后如何返回旧位置，由 Q-13、Q-14 决定。建议保留外部 reference 位置、随新根更新根内工作区及内部文件路径，并重建 Cache。根外工作区与 Cache 的包含范围见 Q-12，源清理和独立备份见 Q-01、Q-15。

**验收** 从用户目录搬至另一测试目录后，同实例 ID、设备和组合、素材记录、工作区 ID 与正式输出均可回读。校验受管文件摘要并核对外部 reference 与工作区。目标验证失败时旧根仍可启动；目标已有新写入后的返回流程单独按 Q-14 验收。 [CASE-07](05_TEST_PLAN.md)

### FR-07 真实素材复制纳管

**状态与来源** Confirmed（实际文件复制纳管需求），来自用户对 Q-01 的批注。copy API 已有实现，当前 Assets 页面仍为占位，面向用户的导入入口待素材 Feature 接续。

用户选真实 FITS 等源文件并选择复制纳管。使用默认 Local 时，副本写入 Data Root 下的受管目录，数据库用资产 ID、工作区 ID 和相对键建立关联。源文件留在原处。显式改选其他工作区时，提交前应显示副本去向。reference 保留原路径，继续作为日常默认模式，Q-06 可评审界面怎样降低选择负担。 [素材 PRD](../asset-import-library/01_PRD.md)

**验收** 选受信目录中的实际 FITS，确认源和副本摘要一致。重启后能按资产 ID 找回副本；再迁移其工作区，旧资产 ID 仍命中新根。离线、容量不足或写入失败时，说明结果并保全源文件。 [CASE-08](05_TEST_PLAN.md)

**影响与验收** FR-02、FR-04、FR-06。测试目标空间不足、预检后剩余空间变化、刷新找回，以及历史列表在选 C 时的多作业场景。

### Q-05 什么时候能声明支持外置盘

**待选。** USB 盘上的工作区从 `E:\Astro` 变成 `F:\Astro`，重绑后同一份素材应能按原 ID 读回。另一个场景是从固定 C 盘搬到固定 D 盘。

| 选择 | 实际行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 跨卷和拔插都实测（建议）** | 当前版本通过真实第二卷迁移、拔插和变更盘符后的重绑，才对外声明支持外置盘。 | 覆盖真实换盘和失联场景，能验证原资产 ID、文件摘要及恢复结果。 | 需要可安全操作的第二卷和外置盘。缺环境时完整验收等待。 |
| **B · 首版只验同卷** | 首版只验收同卷迁移、模拟异常和目录重绑。对外置盘与跨卷保留待验证状态。 | 当前可用环境也能推进首版。 | 无法确认使用第二卷或外置盘的用户能否完成真实迁移和恢复。 |
| **C · 固定双盘先验，USB 拔插后验** | 实测固定 C 盘到 D 盘，首版只对外承诺已通过的跨卷迁移。USB 拔插和盘符变化后补验。 | 能给固定多盘用户明确支持范围，也可分批验收。 | 仍需可用第二卷，并需清楚区分固定跨卷和外置盘恢复。 |

**影响与验收** FR-02、FR-04、FR-05。记录实际测试过的盘、场景和结果。整库搬家若承诺跨卷，按 FR-06 单独验收。 [验收计划](05_TEST_PLAN.md)

### Q-06 普通本机安装怎样开启存储写入

**待选。** 用户在同一台电脑启动 ComfyUI，希望打开 AstroPhoto 后直接导入。默认目录已有自动初始化，现行相关写 API 仍需显式设置 `ASTROPHOTO_LOCAL_STORAGE=1`。

| 选择 | 实际行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 环境变量显式开启** | 延续现有规则，首次尝试写入时显示如何开启。 | 操作者明确控制启用时机，现有部署行为易于维持。 | 普通用户要改启动配置，可能还需重启，开箱体验较弱。 |
| **B · 满足本地限制时默认开启（建议）** | 单用户、回环直连且通过来源检查时默认开放相关写入。其他部署仍按现有规则检查。 | 普通本机用户安装后可以直接进入导入流程。 | 默认行为改变，需要设计显式关闭方式，复核本机、跨源、代理及多用户边界。 |

**影响与验收** FR-01、FR-03、FR-07。授权规则和导入界面分开验收。两项都可把高级存储选项折叠，reference 仍是导入默认，复制时明确显示副本去向。


### Q-07 预期的 Data Root 不见了，能否创建空实例

**当前** 空的显式绝对路径可以初始化；占用、丢失既有 manifest 或不兼容数据库会触发保护。宿主未维护跨启动的活动实例指针。用户最容易误把空设备列表当作数据已丢失。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 任意合法空根直接初始化** | 无 manifest 的合法空目标按新实例处理。 | 与现行正常首启一致。新实例和隔离测试简单。 | 路径拼错、账号切换或挂载异常也可能创建空库，给人旧数据消失的印象。 |
| **B · 默认新装自动，显式改址先确认（建议）** | 首次使用默认目录可初始化。显式选空根时区分「创建新实例」和「打开已存在实例」。选后者必须找到预期实例。 | 保留开箱即用，也保护改址和搬家。 | 需要在启动配置或恢复入口指定预期，兼容现有显式空根部署和测试。默认目录被意外移走时仍可能缺少历史线索。 |
| **C · 记住上次实例** | 记录上次根路径和实例 ID，找不到即进入恢复入口。 | 缺盘或误选更易发现。 | 根外多一份持久状态，需定义谁优先、如何重置和服务账号如何隔离，与开箱即用存在额外管理成本。 |

**影响** FR-01、FR-06。分别验证干净首启、已有根丢失、错误盘符、已有但不兼容的目录和显式创建测试实例。

### Q-08 同一个 Data Root 能开几个 ComfyUI

**当前** 启动和业务操作有文件锁和工作区租约，未有整个宿主生命周期的唯一写入者契约。两个窗口访问同一宿主与两个宿主进程打开同一根是不同场景。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 一个写宿主，多窗口可用（建议）** | 同一根只允许一个宿主写，其他进程提示占用或使用独立根。 | 简化迁移、恢复与重复作业判断。 | 多宿主共享设备目录的用户要切换或分开配置。需要定义崩溃后的锁释放和诊断。 |
| **B · 允许多个写宿主** | 明确支持多进程共用同一实例，以租约、修订与事务协调。 | 共享目录和配置更方便。 | 必须验证缓存、后台工作、Siril 回执和整库维护的并发行为，覆盖远超多进程启动测试。 |
| **C · 一个写宿主，其他宿主只读** | 第二宿主取得有限只读功能。 | 能方便查看共享目录，并限制写冲突。 | SQLite 读取、Cache 与预览会各有边界，需要额外能力模型和故障提示。 |

**影响** FR-01～06。测试第二个进程的实际能力、首个进程退出以及停机搬家时拒绝新写入。

### Q-09 首版允许哪些路径和卷

**当前** 路径守卫要求本机绝对路径，并拒绝链接、重新解析点和不支持的卷类型。Windows ACL、长路径、云盘占位与特定磁盘格式需分别核对。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 本机固定卷和经验证的直连卷（建议）** | Data Root、工作区与 Cache 使用通过校验的本机路径。按 Q-05 所选范围声明实测支持。 | 锁、持久性和可诊断性相对可控。 | 网络盘、云同步路径和经链接组织的目录可能无法使用，需提供具体拒绝原因。 |
| **B · 逐类开放外部来源** | 活动 Data Root、工作区和 Cache 维持 A。素材 reference 可对已批准并验证的额外来源单独支持。 | 可以引用更多已有档案，无须搬走整库。 | 外部源读取超时、重连和变化检查增加成本。与现有路径守卫的差异必须按类型实现和测试。 |

**影响** FR-01～03、FR-05～07。按设备、卷、路径类型给独立验收结果。活动数据库直接放网络或同步目录超出现有范围。

### Q-10 用户如何授权导入来源

**当前** 即使写 API 已打开，仍需 `ASTROPHOTO_IMPORT_ROOTS`。选路径、授予访问权限与复制数据是三个动作。拖拽或选择文件本身也不证明宿主可以读取该路径。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 管理员预配来源目录** | 保持启动时配置允许的绝对本机来源。 | 当前后端已支持，信任范围稳定。 | 用户首次导入通常还要手配目录。允许目录过大时权限暴露面也随之变大。 |
| **B · 宿主确认后记住所选目录（建议先验证宿主能力）** | 用户通过受控入口选择文件夹，显式确认此范围，后续可复用并撤回。 | 既省去启动变量，也适合重复处理同一拍摄目录。 | 需要证明宿主拿到的是实际选择结果，并处理子路径、撤权及重启。已纳管副本与外部 reference 受撤权影响不同。 |
| **C · 仅授权本次选中的文件** | 每次确认具体文件或批次。后续任务再次取得权限。 | 权限范围更小，容易看出此次读了哪些文件。 | 大批次和无人值守麻烦；重启恢复或 reference 的长期可用性需要独立授权设计。 |

**影响** FR-03、FR-07。与 Q-06 组合验收，从一个干净本机安装走到首次导入，覆盖撤权、路径替换和已受理作业。

### Q-11 局部故障时要给用户看到什么

**当前** 存储快照含全局健康、默认位置、Cache 和写能力。工作区的展示状态可能被迁移或禁用覆盖。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 总体状态加详情** | 首屏保留一个状态，用户进入对应设置找原因。 | 实现和界面维护成本低。 | 容易误以为整个功能坏了，或认为授权为 true 就一定能写。 |
| **B · 按用户动作提供可用性和原因（建议）** | 给「查看目录」「引用」「复制」「预览」「正式输出」等动作各自反馈，显示关键依赖和下一步。 | 局部故障时仍能完成可用工作，客服更易复现问题。 | 前后端需维护共同的能力契约。状态可能在真正执行前变化，服务端仍须重查。 |

**影响** FR-01～05、FR-07。保持总状态作为摘要，按所选方案核对默认卷只读、Cache 离线、Siril 未配置及没有导入来源。

### Q-12 整库搬家包含哪些内容

**当前** 已有单工作区迁移，无整库文件清单。资产数据库跨设备、素材、工作区和作业；根外路径来自工作区或 reference 登记。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 搬持久实例数据（建议）** | 搬设置、数据库、根内受管原件与正式输出。核对身份并改写根内路径。根外数据保留原路径。Cache 与运行锁在新根重建。 | 空间和停机时间可控，根外摄影原件不受影响。 | 根外盘缺失后部分资产仍不可读，需要明确依赖清单与后续重绑。 |
| **B · 连可重建数据一起搬** | 在 A 基础上搬迁符合归属的 Cache 等可重建内容，再重新验证可用性。 | 有机会保留近期预览，首次打开较快。 | 增加容量和验证成本。现有 Cache 条目身份依赖设备、inode 等文件属性，跨卷需要重新登记或选择性丢弃。 |
| **C · 搬持久根并可带走指定根外工作区** | 搬家时额外选择一个或多个已登记工作区，明确重写对应位置。 | 能一并完成主机磁盘重组。 | 容量、离线、单卷失败和回滚更复杂。源选择、校验和事务边界须明确。外部 reference 仍按资产契约处理。 |

**影响** FR-04、FR-06、FR-07。测试含根外离线、绝对路径、未知文件、Cache 和未终结作业的实例。

### Q-13 整库搬家由谁停机、复制和启用目标

**当前** `ASTROPHOTO_HOME` 仅在启动选根。当前运行根内的 API 不负责更改宿主进程环境和重新启动它。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 手册引导停机搬家** | 提供清单、人工停机、复制、启动路径配置和验证步骤。 | 工作量最小，适合管理员和自定义启动方式。 | 路径重写、错误目标和 SQLite 一致性依赖受支持的工具或手动操作，普通用户容易做错。仅有复制说明不足以交付 FR-06。 |
| **B · 有预检的停机搬家工具（建议）** | 宿主生成搬家计划。由宿主外工具确认停机、复制并校验，再提示用户以新根启动验证。 | 可重复验证，停机窗口清楚，不依赖控制所有宿主启动方式。 | 需要维护工具、计划格式、失败现场，并为便携版和服务部署写清启用路径。 |
| **C · 应用内发起并自动切换** | 应用协调排空写入、停止、交给外部进程复制、改启动选址和重启。 | 正常流程最省用户操作。 | 涉及宿主生命周期、权限和恢复代理，便携版、服务、多个启动器的集成与维护成本最高。 |

**影响** FR-01、FR-04、FR-06。明确哪些步骤可在活跃宿主内完成，验证旧根与新根各自启动、关闭及阻止同时写入。

### Q-14 目标开始写入后，旧目录还能怎么用

**当前** 单工作区迁移保留源文件。整库搬家尚未建立单一写入者切换。新的 SQLite 写入、设备记录和科学产物可能与旧副本分叉。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 验证期间可回旧根，启用写入后只把旧根当快照（建议）** | 新根先验证。生效并产生新写入后要返回旧位置，需把当前有效实例重新搬回，或做明确的恢复。 | 权威位置清楚，降低误丢新数据的风险。 | 有额外验证阶段。启用后撤回需要再停机、准备空间。 |
| **B · 写入后仍支持一键回退** | 回退流程从新根采集生效后的写入，完整验证后切回旧位置。 | 迁移后处理问题时用户操作更少。 | 实际接近反向搬家，需要捕获新数据、冲突、空间与中断恢复，不能只改路径。 |

**影响** FR-04、FR-06。验证新根已有新增设备和正式输出时，恢复能保留有效状态。关联 Q-01 的清理时点。

### Q-15 首版是否提供独立备份与恢复

**当前** 有内部 SQLite 备份 helper，未形成覆盖配置、受管文件、恢复后运行和丢盘的用户备份契约。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 文档化停机备份和恢复验证（建议）** | 说明备份哪几类文件、怎样停止写入、哪些外部目录需单独保存，以及怎样在隔离位置验证。 | 能给需要备份的用户明确步骤，首版范围小。 | 依赖用户执行和保存备份。对普通用户可发现性较弱。 |
| **B · 提供实例备份与导入恢复** | 生成可验证的备份清单，在隔离目标恢复后检查数据库、文件和缺失引用，再由用户确认启用。 | 可核对恢复责任，适合定期备份和换机前检查。 | 要实现恢复协议、兼容策略、容量检查和失败回滚。跨机器路径映射仍需独立定义。 |
| **C · 提供定期增量备份和保留规则** | 在 B 的基础上加计划、验证和历史恢复点。 | 降低用户忘记备份的风险，减少重复复制。 | 需要额外存储、监控、清理、权限管理和恢复演练，首版维护成本最高。 |

**影响** FR-01、FR-06。单独验收可恢复性，区分数据库副本、完整实例与外部参考丢失。

### Q-16 两块盘有同一工作区标记时怎么重绑

**当前** 原路径仍有匹配标记时拒绝重绑，原路径不可用时接受匹配标记的新路径，并保持工作区 ID。重绑本身不逐文件验证清单。原盘离线时，旧克隆可能被选中。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 手动选盘并验证标记** | 现行方式，用户依靠路径与标记完成重绑。 | 恢复快，特别适合同一盘变更盘符。 | 可能接受旧克隆，直到读取时才发现缺失或陈旧文件。 |
| **B · 标记加登记文件检查（建议）** | 先查标记、实际卷和已登记文件基本完整性，再给出异常和确认。 | 能发现常见的选错盘、残缺目录和遗漏资产。 | 大库扫描有成本，需定义部分缺失是否可重绑及如何提示。同尺寸内容变化仍取决于 Q-24。 |
| **C · 强校验通过才允许重绑** | 对可用清单核对全量内容摘要，任何差异需要另走修复。 | 对恢复副本更严格。 | 旧资产可能没有摘要，几 TB 数据重绑很慢，简单换盘符也需全量读。 |

**影响** FR-02、FR-05、FR-07。测试同标记旧克隆、缺失文件、原盘重新接回及恢复后的读写。

### Q-17 迁移期间，已登记的素材能否继续读

**当前** 非终态迁移可把状态标为 `migrating`，常规受管解析通过 `require(write=False)` 也可能收到 `STORAGE_BUSY`。正式写入还有租约。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 迁移期暂停该工作区读写（建议首版）** | 读写明确提示繁忙，其他工作区继续运行。 | 提交窗口清楚，易于验证。 | 长时间迁移会影响依赖该工作区的查看和处理。 |
| **B · 切换前允许读取源，始终冻结写入** | 读取绑定当时已验证的源路径，切换后新读取使用新根。 | 大文件搬家期间可继续浏览旧结果。 | 需要处理长时间打开的文件、外部修改和读取快照。 |
| **C · 读写继续，追补变更** | 记录复制期间的写入变化，在切换前追平。 | 可减少停机时间。 | 需要增量同步、双重校验与最终冻结，复杂度最高。 |

**影响** FR-02、FR-04、FR-05。测 FITS 保持打开、跨切换读、运行中 Siril、已有导入与新写竞态。

### Q-18 失败或取消后，残留文件负责谁来清理

**当前** 单工作区迁移可保留作业标记与复制文件，重试使用持久计划。终态作业不会继续执行。残留使下一次需要空目标的迁移可能无法开始。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 保留并说明路径** | 展示已完成数据、目标路径和手工处理指引。 | 不增加文件删除风险，失败现场可诊断。 | 残留占空间，新迁移可能需要另选空目标。 |
| **B · 按作业身份显式清理（建议）** | 用户确认后只处理可证明由该终态作业产生的目标文件。 | 能把空间管理和恢复做成闭环，保留来源和陌生文件。 | 需要可靠的所有权证明和部分清理回执。存在复用或状态冲突时必须拒绝。 |
| **C · 自动清理可证明归属的残留** | 过保留期限后自动清掉不可恢复的作业产物。 | 长期可减少无主占盘。 | 可能失去故障线索，需管理期限、实际占用以及用户正在核查的目录。 |

**影响** FR-02、FR-04、FR-06。与 Q-01 的成功源清理独立。测试旧目标夹有其他文件、权限拒绝、清理中断及继续操作。

### Q-19 没收到提交响应时，怎样避免再复制一份

**当前** 后端支持同 kind、同 key、同请求复用，同键不同内容拒绝。现行页面用接到的作业提示跟踪。跨刷新、重复意图和两个页面冲突需独立验收。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 只按请求键去重** | 客户端负责保留原键，手动再次提交有可能发起新操作。 | 规则简单，支持用户主动另做一次。 | 响应丢失或刷新时用户可能无从判断，copy 新作业还可能产生第二份资产。 |
| **B · 恢复上次提交意图（建议）** | 对「再次连接」「重试」保留原键或从近期回执找回同一操作。另给明确的「开始新作业」。 | 可恢复不确定的提交，重复手势与主动新建有区别。 | 需定义浏览器状态保留、跨标签页协调和旧键失效。 |
| **C · 服务端自动合并同内容请求** | 在定义好的条件和窗口内，目标、来源等相同则合并。 | 不依赖单个页面记忆。 | 用户可能有意重复复制，后台无法仅凭内容判断意图。需要额外的显式新建语义。 |

**影响** FR-04、FR-07。分别测试响应丢失、浏览器刷新、两个窗口、不同参数用同键及请求重发。

### Q-20 哪些故障自动恢复，哪些等用户处理

**当前** 启动会重排非终态作业。恢复策略依赖阶段与错误，终态不再执行。取消是请求，最终结果以回执为准；根切换后继续收尾。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 启动恢复与手工重试** | 延续现行方向，提供错误和「重试」入口。 | 运维简单，少消耗磁盘 I/O。 | 用户可能看不到明确动作，离线后接回盘仍要回来重试。 |
| **B · 区分等待、可重试和终态（建议）** | 暂时忙碌可有限重试。盘不可用、容量不足或身份冲突等按原因等待明确恢复；已提交阶段只做收尾。 | 用户能判断该等还是处理，减少无效重跑。 | 需维护阶段与错误矩阵、次数与超时、回执和取消竞态。 |
| **C · 自动长期等待并反复恢复** | 有计划地监测卷和重试，直到用户取消或超过约定期限。 | 无人值守恢复能力更强。 | 会长期占用任务配额和目标保留，后台资源与告警维护成本较高。 |

**影响** FR-02、FR-04、FR-05、FR-06。以接受时间、提交点、重试次数、取消终态和磁盘残留作为验收证据。

### Q-21 工作区里的手工文件和未知暂存怎么处理

**当前** 工作区迁移拒绝未知顶层内容、非空暂存和缺失的登记文件。受管目录为 `objects`、`outputs`、`.staging`。

| --- | --- | --- | --- |
| **A · 严格拒绝并说明冲突（建议）** | 预检指出陌生内容或哪条资产缺文件，用户先解决再搬。 | 不误搬私人文件，目录边界清楚。 | 少量额外文件也会打断流程，需可操作的报告。 |
| **B · 预览后仅搬受管内容** | 明确展示被排除项，用户接受后搬受管文件；缺失的登记文件仍需处理。 | 用户可在有陌生文件时完成搬家，旧目录留有这些文件。 | 用户可能误解为所有文件都搬走，与源清理选项联动。 |
| **C · 审阅后包含普通附加文件** | 用户选中符合路径规则的附加文件一起搬，回执区分其是否登记。 | 满足归档工作区完整目录的需求。 | 文件所有权、冲突、空间和后续删除仍复杂，超出现有受管目录约定。 |

**影响** FR-02、FR-04、FR-06。覆盖未知根目录项、残留暂存、登记缺失与数据保护的提示。

### Q-22 Cache 达到限额时怎么处理

**当前** 写入检查已确认条目的记账字节及磁盘空间。没有通用自动淘汰策略。Siril 正式输出落 Workspace，部分处理或软件验证流程仍可能依赖 Cache。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 拒绝新增并提示清理（建议首版）** | 可重建新数据无法写时显示原因、当前占用与清理入口。 | 数据保留行为可预期，贴近当前实现。 | 一次处理可能因 Cache 满中断，需要用户处理。 |
| **B · 自动淘汰空闲条目** | 按明确排序清理无租约且可重建条目，腾出空间后再写。 | 正常用户较少停下来管理缓存。 | 需要定义淘汰顺序、保护打开的预览、记账和清理失败的行为。频繁重算会耗费时间。 |
| **C · 双预算，超额拒绝** | 分别显示和约束可重建条目及处理临时空间，任一预算或磁盘空间不足时拒绝新任务，由用户清理。 | 用户更容易理解「页面用量低但磁盘满」，并发临时空间也可约束。 | 增加预留、释放及崩溃回收逻辑，也增加高级设置项。用户仍要介入清理。 |

**影响** FR-03、FR-04。用缓存记账与实际磁盘占用双重核对，覆盖并发临时任务、限额下调及正式文件保护。

### Q-23 改 Cache 路径后怎么处理旧预览和旧空间

**当前** 改址保留旧 Cache。缓存读取校验活动根。通用清理使用当前根、文件身份和租约；Siril 临时目录有独立的生产者清理路径。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 切换后重生成，旧位置手动管理（建议首版）** | 明确提示旧候选可能失效、旧目录仍在，可重新生成。 | 规则直观，改址无需迁移临时数据。 | 需要重算，旧盘空间由用户管理。 |
| **B · 短期保留旧预览后提供旧 Cache 清理** | 换址后允许既有预览在保留期内读取旧根，新预览只用新根。用户可确认清理。 | 切换过程对已打开的窗口更平滑，也能回收空间。 | 需要旧根登记、读权限、过期和清理协作。旧盘离线时仍会失效。 |
| **C · 换址前等待使用结束再切换** | 所有占用释放前显示处理中，新路径待启用。 | 切换较易解释，保持单活动 Cache。 | 任务长时间处理时可能阻塞切换，需要取消或超时规则。 |

**影响** FR-03、FR-04。测试读取与清理冲突、活动预览、描述文件脱落以及不同步骤的失败回执。

### Q-24 哪些搬运要逐文件验证内容摘要

**当前** copy 导入用大小、文件身份和源状态进行保护；单工作区迁移在切换前校验 SHA-256，提交后恢复检查尺寸。整库未实现。普通可用性探测不能证明文件完整。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 保持按场景验证（建议）** | 导入继续使用现有验证方式，工作区与整库权威切换要求内容校验。恢复阶段根据上次验证证据与异常重新检查。 | 日常导入开销较小，为改变权威位置的操作保留更高标准。 | 机制不统一，必须把每种校验的保证范围写进回执。 |
| **B · 一律保存摘要并核对** | 新的受管文件、搬家和恢复均按内容摘要核对；历史资产提供补算。 | 易解释，支持后续检测损坏和备份对账。 | 大型素材的 I/O、耗电和时间显著增加，旧库需补算或显示未知。 |
| **C · 提供显式强校验选项** | 日常导入可选强校验，权威切换维持固定的最低标准，恢复可发起专项检查。 | 高价值归档可选择更强保障，普通用户不用承担所有开销。 | 增加用户选项、回执区分和测试组合。同一批文件的证据级别可能不同。 |

**影响** FR-02、FR-04、FR-06、FR-07。注入同尺寸变更、中途中断、旧文件无哈希及目标有错误副本，区分每个阶段预期能检测的故障。

### Q-25 Siril 排队后更改默认工作区，结果应该写到哪里

**影响** FR-02、FR-04、FR-05、FR-07。用多个等待任务、默认值切换和卷离线验证落点，和 Q-02 的离线决策一起评审。

### Q-26 一批素材有的成功、有的失败，用户怎样继续

**当前** 导入保存逐项检查点。reference 对同路径同文件状态可跳过，新的 copy 作业允许独立副本。已有素材专题的内容身份和关联决定仍由素材专题维护。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 保留已完成项并汇报失败（建议）** | 回执分别显示成功、跳过、失败。用户从失败原因继续处理或明确重试。 | 大批量中一张损坏或失联原片不会抹掉其余成果。 | 用户要理解「作业完成」仍可包含失败项。只重试失败项要防止生成重复副本。 |

**影响** FR-03、FR-04、FR-07。覆盖重复内容、相同路径、源改变、取消、授权撤回和只重试失败项。资产去重与删除由素材 Feature 联合评审。

| --- | --- | --- | --- |
| **A · 保证位级内容、业务身份与目录结构（建议）** | 保持 FITS 原始字节、业务关联和必要目录形状。明确目标继承自身权限，可能变化的文件系统属性给出说明。 | 聚焦科研与应用正确性，跨支持卷较易验证。 | 依赖旧 ACL 或原始文件属性的用户需单独核对，不能把迁移视作取证级复制。 |
| **B · 保留受支持的常用属性** | 在 A 基础上尽量保持明确列举的时间和权限属性，在目标不支持时预检说明或阻止。 | 更符合归档和特定工作流预期。 | 不同卷能力不一致，权限迁移可能使新根不可访问，需要实机测试。 |
| **C · 按磁盘管理级别完整复制** | 对允许的卷承诺更完整的文件系统属性并提供失败回滚。 | 适合少数要求高保真磁盘复制的场景。 | 远超现有跨平台文件复制边界，可能与链接和路径安全策略冲突。 |

**影响** FR-02、FR-06、FR-07。始终对比 FITS 原始字节及身份；选 B/C 时另测名单中的权限与属性。ComfyUI 全局目录仍由宿主管理。

### Q-31 搬家后，已有 ComfyUI 工作流找不到文件怎么办

**当前** FITS 资产入口可以按资产 ID 解析位置；手填绝对路径的节点值由 ComfyUI 工作流管理。工作区迁移不批量改图，旧副本保留期间，硬编码路径甚至可能仍能读到旧内容。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 推荐稳定资产 ID，手填路径明确由用户重选（建议）** | 正式验收 ID 绑定的工作流。手填路径失败时提供位置提示和重新选择指引。 | 保持宿主所有权，避免无声改动用户图。 | 旧工作流可能要人工修改。源目录保留时，旧路径可能继续读旧副本。 |
| **B · 提供显式的当前图路径检查和重选** | 用户打开图并主动发起检查，预览 A→B 路径映射，确认后只改受支持节点并使用宿主撤销。 | 旧图更容易恢复，用户能看到变更范围。 | 依赖前端桥和宿主图契约，不能覆盖任意自定义节点或未打开的工作流。 |

**影响** FR-02、FR-05、FR-06、FR-07。用保存的实际工作流在迁移前后分别验证 ID 绑定、绝对路径与源副本清理。若选 B，须与工作流/宿主能力联合规划。

### Q-32 正式资产占盘时，首版提供多大的清理能力

**当前** Cache 清除只面向可重建条目。解除工作区登记不会删除目录，且登记被资产引用时会被拦截。素材尚无通用资产删除接口。Siril 正式输出是受管资产。

| 选择 | 行为 | 优点 | 缺点与代价 |
| --- | --- | --- | --- |
| **A · 首版显示正式占用，删除留给素材专题（建议）** | 向用户区分可清理 Cache、正式数据与外部原件。存储页负责工作区管理，不提供直接删正式资产的入口。 | 职责清晰，降低误删与索引悬挂风险。 | 用户暂时不能在应用中逐项释放正式产物空间，需说明已有可用方式。 |
| **B · 联合实现带引用核对的正式资产清理** | 先展示资产、会话、处理结果和源文件状态，再让用户明确选择解除引用或删除受管副本。 | 能从应用内安全回收按项确认的空间。 | 需要资产生命周期、引用查询、错误回滚和并发写入保护。外部摄影原件仍保留。 |

**影响** FR-02、FR-03、FR-05、FR-07。与素材删除专题共享验收，区分清 Cache、解绑、删除受管副本和迁移旧根清理。
