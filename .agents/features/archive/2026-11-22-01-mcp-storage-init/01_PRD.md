# 扩展启动时自动初始化 AstroPhoto 目录

PRD v0.13 · 用户确认最终验收范围 · 2026-11-22

## 目标与范围

用户安装 AstroPhoto 扩展后，ComfyUI 首次加载并启动扩展时，扩展自动在宿主实际使用的数据根创建四个顶层目录和两个配置 JSON。安装阶段只部署扩展，数据目录和配置的生成发生在宿主启动扩展时。扩展独立完成初始化，无需安装或连接 MCP，也无需手动调用 `init()`。

默认数据根为宿主进程用户的 `~/.astrophoto/`。扩展确定实际使用的数据根，验收可使用空的隔离数据根。四个目录允许包含扩展正常启动所需的文件与子目录。

数据根的管理记录和协调能力由 `.astrophoto/` 内部承担，不再依赖用户目录下独立的 `.astrophoto-control/`。涉及项目现有调用链的调整应保持一致；具体实现和影响由 TECH 核实。

## 目标结构

```text
.astrophoto/
├── config/
│   ├── manifest.json
│   └── settings.json
├── database/
├── storage/
└── runtime/
```

目录树只列出本次验收所需的路径。用户无需自行创建目录或编辑 JSON。

## 启动时核对与补齐

扩展每次启动核对目标结构。在已初始化且配置有效的数据根，`database/`、`storage/` 或 `runtime/` 缺失时，扩展在本次启动中直接创建所有缺失的这些顶层目录，再复核四个目录及两个配置文件。目录补齐无需数据库健康、工作区登记或缓存状态等业务检查作为前置条件。

目录补齐仅创建缺失的顶层目录，并保留已有内容。扩展正常启动可以生成必要文件或子目录。本功能验收聚焦四个顶层目录和两个配置 JSON。目录内业务文件的重建、业务数据恢复、业务服务就绪和旧布局迁移均超出验收范围。

已有有效配置和用户数据予以保留；扩展管理的临时缓存按其现有生命周期处理，本次不修改缓存清理行为。

首次启动在空数据根生成两个配置 JSON。再次启动保留有效的已有配置和内容。已初始化实例缺少约定的配置文件时，包括整个 `config/` 缺失，扩展启动时报告具体缺项并保留仍在的文件。

## 配置文件

首次启动生成的 `config/manifest.json` 和 `config/settings.json` 须能由扩展现有的启动和设置逻辑读取。实例 ID 和首建工作区 ID 均须有效，首建时的默认工作区 ID 与首建工作区 ID 一致。再次启动保留已有有效配置。

具体字段和默认值沿用现有首建与设置读写逻辑，由 [TECH](03_TECH.md#配置-json-与现有读写) 记录。本功能无需新增版本维护机制。

## 功能需求

| 编号 | 要求 |
| --- | --- |
| FR-01 | 扩展在 ComfyUI 启动并加载它时自动初始化本地数据根。用户只需安装扩展并启动 ComfyUI。 |
| FR-02 | 扩展在空数据根创建四个顶层目录与两个配置 JSON。首建配置须能由现有逻辑读取并满足实例 ID 和工作区 ID 的要求。对已初始化且配置有效的数据根，在同次启动直接创建缺失的 `database/`、`storage/` 或 `runtime/`，随后复核目标结构。 |
| FR-03 | 使用同一数据根再次启动扩展时，保留有效的已有 JSON 和其他已有内容。目标结构完整时无需重新生成。 |
| FR-04 | 目标路径冲突、写入受阻、已初始化实例缺少约定 JSON 或已有 JSON 无法解析或验证时，启动过程报告本地存储初始化问题及原因，并保留已有内容。 |

## 决策与状态

- D-02 数据根由宿主中的扩展确定。
- D-05 用户确认四个目录可以包含扩展启动所需的内容。原决定中与 MCP 调用结果相关的验收随 D-08 更新。
- D-07 用户确认 `database/`、`storage/`、`runtime/` 可在缺失时直接补建，适用于单个或多个目录。触发时机随 D-08 改为扩展启动。关联 FR-02、FR-03 及 AC-02、AC-03、AC-05。
- D-08 用户确认以下四步流程。该决定取代 D-01 的 MCP `init()` 入口及 v0.8 的调用回执要求。关联 FR-01 至 FR-04、AC-01 至 AC-07。
  1. 用户安装 AstroPhoto 扩展。
  2. 用户启动或重启 ComfyUI，宿主加载扩展。
  3. 扩展后端在首次启动时自动生成四个目录和两个配置 JSON，后续启动时补建缺失的 `database/`、`storage/`、`runtime/`。
  4. 用户无需额外执行初始化，也无需 MCP 或手动创建目录与文件。
- D-09 用户确认优先快速实现，首版 JSON 以 ID 为主，本功能无需新增版本维护机制。关联 FR-02 和 AC-01。
- D-10 用户选择方案 A。验收聚焦四个顶层目录和两份有效 JSON。业务数据恢复和业务服务就绪超出验收范围。关联 FR-02、AC-03、AC-05 和 AC-06。
- D-11 用户选择方案 A。两份配置 JSON 由现有逻辑读取，首建实例 ID 和首建工作区 ID 须有效，首建时默认工作区 ID 与首建工作区 ID 一致。具体字段和默认值由 TECH 复用现有实现。关联 FR-02 和 AC-01。
- D-12 用户决定取消对 `.astrophoto-control/` 的依赖，将数据根管理记录和协调能力置于 `.astrophoto/` 内并同步项目相关调用链。保留既有用户数据，不在本 Feature 引入旧布局迁移。
- D-13 采用操作系统默认权限；已有用户数据和配置保留，扩展管理的临时缓存遵循现有生命周期。
- D-14 用户确认本次结项只验收 AC-01 的首建结构与 JSON。真实 ComfyUI 安装与启动、默认路径复测、原 AC-02 至 AC-07 和其他额外验证移出本次验收。原编号保留于历史记录。已有启动行为和功能需求仍以本文为准。
