## 范围、优先级与执行条件

P0 优先验证文件保留、权限、错误后无误写、任务恢复及核心端到端链路。P1 验证完整规则、跨客户端一致性和交互。P2 记录非阻断的视觉及规模观察。单次导入一个素材或一个子帧组，覆盖四种素材类型、两种存储方式、五类设备、四种校准主帧、项目逻辑树及当前 23 个目录 MCP 工具。DEV-079 的 27 工具和 DEV-086 的 26 工具为历史基线，DEV-093 完成名称驱动重构。旧混合分组、文件元数据识别及旧关系数据迁移属于历史范围；SQLite 旧关系清理仍有回归价值。图像处理、校准计算和主帧生成属于其他验收范围。

开发阶段按当前改动选择必要的局部测试和回归，不因本计划存在而自动执行完整验收；正式验收另按用户指示安排。仅在用户明确要求时使用 Computer Use 检查界面。

| 环境 | 准备与证据 |
| --- | --- |
| Repo | 使用独立 uv workspace 和 pnpm，记录 Python、Node、浏览器版本。HTTP 测试在允许绑定回环端口的环境运行，Windows 上使用短临时路径。 |
| Host | 隔离 ComfyUI 单用户回环实例，独立数据根、工作区、用户目录及输入输出。真实浏览器视觉复核按用户要求安排，Computer Use 仅在明确要求时使用。Windows 原生对话框单列，不以路径注入或 HTTP 替身代替。 |
| MCP | 分别套用进程内 Client、真实 stdio 子进程。以下有权限差异的场景使用隔离凭据，报告只保存配置状态、工具列表、错误和脱敏响应。真实聊天客户端作为单独验收证据。 |
| 双盘 | 两块可写物理盘，记录物理盘标识及卷标识。单盘多目录可验证事务及引用，但真双盘 TC-015 分支在硬件缺失时标为 Blocked。 |

每次运行使用独立运行标识和数据目录，不写共享预览库。磁盘文件比对统一记录 SHA-256、大小和路径，涉及时间戳或 FITS Header 时附相应快照。删除/断盘/迁移实验限定隔离夹具。事后先移除本次测试的项目引用及校准关系，再清理本次数据根和复制品。
