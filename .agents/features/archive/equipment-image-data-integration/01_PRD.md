## 1. 概述

本机天文摄影用户在 ComfyUI 中维护设备、设备组合和图像数据。受权的外部 MCP 客户端使用同一份业务数据完成查询及获准的管理操作。本 Feature 将三类业务的前后端、MCP 工具、持久化目录和业务数据库一并交付，并在目标宿主上联合验收。

## 2. 目标与范围

- **Confirmed** 完成设备、设备组合与图像数据管理的最终前后端联调，构建三个领域的完整 MCP 工具集。
- **Confirmed** 同期实现和验收有效数据根下 `storage/` 与 `database/` 的内部结构，覆盖文件落位、业务记录和两者的关联。数据根默认为 `~/.astrophoto/`，也可使用 `ASTROPHOTO_HOME` 配置。
- **Assumption** 「图像数据管理」以已确认的摄影素材库 v0.7 为起点，覆盖登记与导入、查询和组织、文件位置、科学属性、素材与设备及组合关联、校准关系和正式输出收录。
- **Proposed** 按用户任务列出三类管理的界面能力、MCP 可调用能力及授权方式，作为工具完整性的验收口径。
- **Proposed** 观测地、Capture Profile、硬件控制、自动校准推荐、外部画布桥接、新增科学处理算法和产品 Skills 属于本次范围之外。

## 3. 用户场景

1. 用户在 Settings 登记相机、主光学等设备，建立和修改设备组合，并处理名称、归档和引用冲突。
2. 用户在 Assets 登记实拍素材，核对位置与科学属性，按项目、会话或 Collection 管理素材，选择设备、组合及显式校准关系。
3. 受权 MCP 客户端查询刚由用户保存的记录，执行已确认可开放的管理操作。需要审批时，客户端读取审批结果，用户在 Assets 查看最终数据。
4. 用户查看默认工作区和可用空间，按需逐个登记其他工作区。工作区离线时，用户能从存储设置和素材界面判断受影响的文件位置。

## 4. 功能需求与候选验收条件

### FR-01 设备管理联调

设置入口和页面标题为「设备」，页面包含「我的设备」与「设备组合」两个标签。面向用户的组合名称及相关操作、素材字段和反馈统一使用「设备组合」。

设备表单基础区仅显示名称及成像关键参数。相机显示成像类型、像素宽高和传感器像素宽高，望远镜 / 摄影镜头显示口径和原始焦距，光学配件显示类别和标称倍率，滤镜显示类别。制造商、型号、备注以及其余规格、相机读出模式和滤镜通带收纳于默认折叠的高级区。设备名称必填，规格保持选填。已填写的高级字段应保留并可编辑，发生高级字段校验错误时展开显示。

沿用四类设备档案及已有专业字段。支持查询、新增、编辑、归档、恢复及受保护的删除。同一列表中的重名创建或改名应提示用户更换名称。被引用设备的删除失败应告知引用原因，保留业务数据。

- **AC-17** 分别打开四类设备的新增与已有设备编辑表单，核对基础字段和默认折叠的高级字段。仅填写名称可保存，填写高级字段后保存并重载保持原值，高级字段校验失败时可见错误和已有输入。 [DEV-008](04_DEV_LOG.md#dev-008-设备表单基础与高级分组) · [TC-010](05_TEST_PLAN.md#tc-010-设备表单基础与高级分组)

- **AC-16** 在中英文界面检查设备入口、页面标题、两个标签、组合操作与素材字段，中文使用「设备」「我的设备」「设备组合」，英文使用 Equipment、My Equipment、Equipment Groups。

- **AC-01** 在真实 Settings 界面完成设备新增和修改，重新打开后显示后端保存的值。用重名及引用删除场景验证，在失败后原记录和已有引用仍可读取。

### FR-02 设备组合管理联调

设备组合可以先保存不完整配置，配置齐全后显示为已配置。保留配件顺序及已有兼容数据。允许移除已归档设备的旧引用，禁止新增对该设备的引用。删除组合后将其从普通列表和新关联选择中隐藏，保留已有引用及相关设备。删除释放名称，旧素材仍可通过原 ID 读取历史组合。需要可恢复地停用组合时使用归档。

- **AC-02** 从 Settings 保存并重新读取一条设备组合，配置与配件顺序一致。尝试加入已归档设备时显示可处理的反馈，原配置保持有效。
- **AC-03** 删除一条已有关联的设备组合后，普通列表和新关联选择中不再出现该组合；可以同名新建；既有素材仍解析到旧组合 ID 和历史配置，相关设备仍可查询。另将一条组合归档并恢复，核对原 ID。

### FR-03 图像数据管理联调

项目虚拟文件夹在项目树中创建和重命名。根目录可直接新建，各文件夹提供新建子文件夹、重命名及删除操作。输入名称后回车保存，Esc 取消。删除前提示子文件夹和项目关联受影响，保留存储文件。创建项目时可选择常用文件夹模板。

项目文件树提供选中状态：选中文件夹后使用新建入口，在该文件夹下创建子文件夹；未选中时在项目根目录创建。文件夹右键菜单提供已有的子文件夹创建、重命名和删除操作。支持在同一项目内拖动文件夹及已有素材以调整虚拟层级，包括移到根目录；禁止移入自身或其后代。移动应保留子树与素材关联，不移动或复制底层素材文件，失败时提示原因并保持原有层级。

- **AC-22** 分别在未选择文件夹和选中文件夹时创建目录，核对实际父级；通过右键菜单创建子目录、重命名及删除。将目录拖入其他目录及项目根，重载后核对层级、子树及素材关联；尝试拖入自身、后代或其他项目应被拒绝，原文件保持不变；失败和版本冲突后可见反馈且原关系不丢失。 [DEV-070](04_DEV_LOG.md#dev-070-项目文件树交互) · [TC-070](05_TEST_PLAN.md#tc-070-项目文件树交互)

- **AC-21** 在项目树中依次创建根文件夹与子文件夹，重命名并重载确认层级和名称。验证 Esc 取消、删除确认及文件保留，项目模板和原有素材关联可用。 [DEV-060](04_DEV_LOG.md#dev-060-项目文件夹树内管理) · [TC-060](05_TEST_PLAN.md#tc-060-项目文件夹树内管理)

已有项目的项目行菜单提供「添加已有素材」。项目列表为空时先新建项目，再从该项目菜单操作。用户可从已登记素材中搜索、多选并批量加入项目。已属于项目的素材标识为已添加，重复添加保留已有位置。项目关联不会复制或移动素材文件。

- **AC-20** 在项目中搜索并选择多项已登记素材，提交后在项目中可见。已在项目内的素材和集合成员显示已添加，重复提交不更改其原位置。失败时保留选择且不产生部分关联。 [DEV-050](04_DEV_LOG.md#dev-050-项目添加已有素材) · [TC-050](05_TEST_PLAN.md#tc-050-项目添加已有素材)

素材页标签从左到右为「全部素材」「项目」。全部素材顶部移除更多操作菜单及其新建集合、收录正式产物、Agent 待审批请求和刷新入口。已选素材创建集合的入口保留。

以素材库现行产品基线组织登记、导入回执、检索、元数据、项目、会话、Collection、校准关系及正式输出。验证素材持有的设备和组合引用能够按现行规则保存和读取。覆盖文件缺失、版本冲突和受保护关系等影响日常管理的失败场景。

素材列表提供「导入单张」与「批量导入」入口。复制模式下点击入口直接打开文件选择，登记模式下进入服务端路径表单，可手动输入或调用文件选择器选取宿主机路径。单张入口一次选择一个文件，重新选择时替换原选择；批量入口支持多文件和文件夹。导入页内通过下拉框选择分类与项目，均可不指定，批量选择的分类和项目应用于本次所有素材。导入沿用设置中的登记或复制方式，预检和确认后执行。

- **AC-18** 在登记和复制两种导入方式下打开素材导入页，确认策略及首选位置摘要不显示，按当前设置完成导入，并能访问存储设置及查看适用的实际位置反馈。 [DEV-009](04_DEV_LOG.md#dev-009-隐藏导入策略摘要) · [TC-011](05_TEST_PLAN.md#tc-011-素材导入策略摘要)

- **AC-04** 在真实 Assets 界面登记样本，保存设备与组合关联，组织到项目并建立一项适用的校准关系。刷新后从界面和后端重新读到同一组记录和关系。

### FR-04 MCP 工具构建

设备及设备组合均提供 MCP 新建、查询、修改和受保护删除，与 Settings 使用同一套版本、重名和引用规则。保留现有查询及素材库工具兼容行为。用户可向 Agent 提供包含多类图像和校准素材的一批文件；Agent 在聊天中分组列出导入与绑定提案，用户按组明确批准或拒绝，随后可在聊天中看到各组结果。

Agent 可按名称查询已登记设备和设备组合，结合可用的文件元数据及用户说明提出绑定。提案使用稳定 ID，并在聊天中说明匹配依据。校准场从已登记校准库选取，用现有兼容规则校验后提出素材或 Collection 与校准主帧的关系。绑定表示记录关系，校准处理另行由用户发起。歧义、元数据缺失和兼容冲突需要用户补充，见 §8 的设计约束。

- **AC-06** 独立 MCP 进程连接真实 ComfyUI，发现并调用设备与设备组合 CRUD。核对 Settings 与 MCP 的 ID、数据及版本一致，覆盖重名、引用保护及缺少授权时零写入。
- **AC-07** 向 Agent 一次提供跨目标、设备组合、滤镜和类型的素材。Agent 从现有设备组合与校准库给出分组提案，逐组说明数量、目标项目、设备/组合、校准关系及未匹配项。批准一组、拒绝一组、保留一组待定。核对仅获批且通过执行前验证的操作落库，逐组可查询结果，已有业务记录保持正确。客户端、授权凭据、过期、重放和失败路径见 TC-117。


### FR-05 工作区与文件布局

交付有效数据根下的工作区内部结构。以当前 `storage/<工作区 UUID>/` 为基线，默认工作区包含工作区身份、受管素材、正式输出和发布前的暂存位置。已有工作区继续按登记位置解析。Copy 素材写入有效工作区并登记受管位置，Reference 素材保留原件及外部位置登记。正式输出有可追溯的位置，暂存文件只在发布完成后才可作为正式文件使用。设置中的存储状态和 Assets 中的文件位置反馈以同一份登记为依据。 [本地存储契约](../../../../docs/local-storage.md)

- **AC-09** 从空有效根启动宿主，可使用默认工作区。分别登记一份 Copy 素材、一份 Reference 素材和一项正式输出，核对各自的文件去向及界面回读。重启后工作区及记录 ID 一致。
- **AC-10** 受管文件发布中断时，保留可核对的原状态与操作回执，重试后同一条目只发布一次。
- **AC-11** 外置工作区离线时，设置和素材入口显示相应状态，业务登记及已有引用保留。原工作区恢复在线后，原素材登记可重新定位。

**AC-28 子帧成组与多盘复制**（FR-03、FR-05、FR-06、DEV-113、TC-113）。复制导入默认将整批放到同一存储位置。分类为子帧时，每个文件有独立素材 ID、组内顺序和位置，每组在每个实际使用的位置建一个目录。主帧与视频各自按完整文件保存。旧素材可按原路径读取。项目引用、单帧浏览和剔除独立于磁盘布局。

批量复制可显式开启多盘并行并选择参与的位置。预检只提交文件清单和大小，确认后逐文件直接写入目标卷、校验并登记。卷与位置配额均适用。同一物理盘共享写入队列，拓扑无法判定时保守串行。素材库统一展示组和各位置数量。中断后保留已完成帧，可重试剩余文件；重新发送已登记的同一条目应返回原结果。用同一组样本核对中转、单盘直写和独立双盘直写的耗时与吞吐，默认采用单盘。

### FR-06 业务数据库结构与兼容迁移

交付 `database/` 内承载本 Feature 的业务库结构。以现有 `assets.db` 为基线，承载工作区、文件位置及持久操作，以及设备、设备组合和兼容历史、素材、项目、会话、Collection、校准、正式输出和审批。保留业务身份与关联。受管文件通过工作区身份和相对位置定位，Reference 文件通过登记的外部位置定位。现有受支持的数据根可在宿主启动时迁移至交付版本。库缺失、归属冲突或结构无法识别时报告可诊断状态并保留现有文件。具体目录映射、库表和约束、迁移步骤在 TECH 中确定。 [持久化架构](../../../../docs/architecture.md#后端状态与数据目录)

- **AC-12** 在隔离宿主验证新库首建和受支持旧库升级。升级后可用原 ID 查询已有设备、组合、素材、工作区和文件位置，引用关系仍能解析。关键操作在重启后可按原标识查回。
- **AC-13** 复验缺失库、身份冲突或不支持的旧库结构。宿主提示故障，原文件保留，界面与 MCP 业务调用获得与实际可用性一致的结果。

### FR-07 精简存储设置

- **AC-14** 依次登记名称逆字母序的两个位置，核对均追加到列表底部且重载后顺序一致。无效路径保留已有记录和表单内容。配置页隐藏整库搬家和缓存管理入口。位置删除见 AC-26。新增时以所选路径为准，名称只作显示。按现有路径规则，卷根目录不能登记，所选目录与数据根或已有位置相互包含时拒绝登记。隔离环境中的复验见 TC-111。
- **AC-15** 在隔离 ComfyUI 打开「设置 → 配置」，确认页面没有数据根展示区、数据根路径、来源或数据库状态。默认素材导入方式、工作区列表及新增入口仍可用。 [DEV-005](04_DEV_LOG.md#dev-005-移除数据根目录展示) · [TC-007](05_TEST_PLAN.md#tc-007-配置页数据根展示)

## 5. 数据与运行约束

- 设备和设备组合各有稳定身份。素材库继续使用既有资产、文件位置、会话、项目、Collection、校准和审批关系。归档、删除和取消登记沿用各领域的语义。
- 扩展在 ComfyUI V3 `on_load` 初始化并协调存储和业务库。MCP 通过公开业务 API 查询和操作记录。宿主启动初始化沿用[已验收约束](../mcp-storage-init/00_FEATURE_INDEX.md)。沿用当前本机直连授权边界；如要新增设备写入，需确认该类操作的独立权限和用户确认方式。
- 真实宿主验收使用隔离数据及代表性文件样本。历史 PARTIAL 记录用于追踪覆盖，当前结论由交付版本的运行证据给出。构件、目标宿主版本和取证方式由后续阶段明确。
- 复用现有存储设置、Assets 和独立 MCP 发行入口。 [架构](../../../../docs/architecture.md) · [宿主验证](../../../../docs/development.md) · [素材库 v0.7](../../../archive/04-equipment-optical-trains/01_PRD.md#astrophoto-摄影素材库-prd-v07)

### 设置首页入口调整（D-15）

设置首页按「设备、软件管理、配置」顺序显示三个入口；移除「知识库」「用户记忆与隐私」「Agent 上下文与 MCP」「系统状态」入口。此调整针对首页展示，不改变各业务服务。

**AC-23** 设置首页仅显示上述三个入口且顺序正确；分别进入并返回，原有页面正常使用。关联 DEV-080、TC-080。

### 项目与文件夹统一树（D-16）

项目直接作为文件树根节点，可独立展开；文件夹和已登记素材在项目内原位显示。项目右键与菜单提供添加已有素材、新建根文件夹、编辑项目；项目行接受移回根目录的拖放。搜索项目、文件夹和素材时展示匹配项目与完整祖先路径。展开箭头复用既有折叠组件。虚拟目录操作不移动磁盘文件。

**AC-24** 多个项目可同时展开，子文件夹及素材显示在所属项目下；搜索可定位子项并保留祖先路径；项目菜单和右键操作正常，文件夹可拖回所属项目根且跨项目目录移动被拒绝。关联 DEV-090、TC-090。

### 宿主通知复用（D-17）

扩展错误提醒和操作反馈统一接入 ComfyUI 宿主通知；兼容不同宿主通知接口，接口不可用时保留页内反馈。字段校验、版本冲突、加载重试、详细诊断与批量结果同时保留在操作上下文；加载进度、空列表等页面状态继续原位展示。用户明确取消的项目拖放成功提示不恢复。

**AC-25** 节点、素材、项目、设备、配置、存储及 Siril 的错误和操作反馈使用宿主通知；宿主通知不可用时用户仍能看到反馈。验证表单校验、冲突重试、批量详情和加载失败入口仍可用；成功拖放不产生额外提示。关联 DEV-100、TC-100。

### 删除位置时迁移受管数据（D-18）

**AC-26** 最后一个位置受保护。存在其他位置时，可以删除包含素材的位置，也可以删除 Local 或默认位置。用户选定目标并确认后，系统迁移受管文件并核对内容，素材以原 ID 从目标路径打开，项目关联继续有效。删除默认位置后仍有有效的默认位置。仅登记的外部文件保留原路径，未登记文件保留在磁盘。取消不产生写入；迁移受阻时显示原因，保留可读取的文件和相应位置记录。关联 FR-05～07、DEV-110、TC-110。

### 侧栏全局任务进度（D-19）

用户确定在 AstroPhoto 侧栏底部展示全局任务框。存在素材导入或数据迁移任务时显示，可折叠与展开，切换节点、素材和设置时持续可见。展开后显示任务阶段、实际已处理数量、总量、结果和错误详情；支持清除已结束任务的界面记录，以及按任务类型继续或重试。折叠状态显示运行数量或单任务进度。完成及失败复用 ComfyUI 通知。展开状态和已清除记录保存在浏览器会话中；刷新后从服务端恢复任务状态。直传若因页面关闭中断，继续时重新选择原文件。历史右侧面板核查保留于 DEV-112。

**AC-27** 分别启动引用导入、复制直传和位置迁移，在侧栏底部查看阶段、实际数量与结果；切换页面、折叠和重开后状态正确。未知总量时显示阶段。浏览器刷新后可重新查询任务，直传未完成项可在导入页重新选择文件继续；错误详情和可用重试入口可访问，结束任务可仅从本会话界面清除，运行任务不可清除。完成或失败使用宿主通知。任务框不得改变素材 ID、项目关联或迁移事务结果。关联 DEV-114、TC-112。

### 分组与确认设计约束

- 建议按动作、项目/拍摄目标、素材类型、设备组合和校准策略决定审批分组。避免把匹配不一致的素材捆绑到同一批准单元。无把握项可单列为待补充，已经明确的组可继续审批。
- 名称及别名用于候选检索。FITS 头、文件名、目录和对话信息用于辅助匹配，可信度与冲突应可见。唯一且一致的候选可预选，候选同名或历史版本不明时由用户选择。实际关系使用目录记录的稳定 ID。
- 校准候选按类型及业务规则逐一验证，例如相机、binning、曝光、增益和滤镜，具体适用字段随种类变化。确认卡展示候选、缺项和冲突。当前用现有校准主帧及关系表示所选校准组合。显式选择时按主帧分别列出 `conflicts` 与 `unknown`；批准即等同素材库的差异确认。设备组合保存配置缺项时归为需补充，不记为冲突。
- 客户端内确认必须来自受信的用户交互，普通 MCP 提案凭据无法代批。批准绑定具体组及其不可变内容；重新分组或更改核心绑定需再次确认。客户端能力不足时报告无法在当前会话确认。审批能力验证、提案持久结构和导入/绑定部分失败的执行策略见 TECH。

### 已登记同源与固定版本（已确认）

分组导入的批准针对“这一批文件”和“批准时的设备、组合、校准主帧与项目版本”。两类边界需要产品口径：

- **已登记同源**（登记模式；复制模式不会跳过）：示例为两帧 Light，其中 `Light_0002.fit` 已在库中且指纹一致。已确认口径 **A**：新帧登记（或复制，取决于模式）并加入项目、绑定相机；已登记帧计为 `skipped`，**不加入本次项目、不写入批准属性、不建立绑定**；组显示 `partial`，并通过 `skipped_assets` 返回被跳过的素材 ID 与原因。B（跳过时施加批准内容）与 C（单独的“应用到已有素材”动作）保留为后续能力。
- **固定版本**：批准后若设备、组合、校准主帧或项目被修改，启动导入时拒绝（`import_failed`）；导入完成后的绑定阶段记为 `binding_failed`，两种状态都带 `requires_new_approval: true`，重试入口保留，用户可手动绑定或重新提案。已确认口径 **C**；技术细节见 [TECH 的已确认节](03_TECH.md#已确认口径绑定期版本变化与已登记同源spec-001-cq-04-a)。

以上口径已生效，对应实现见 `agent_imports.status`、`imports.import_reference`，验收见 TC-122/TC-117-C。
