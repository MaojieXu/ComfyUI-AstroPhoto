# AstroPhoto 前端设计

主 Agent 全程负责需求理解、调研、设计决策、实现和视觉验收；不要将前端设计、审美判断、布局决策或 UI/UX 审查交给子 Agent。纯后端及不改变界面行为的重构不触发本流程。尊重用户已确认的目标、范围和长期偏好。

## 设计与确认

1. 阅读[项目设计规范](../../../DESIGN_SYSTEM.md)、相关功能文档及实现，核对目标 ComfyUI Frontend 版本、当前界面、相邻宿主界面、实际用户路径与技术约束。优先检查项目现有组件和目标版本的公开扩展能力；区分已验证事实与假设。
2. 主 Agent 结合[原生设计语言](references/design-language.md)和[扩展实现边界](references/extension-implementation.md)，向用户提出可审阅的推荐方案：问题及现状、参考依据、布局与信息层级、用户操作和反馈、颜色间距字体图标及主题、实际可达状态、实现方式与版本、预计修改范围、验收标准。简单变更可用简短的前后说明；复杂变更按需要提供线框、标注截图或原型。有实质取舍时说明备选和理由。
3. **用户明确确认具体设计前停止，不修改业务代码。** 用户提出修改时更新方案并再次等待确认；未反对、超时或笼统要求“开始实现”不能视为对尚不存在的设计的确认。若用户已明确批准同一具体方案且范围、条件仍适用，直接沿用，不重复确认。

## 实施与视觉验收

由主 Agent 按获准设计实施，复用目标版本支持的组件、主题、API 和交互；普通技术细节自主解决。技术限制迫使布局、操作路径或其他已批准设计发生实质变化时，先说明并等待用户确认调整。

主 Agent 按[视觉验收](references/visual-validation.md)检查实际渲染，与获准方案逐项比较，并在确认范围内修正差异。按影响覆盖主题、节点和侧栏尺寸、画布缩放、长文本及中英文、状态、键盘焦点和图标；不适用的项说明原因。分别报告真实宿主、模拟环境及源码检查，不能渲染时明确缺口，不将构建或静态检查当作视觉验收。

按现有 [feature-pipeline](../feature-pipeline/SKILL.md) 记录适用的 Feature 决定和证据，不另建审批流程。预览、构建与重启遵循[本机预览与验证流程](../../../docs/development/setup-and-testing.md)及仓库规则；运行环境发生变化时重新核对版本与现状。
