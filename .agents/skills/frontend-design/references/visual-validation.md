# 前端视觉验收

由主 Agent 以用户明确批准的设计为验收基准。先确认目标实例、Frontend 版本、构建资源与可观察的界面；若需要重启，按仓库规则核对进程、数据根和未保存工作流。优先复用项目 `frontend/tests/`、Playwright 与 `docs/development/setup-and-testing.md` 中的宿主流程。

## 检查范围

按改动实际影响选择并记录适用项；没有对应状态或表面时说明不适用：

| 场景 | 对照批准方案检查 |
| --- | --- |
| 布局与视觉 | 节点、侧栏或弹窗的位置、层级、间距、对齐、图标和主次操作；与相邻宿主控件比较。 |
| 主题与内容 | 可用的深浅主题；中英文、长名称、文件路径和窄宽度下的截断、滚动和完整查看。 |
| 画布与节点 | 受影响的画布渲染模式、缩放、节点尺寸、折叠、端口及 Widget 排布。 |
| 操作与状态 | 可达到的加载、空、正常、错误、禁用等状态及恢复；鼠标、键盘、焦点、关闭和返回。 |

对每项差异判断是否属于已批准设计：范围内直接修正并复查；改变已确认的布局、操作路径或其他实质决定时，说明限制并重新取得用户确认。不要通过不相关的视觉重构扩展范围。

## 证据和限制

区分真实宿主渲染、模拟环境或组件测试、构建与源码检查；记录具体版本、主题、尺寸或缩放、关键操作和结果。无法观察的主题、画布模式或状态标明未验证，不能把静态检查或构建通过写成视觉验收通过。

官方 [Frontend v1.59.1 Storybook 文档](https://github.com/Comfy-Org/ComfyUI_frontend/blob/v1.59.1/.storybook/README.md)用组件状态示例和视觉回归支持界面检查，但组件截图不能替代 AstroPhoto 扩展在真实宿主的交互验证；是否使用 Storybook 按项目现有能力与任务需要决定，不强制引入新工具。
