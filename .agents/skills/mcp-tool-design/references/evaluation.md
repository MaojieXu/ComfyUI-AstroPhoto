# MCP 工具设计评估

## 确定性审查

选取真实任务及现有工具契约，验证下列可观察结果，不要求每个任务都有全部步骤：

1. **定位与选择：** 用户用中文提出目标时，能区分对象搜索、实例查找、读取与修改；重名时返回可区分候选而非猜测。
2. **参数：** 参数来自用户、前一步回执或明确默认；必填、单位、枚举、路径、未传/null/空数组的含义一致。无关字段不应被静默误用。
3. **分页和状态：** 多个查询不能混用续读；跨实例、过期或上下文丢失时明确失败并指出恢复方式。测试实际承诺的数据一致性，不假定分页就是快照。
4. **确认与副作用：** 明确展示影响、取得用户同意、绑定目标和当前状态；用户同意后仍校验权限和文件保护。未确认、影响变化及不支持的作用域不能静默执行。
5. **失败与恢复：** 服务离线、超时结果不明、部分失败、重复请求、任务取消未完成时，观察回执与下一步是否准确；只有有证据才报告成功。
6. **版本与发现：** 核对实际 MCP 会话工具清单、协商协议及客户端能力，与源码区别记录；不要把本地新进程的结果当作已连接会话已更新。

根据请求选择静态评审、隔离单元/集成测试或真实宿主验证。评估工具选择是否清晰时，检查近义工具的输入、描述、结果及边界；合理的多个执行路径可以接受，不应只按预设调用序列判失败。

## 模型评估（仅在授权且有条件时）

使用独立任务集和真实可用模型，覆盖明确目标、信息缺失、重名、多轮分页、错误恢复、中文用户与固定枚举、以及不应调用工具的请求。隔离副作用并保护数据。

记录模型及版本、提示与工具清单、场景和数据版本、运行次数、环境、成本；分别观察工具选择、参数合法及语义正确、任务最终结果、恢复情况、调用次数/耗时。必要时给出抽样与人工复核，不因 schema 合法就认定任务成功。

小模型、长编码、工具数量和上下文长度的影响是需要测量的假设；静态审查不能证明某模型调用成功率提高。本项目曾决定暂不进行小模型测试，执行新请求时以用户当时授权为准。
