# Chat 事项提取与事件覆盖回执

**未实例化模板。** 尚未登记实际窗口、读取消息、识别真实事件或形成完整性结论。空表表示待填写，不代表没有事项、没有事件或已经全部读取。此文件是人类可读的提取回执，脚本 JSON 输入按技能内 `references/StructuredContext.md` 单独生成。

<a id="reading"></a>
## 2. 实际读取、新内容段与附件

| reader / 时间 | 原文版本及分卷 | 实际已读消息/行/页范围 | 未读范围 | 必需附件及查看方式 | 回执定位 |
|---|---|---|---|---|---|

| 新内容段身份 | 在完整原文中的精确范围 | 前后检查点依据 | 新消息/修订/历史复制 | 新段文件位置（若生成） | 仍未确认的边界 |
|---|---|---|---|---|---|

新段只用于定位新增事件；完整相关原文与附件继续保留。没有可靠边界时，不把历史复制当成 NEW_INPUT，也不把看不到的新内容当成“无提及”。工具截断后未读完的部分继续列为未读。

<a id="items"></a>
## 3. 稳定事项与完整语义

| 实际事项 ID / 来源旧ID | 类型 / 标题 | 当前完整正文位置 | 本次新建/更新/沿用 | 关联真实ID | 原文及证据位置 |
|---|---|---|---|---|---|

事项类型按协议使用 DECISION / TEST / ERROR / RISK / QUESTION / CONSTRAINT / ATTEMPT。一个事项多次讨论沿用原 ID；只有独立语义才拆新事项。旧 ID 同名时保留命名空间和映射。

以下为可复制的人类记录格式，尚未填写，不直接作为引擎 JSON：

```markdown
### <真实ID> · <标题>
- 类型与范围：<实际类型、专题、消费者、环境和排除项>
- 完整语义：<目标、前提、触发、动作、预期/实际、持久状态、例外和反例>
- 用户原话：<精确引用和消息/行范围；无法取得原话则明确忠实整理或缺失>
- 决定与理由：<接受/提议/延后/否决/替代；来源、取舍、仍有效条件>
- 错误与恢复：<error/skip、已执行/跳过步骤、原状态、清理、取消、回滚>
- 测试与运行：<真实用例/断言、命令、运行身份、环境、时间、结果和未覆盖边界>
- 尝试与未决：<尝试、失败/放弃依据、未答问题、长线目标与下一步>
- 业务状态：<决定、实现、证据、执行、阻塞分别填写>
- 来源与关联：<原文、附件、实际ID、替代关系及反向定位>
- 固定保留：<pinned 的实际依据或不固定的依据，不能凭年龄取消有效约束>
```

<a id="candidates"></a>
## 4. 候选与语义匹配

| 候选定位 / 原文片段 | 说话者 | 精确ID/别名/间接语义 | 候选事项ID | 已匹配/歧义/无关/历史 | Main判断依据及需补材料 |
|---|---|---|---|---|---|

精确 ID 检查边界；别名冲突列出所有候选。间接语义必须能回到实际原文与目标行为。关联 ID 不是自动唤醒清单；需要传播到多个事项时逐项保留影响依据。没有命中关键词不能证明原文没有相关纠偏。

<a id="events"></a>
## 5. 实际事件与唤醒依据

| event_id | item_id | kind / origin | source_id / source_revision | locator / 精确片段 | 说话者 / 提取者 | 运行/消息身份 | 唤醒或不唤醒理由 |
|---|---|---|---|---|---|---|---|

事件分类按协议使用：MENTION、CHANGE、TEST_RUN、ERROR_RECURRED、USER_DIRECTIVE、CARRY_FORWARD、ROUTINE_CHECK、HISTORICAL_QUOTE、NOT_RELEVANT。是否来自真实新增范围单独记录。

MENTION 等有效新事件使事项恢复关注或计数归零；历史复制、例行检查和旧引用保持来源，不据此唤醒。TEST_RUN 要有真实新运行回执，ERROR_RECURRED 要有本次实际发生依据。只看到名字、截图或旧日志，不填写为新执行。

已经记录的同一事件保持原身份和原来源版本，新导出到该事件的映射另记。尚无事件时不填示例行凑数；只有格式空表不能证明“本轮无事件”。

<a id="coverage"></a>
## 6. 所有声明范围的去向

| source_id / revision / 连续消息或行范围 | 范围内容与独有限定 | 去向类型 | 对应事项/事件/正文位置 | 是否完整保留 | 依据或缺口 |
|---|---|---|---|---|---|

去向类型：创建/修订事项、形成事件、等价重复、历史携带、例行复核、无关排除、缺失/未读/待判断。可以合并连续同性质范围；不能跳过反例、限制、失败、否决理由或未决部分。重复内容给出已有完整覆盖位置，原文继续保留。

| 范围集合 | 实际内容/依据 |
|---|---|
| 声明集合 | 待填全部相关消息、分卷和附件范围 |
| 已读集合 | 待填 Main 与提取者各自真实读取回执 |
| 已映射集合 | 待填覆盖账中的真实范围 |
| 有依据排除集合 | 待填范围和排除理由；不能移除缺回执窗口来凑完整 |
| 未读/未取得/未判断集合 | 待填精确缺口与影响 |
| 分卷边界和附件完整性 | 待核对；不能根据文件数量推定 |

反向核对：每个输出结论能否追到来源，是否把建议写成用户决定、把历史结果写成本轮结果。原文覆盖不能只靠字节数、哈希或事项数量证明。

<a id="protected"></a>
## 7. 业务状态与固定保留项

| 事项ID | 决定/实现/执行/阻塞的真实状态 | 当前有效规则/AC/权限位置 | 当前必办或阻塞依据 | pinned / 原因 | 允许归档的历史讨论位置 |
|---|---|---|---|---|---|

仍有效约束保持当前可见。明确当前必办事项不能因五轮空闲而自动消失。归档可以降低历史讨论的默认加载量，不删除测试代码，不改变 FAIL、未解决或未验收身份。固定保留变化需有真实新决定或事实依据。

<a id="revisions"></a>
## 8. 重导出、等价重复与修订历史

| 本次来源/范围 | 原事项/事件身份及版本 | 同一事件重导出或真实新发生 | 不重复计次/新事件的依据 | 独有变化完整保留位置 |
|---|---|---|---|---|

导出时间和 source_revision 改变不自动产生新发生事件。真正重复测试运行必须有新的运行回执；相同失败再次发生可以保留同一问题 ID、追加新复现事件。消息被修订时保留原版本及其替代范围。

<a id="gaps"></a>
## 9. 缺口与未决

| gap_id / 事项ID | 原文/事件/读取/匹配的具体缺口 | 已知内容及实际来源 | 影响计数或唤醒的范围 | 补充责任与最小材料 |
|---|---|---|---|---|

| 未决产品问题 | 已完整取得的各方主张/条件 | 当前有效用户决定 | 仍需决定的内容 | 正文与来源去向 |
|---|---|---|---|---|

完整呈现的产品未决与资料缺失分开。未读或不能判定的活动事项不能当作 UNCHANGED；无法证明范围完整时不宣称覆盖门通过。

## 10. Main 核对与脚本衔接

- [ ] 已实际取得并读取声明范围内的完整相关原文与必需附件。
- [ ] 上一检查点之后的新范围可定位，历史复制没有被标为新发生。
- [ ] 稳定事项 ID、完整条件、业务状态、反例与失败保留，所有消息范围有去向。
- [ ] 候选之外的间接语义已检查；歧义、未读与无法核实项有明确缺口。
- [ ] 新事件具有真实来源片段；旧事件重导出未生成第二次发生身份。
- [ ] 实际运行与旧日志、实际复现与历史引用已经区分。
- [ ] 仍有效约束、当前必办和必要阻塞说明保持固定可见。
- [ ] 事件/事项/观察项按当前引擎 JSON 协议生成，未手改引擎状态与计数。
- [ ] 新事件引起的正文、业务状态或固定保留变化已合并到完整 upsert，准备与事件同次提交；此前 touch 的重放按既有事件处理。
