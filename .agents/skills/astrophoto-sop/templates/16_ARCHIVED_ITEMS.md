## 1. 使用方式

本模板用于首次导入时清点完整语义和历史，不是引擎生成文件的手工补丁。启用 v2.2 引擎后，从 CURRENT 指向的同一快照读取 state 与视图，由 state 唯一生成本文件及 ACTIVE_CONTEXT；不能手改计数、活动正文或当前归档视图。不要用空模板覆盖已有档案。规则见技能中的 `references/Archiving.md`、`references/StructuredContext.md` 与 `references/ChatExtraction.md`。

所有占位字段均替换为实际资料、明确未知或有理由的 N/A。先完整批量读取 Local Chat、核对事项/事件与原文覆盖、融合最新 bias，再预览候选全量包；收集批次与包完整性门通过后，才以 advance apply 固化本轮计数和归档。真实新语义提及即使没有修改代码，也可先 touch 恢复或归零；touch 不计 Handoff，下次完整 S8 建立 H0=0。

五次是最后变化、真实新提及或本政策首次完整导入的 H0 之后，连续无变化且无新语义提及的 H1–H5。要求同一正式主线、不同真实收集批次、每轮完整 S8 和条目真实复核；只有未 pin 的条目可归档。草案、重打包、并行分支副本不累加。缺轮证据不按空闲处理，v2.1 旧计数不直接继承。

复制下方条目格式时使用实际稳定 ID 和显式 ASCII 锚点；生成真实链接前确认目标文件及锚点存在。格式示例中的跨文件链接仅用于说明，不是已存在的项目文件。

当前 ARCHIVED 条目在本文件保留完整正文；恢复后完整正文移回 ACTIVE_CONTEXT，本文件只保留稳定锚点、恢复索引及当前正文链接，完整历史版本和事件继续随同包 state.json 与原始来源携带。`FULL_HANDOFF.md` 全文纳入当前归档、ACTIVE_CONTEXT 与 CONTEXT_INDEX 并核验跳转；旧快照不回写。S4 仍交付专题全量，S8 仍交付全项目全量。

## 8. 本轮归档批次回执

以下字段未填写，不代表已完成检查：

- 已批量读取并对账的 Local Chat / 来源范围：待填实际范围及缺失来源。
- 最新用户 bias 已融合的位置：待填真实决定与受影响条目。
- 提取与分类回执：待填 item/event ID、source_id/revision、原话范围、覆盖去向及未决候选。
- 本轮新增归档 / 重新激活 / 继续继承条目：待填实际 ID；空闲判断须同时确认无变化和无新语义提及。
- TEST_RUN / ERROR_RECURRED：待填实际新执行或复现证据；打印测试名、重传旧日志和例行检查不能替代。
- 只计算候选但尚未固化的条目：待填 ID 和未通过的门。
- touch 恢复 / 预览候选 / advance apply：待填真实事件与回执；touch 可先完成，但不计 Handoff。
- 计数证据缺口与处理：待填补证或新 H0，保留原历史。
- 收集批次门 / 包完整性门：待填实际结果；INCOMPLETE 不累加本轮计数。
- 正式固化的 handoff_id / source_batch_id：待填写实际完成回执。
- CURRENT / state revision / 同版视图：待填实际快照身份；touch 后读取新状态并重新预览。
- 合订本全文纳入、双向链接、信息去向表位置：待填真实检查记录。
- 未覆盖事项：待填；不能因模板存在就声称“每件事都已记录”。
