## 1. 效力与用户最新决定

在适用的系统、工具权限和仓库规则内，用户最新明确决定用于确定产品目标与流程要求；当前源码和运行证据分别用于判断实现与验证。文档更新时间本身不能替代这几类依据。

用户在构建 v2.0 时明确纠正：

> S8,S4都是做全量，而非增量附件，我们无法接受文件的熵减。
> 并且核心思想是resnet的跳跃链接，残差链接。
>
> llm模型本身作为输出，而我作为bias,不断指正流程走向。

本版将这条决定落实为：

1. S4 每次输出本专题完整开发包，S8 每次输出全项目完整交接包。
2. 仍有效的旧内容直接进入新完整基线；本轮变化以残差关系说明，并融合进正文。
3. 原始需求、用户纠偏、契约、源码、Guard、测试和风险之间可通过稳定编号与有效链接直接到达。
4. 用户在任何阶段的明确纠偏都更新相关条款和后续输出，保持原话来源、作用范围与替代关系。
5. 文件数量、拆分方式或摘要便利不能造成有效信息无去向地消失。
6. 证据不充分时保留未知与材料缺口；完整覆盖不能冒充已实现、已验收或本轮全部重测。

用户随后要求以入口文件和 `Phases/Phase1, Phase2, ...` 的方式构建最终可用 SOP。本版采用标准入口 `SKILL.md`，并保留原 S0–S9 编号：`Phase4.md` 对应 S4，`Phase8.md` 对应 S8。

## 5. 原理类比与证据边界

ResNet、恒等通路及用户 bias 在本 SOP 中构成工作流类比：保留完整基线、让原始依据直接到达后续阶段、融合修正、输出新完整版本。

落实这些原则的载体是文档正文、稳定编号、来源记录、条目去向、实际代码和测试证据。它们不意味着修改 LLM 权重、获得永久记忆或自然保证每次生成无损。

“不接受文件熵减”按用户语境落实为：有效需求、条件、决定、例外、失败处理、证据边界和未完成项不能无依据地丢失。完整性需要逐项比对与接手验证；文件大小、链接数量、校验和及论文类比都无法单独证明语义完整。

本版的来源校验只证明所采用附件字节一致、配套 Prompt 一致和官方参考可查。业务源码、宿主运行、测试结果及流程效率需要在实际任务中分别取得证据。

## 8. v2.2：结构化计数、提及恢复与细粒度 Chat 提取

本版据此作出以下可执行定义。五轮阈值来自项目要求；字段、去重规则及事务边界是为可靠执行要求作出的实现选择。

| 需求与旧规则的关系 | v2.2 的有效规则 | 完整性与事实边界 |
|---|---|---|
| 在 v2.1 “五轮未变”基础上增加再次提及恢复 | `idle_handoffs` 统计最近有效新提及或实质变化之后的合格闲置轮；H0 为 0，第五个后继闲置轮达到 5 归档 | 有效提及归零；重复导出、旧日志、例行扫描和全量包原样携带不构成新提及 |
| 内容移出归档 | 当前归档全文移回 ACTIVE，归档保留稳定入口与恢复索引；完整旧正文、事件和版本保存在同包 state 及旧快照中 | 不要求当前档案重复保存活动正文；不删除历史或改写业务状态 |
| 通过脚本检测计数和搬移 | Agent 提取有来源的语义事件；脚本校验、去重、计数、生成视图、保存完整状态 | 脚本不自行读其他 Chat，不根据一个关键词推断用户意图 |
| 对 Chat 更细致地提取 | 事项 ID 与事件 ID 分离，保留完整条件、源版本、消息/行定位、原文摘录、新旧边界、关联、去向和覆盖缺口 | 历史引用、计划测试、实际执行、错误再次出现分别记录；不需要或虚构隐藏推理 |
| 及时响应再次提及 | `touch` 可以在整轮来源尚未收齐时恢复已确认提及的事项；正式计次继续等待完整 S8 | 缺来源不能当作五轮未用证据；下一完整 S8 建立新的 H0 |
| 防止有效规则被剪走 | CONSTRAINT、当前必办或必要阻塞信息按事实固定保留 | 测试事项归档不删除测试代码、不把 FAIL 改为 PASS；有效 AC 与规则持续生效 |
| 在全量要求下减少活动上下文 | 完整资料进入交付包，普通工作 Chat 通过轻量索引和稳定链接按需读取 | S4 专题全量、S8 项目全量不变；归档不是把资料从最终包删除 |
| 新增结构化状态与视图 | 原 19 份主 Markdown 保留，启用引擎后加 ACTIVE 与 INDEX 两份，并同包携带完整 `state.json` | 实际至少 21 份 Markdown，原始聊天另计；文件数目标不得限制完整保存 |
| 迁移旧计数 | 原 v2.1 复核账作为历史保留；首次启用新语义建立可证明的 H0 | 不把未包含提及语义的旧次数盲目导入，不从截图或目录数量推算 |
