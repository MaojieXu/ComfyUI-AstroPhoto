## 1. 分工与能力声明

在任务确实可并行、能节省时间或提高核查质量时分派。共享工作树的最终写入、契约协调、集成和验收由指定 Main 统筹。

| 角色 | 历史推荐 | 责任与边界 |
|---|---|---|
| Local Main | Sol High | 实现全部有效 AC，复核关键事实，统一消费者与最终结果 |
| 官方复用研究员 | Terra Medium | 只读调查目标版本宿主/前端/项目实现，返回定位与适用边界 |
| 分域审计员 | Terra Low | 清点分配域内全部源码和测试，追踪 Feature/Guard/Test 与历史变化 |
| Chat 提取者 | 按实际可用模型 | 对明确来源范围提取稳定事项、事件及覆盖去向；Main 实读原文并最终核对 |
| Web Chat | 按实际可用模型 | 专题设计、原型、开发契约、用户纠偏与专题交接 |

具体模型以用户指令、目标仓库现行 Skill 和实际工具配置为准。不能仅因 Prompt 写了模型名称就宣称已经切换，也不能让推荐型号成为虚假的权限或验收证明。

历史复用 Skill 要求 `gpt-6.1-terra`、推理 `medium`、`fork_turns="none"`。执行前读当前 Skill；不可用时报告真实执行者、已完成查证与缺口，在已有授权内继续可完成的工作。

只读子任务不得写业务代码、修改依赖、改变宿主或处置用户数据。需要落地报告时，Main 可明确授权写入本轮全新报告文件；报告目录与业务目录分别限定。

## 2. 独立任务的完整输入

每次分派都提供足以独立执行的任务正文，尤其使用 `fork_turns="none"` 或跨 Chat 转交时。

必须包含：

1. 实际仓库绝对路径、工作树、目标宿主与官方源码位置；未知项如实写未知。
2. 本次用户目标、有效 AC、最新相关纠偏及不可被覆盖的既有决定。
3. 可访问的 PRD、完整包、交接、测试和历史资料，逐项列明路径或提供正文。
4. 明确负责域、具体问题、必须检查的目录与排除范围。
5. 共享接口、生产者、消费者、旧数据和旧工作流边界。
6. 允许的读取、查询、验证及新报告写入范围。
7. 交付格式、事实分层、精确定位与需要 Main 复查的内容。

传递与本任务相关的完整语义，避免凭据、私有素材和无关聊天。不能只发一个模块名、一个无法访问的本机路径或“按之前说的做”。

相关内容已归档时，提供同版归档的稳定 ID 和可读全文，不因不在活动待办中而省略有效约束。Local Chat 来源与已读/未读边界按 [对话注入规范](LocalChatIntake.md) 传递，归档与恢复按 [归档规范](Archiving.md) 处理。

提取子任务按 [ChatExtraction](ChatExtraction.md) 明确 source_id/revision、完整相关原文、前后检查点、实际新增范围与可读附件。返回稳定事项/事件 ID、原话定位、事件分类、覆盖去向及歧义；不把重复导出、旧日志、例行检查当成真实新提及、TEST_RUN 或 ERROR_RECURRED。Main 不用摘要替代自己的实际读取。

用户纠偏直接进入子任务原文。主 Agent 的推测与建议需标明身份，不得转换成“用户已经接受”。

## 3. 只读复用研究 Prompt

适用于 S3/S5 在定方案、写实现前需要查证的官方与项目复用问题。由 Main 填好具体输入，不能依赖子 Agent 读取主对话。

```text
你负责 AstroPhoto 的只读复用研究。实际执行模型按可用配置如实记录。
项目仓库：[绝对路径、工作树]；宿主及官方源码：[绝对路径、版本或未知]。
输入：[逐项列出可访问的PRD、源码披露、相关交接和测试]。
用户已确认的行为与最新纠偏：[相关原文或保留完整条件的准确复述]。
需要回答：[按AC列具体入口、接口、组件或生命周期问题]。
责任范围：[目录和调用者]；排除：[无关模块、数据和操作]。
允许操作：[只读查询及明确获准的验证]；输出：[返回Main或指定的新报告路径]。

先读目标仓库 AGENTS.md 与适用复用 Skill。有可用 CodeGraph 则查询精确文件、符号与调用者，再读源码；无索引用 rg。区分实际宿主、官方参考镜像、项目实现和历史材料。前端查组件表、模板原码及已有适配；后端从真正宿主源树查，排除扩展误命中。
逐问题返回 path::symbol、版本/公开性、输入输出、状态所有者、调用链、依赖/许可、权限、错误/skip、取消/卸载/序列化边界及测试断言。比较直接调用、最小修改、移植适配与必要补足，给出依据和消费者影响。未找到与未能完成搜索分别说明范围。
业务代码、依赖、宿主和用户数据只读。不得自行改变产品决定。报告包含复用矩阵、必要源码片段、事实证据、真实执行与未测项、风险及需Main复核的问题。保留影响判断的细节，不以“官方支持”代替定位。
```

## 4. S8 分域全量审计 Prompt

S8 的全项目范围由 Main 划分到每个责任域。每个子任务完整覆盖其分配域；多个局部摘要不能代替全域清点和全局融合。

```text
你负责 AstroPhoto S8 的只读分域全量审计。
项目仓库：[绝对路径、工作树、已知HEAD]；目标实例：[标识或未知]。
上轮完整交接：[路径]；各Chat专题终稿：[本域相关路径]；有效原始PRD与完整技术包：[路径]。
本域相关Local Chat源材料与注入批次：[可读材料、范围及缺口]；相关完整归档：[同版路径与ID]。
用户最新决定：[相关完整语义]；共享契约和消费者：[清单]。
责任域：[域名称]；必须覆盖的源码/测试/配置/注册入口：[目录清单]；排除：[范围]。
允许验证：[命令或操作条件]；报告位置：[本轮全新文件或回传Main]。

1. 清点分配范围内实际文件，记录已读、未读及原因；区分业务、测试、生成物、第三方和历史材料。
2. 从UI/API/Node/MCP等正式入口追到最终结果，逐可观察行为列Feature、真实path::symbol、输入输出、持久副作用、共享消费者和实现状态。
3. 逐Feature查实际生效的参数、路径、格式、权限、并发、生命周期、外部进程、错误/skip、清理和恢复，给出Guard调用位置。未找到注明搜索范围，写NO_GUARD_FOUND。
4. 查精确测试用例、前置状态、断言、Mock/真实边界及其对应AC。没有测试写NO_TEST_FOUND。按已授权条件验证，记录命令、环境、时间、退出码和结果；未运行写NOT_RUN。
5. 对照全部本域原始有效需求、旧交接和用户纠偏，逐项列保留、修改、取代、延后和未知的去向，保持原编号与来源；不只审计本轮变动文件。
6. 输出完整本域文件覆盖、Feature、Guard、测试、契约、残差与风险记录。历史验证保留日期和环境；源码、历史运行、本轮运行、推断分开。

业务源码、依赖、宿主、用户数据及旧交接只读；不要运行未授权或会改写这些对象的命令。可按授权写本轮新报告。不要复制凭据或私人素材。返回报告路径、实际覆盖范围、条目数、未覆盖文件、冲突和需要Main复核的重点；主体信息必须在完整报告中可读，不能仅留短摘要。
```

## 5. Main 的复核与融合

Main 复核共享契约、重要 Guard、版本判断和所有拟声明通过的验收结论。检查子报告是否真实读取了分配范围，是否存在遗漏调用者、未读文件、错用模板路径或没有断言支持的完成声明。

需要补充时给出定向问题，保留原回执及修正来源。子报告中的不同观点按需求、源码、运行或证据分别裁决，不能靠投票、文本日期或模型级别决定事实。

合并同一行为时保留各来源及验证边界；重复编号建立映射，不把旧 `C` 的“变更”与另一来源 `C` 的“契约”静默合并。

S4/S8 的全量包必须承载必要的子报告事实、反例、条件和未完成项。可以整合表达、去除真实重复，也可以将必要完整子报告纳入包内；不能只保存 Main 摘要并丢弃决定性细节。

对子任务归纳出的每条有效要求和证据检查新包去向；主报告与子报告冲突时明确写来源、影响、当前有效结论及剩余未知。

子 Agent 审计报告不能代替相应 Local Chat 的源材料回收。最终生成 Handoff 的 Main 按 [对话注入规范](LocalChatIntake.md) 对照预期窗口名单批量收取、实际阅读、核对并融合来源，保留逐源读取回执和条目去向；收到文件、拿到路径或其他 Agent 声称已读均不等于 Main 已完成注入。先完成本轮统一批次全部预期来源的完整注入与冲突核对（允许分批读取），再按 [归档规范](Archiving.md) 判断最终剪枝，不能先归档后遗漏新纠偏。

五轮计数由 Main 根据同一规范 S8 谱系中的已完成快照、完整提取与实际条目复核统一确定；子报告、S7、即时同步、草案和重打包不另计轮次。最后变化或真实新语义提及建立 H0=0，随后 H1–H5 连续无变且无新提及才计 1–5；缺证据不能推定空闲。

使用 [StructuredContext](StructuredContext.md) 时，由同一 Main 从 CURRENT 读取状态，协调结构化输入与预览；子 Agent 不并发手改 state、计数或生成 Markdown。明确新提及可立即 touch 恢复，不等待整轮 S8；touch 不计次数，下次完整 S8 建立 H0。最终先完整 intake、预览候选并检查全量包，再由 advance apply 固化。脚本约束写入顺序，Main 仍负责来源和语义判断。

恢复事项全文进入 ACTIVE_CONTEXT，当前归档留稳定锚点与简短恢复索引；完整历史随 state 与原始来源携入新 S8。各视图来自同一快照，不手工分别维护。普通子任务先读当前约束、活动与索引，按任务读相关冷档；S4/S8 最终交付仍保全全部必要信息。

## 6. 多窗口阶段对齐

| 阶段 | Main 要核对的内容 |
|---|---|
| S1 | 专题、负责窗口、可改范围、只读依赖、共享接口所有者和消费者；登记未来 S8 的 Local Chat 来源引用、负责人和范围；窗口未建立时先记计划分工 |
| S4 | 全量专题包中的最新契约；变化影响哪些窗口、旧/新字段或行为、兼容决定和验证责任 |
| S5 | 各窗口代码所在工作树、HEAD/未提交变化、测试版本、构件、实际集成状态及目标组合待验项；保存对话来源、用户纠偏、重要失败尝试和执行回执 |
| S6 | 最新用户纠偏、真实新提及及受影响窗口；原话/事件身份、touch恢复、契约/实现/断言与仍有效决定 |
| S8 | 所有专题与目标工作树的对应、完整项目功能/Guard/Test、契约冲突、证据边界、遗留项及全量包去向；先完整来源提取与注入，再预览及检查，门通过后固化计数，完整携入活动/归档/状态历史 |

共用工作目录时，不按 diff 猜测作者；归属须有独立回执。不同 worktree 时，专题分支通过的测试不能直接记为最终集成工作树通过。

协调写入不等于自动发送消息、归档窗口或合并分支。按用户已有授权执行具体动作，不能把“同步查看”扩大为修改。

## 7. 即时同步与独立评估

用户说“同步这几个窗口”时，读取用户提供或当前对话已经明确登记的窗口。窗口不可读则列出缺少哪份回执，继续整理可读部分；再次同步优先核对上次回执之后的变化。

在当前回复返回：**专题｜负责窗口｜已确认决定｜实际代码落点及集成状态｜测试证据｜冲突或待办**。核对仓库、工作树、分支、HEAD、相关未提交变化和目标实例。即时同步是只读汇总；没有要求整轮交接时，不自动触发 S8。

即时同步不等于最终 Handoff 生成前的批量注入。“再次同步优先核对变化”只适用于当前同步动作，不能用最新 diff、最后一条成功回执或短摘要替代 S8 的完整来源回收、实际阅读和语义融合。不可读窗口列明具体来源缺口，不宣称所有 Local Chat 已注入。

需要检验 SOP 或方案能否被新 Agent 正确使用时，可另做独立任务评估。给评估者真实任务、所需文件和工具边界，避免提前泄漏期待答案、已知缺陷或主 Agent 的判断；评估目标是它能否从材料独立完成任务。

复用研究与正式开发仍须提供完整相关决定，不能把“独立评估不泄漏答案”的规则误用为故意隐去需求。保持输入完整，同时区分事实、用户决定、待检验假设和主 Agent 建议。
