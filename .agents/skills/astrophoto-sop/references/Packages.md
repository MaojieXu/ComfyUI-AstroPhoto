## 1. 共同要求

每次正式交付使用独立版本目录，保护旧包。需求/交换包放 `.artifact/<专题>/<版本>/`；全局历史包放 `.agent/handoff_history/ComfyUI_AstroPhoto_Handoff_<日期>_<序号>/`。根目录存在时先清点，使用下一个序号；用户明确指定覆盖时按其范围执行。

本节文件名是可用的完整结构。项目已有稳定文件名时沿用，并映射相同职责；不机械改名造成旧链接失效。严禁“省略未改动文件”“只发增量”“引用旧附件补正文”。

普通正式包按职责分组，不压掉语义。S8 原有核心结构为 19 份 Markdown；启用 v2.2 结构化引擎后另带活动全文与索引两份，至少 21 份 Markdown。此前少于 20 的组织目标让位于这次明确新增职责。完整相关 Local Chat 原始导出、附件和其他必要取证材料保留原格式，实际 Markdown 总数如实统计；不能改扩展名或删内容凑数量。

普通证据的关键语义正文内嵌，不默认增加截图和 `evidence/`。S8 批量注入的 Local Chat 原始导出及必要附件是本版明确要求的来源层，随包放入 `sources/local-chats/`。用户要求其他原始日志、证据目录、哈希或截图时按范围保留，并脱敏。UI 原型是可执行设计材料，必须保留适用内容。

ZIP 必须来自整个最终目录，包含未变更文件、必要原型与资产；不能只压 diff。ZIP 放在该目录外，防止递归包含自身。文件名按本次主要需求或交接轮次命名，并与目录版本一致。

## 2. S4：专题完整开发包

建议目录：`.artifact/<Feature>/<version>/`；跨环境同名 ZIP，如 `AstroPhoto_<Feature>_Requirements_and_Engineering_v2.2.zip`。日期/版本按本轮实际情况填写。

| 文件 | 必须承载的完整内容 |
|---|---|
| `00_START_HERE.md` | 专题范围、版本、状态、输入、完整性、阅读路径、实施入口、阻塞 |
| `01_PRD_AND_DECISIONS.md` | 完整有效需求、用户流程、AC、状态、数据副作用、权限、全部有效 bias、替代/延后关系 |
| `02_UI_AND_PROTOTYPE.md`（适用） | 完整交互规格、组件映射、主题/窄栏/键盘、正常失败状态、原型模拟边界 |
| `03_CODE_DISCLOSURE.md` | 必要源码披露全文、真实入口、I/O、状态持有者、共享消费者、源码与运行证据边界 |
| `04_CONTRACTS_AND_IMPLEMENTATION.md` | 完整契约、兼容/数据处置、逐AC实施点、REUSE/MODIFY/ADD、调用顺序与计划 |
| `05_GUARDS_AND_TESTS.md` | 错误/skip/权限/取消/清理/回滚、具体测试及关键断言、命令与环境、拟建和已有区分 |
| `06_SOURCES_AND_PRESERVATION.md` | 官方来源/版本/适用短示例、所有输入信息去向、残差演进、来源映射与风险 |
| `07_AGENT_PROMPT.md` | 新 Local Agent 可独立使用的短启动 Prompt、准确包路径和必须回报内容 |
| `FULL_REQUIREMENTS.md` | 以上所有适用专题正文完整合订，重写内部链接 |
| `prototype/index.html`（适用） | 可离线操作的完整交互原型，必要资产同包提供 |
| `MANIFEST.sha256` | 对最终文件进行 SHA256 登记，排除清单自身 |

可调整分组，但不得省去表中适用的语义。纯后端专题可在入口说明 UI 不适用，不创建空 UI 文件。原型与技术规范一致；主流程、按钮、空/加载/失败/成功/禁用/冲突等状态按需求覆盖。

S4 需要正式入口、文件/函数、I/O、副作用、错误/skip/恢复、测试断言及目标版本官方参考。已有符号标明证据，拟新增符号标明计划。缺 S3 不能靠发明函数补齐。

接手者可仅凭本包理解本专题完整设计和实施上下文；实际源码按明确仓库定位读取。官方 URL 是参考来源，关键适用结论与必要短例应在包内，不要求复制整份第三方文档。

本专题涉及已归档决定、错误或方案时，将相关完整档案及必要来源携入本包的决定/保全章节或明确附件，当前仍生效规则和影响写入对应正文。S4 不需要携带无关领域全部档案；也不能只留一个指向未携带全局旧包的链接。新的明确反馈按原 ID 重新激活。

## 3. S7：完整专题收尾

专题收尾完整覆盖最初有效范围，通常采用 3–6 份 Markdown，数量根据内容确定：入口及决定、完整 Feature/契约、Guard/测试/证据、完整遗留与风险、输入去向与接手说明。必要时合并。

保留 S4 的有效 PRD、技术说明、最终原型及 Local 的事实回执。可以将这些资料放入同一专题交接包，或在 S8 汇合时实际携入；不能仅以外部旧包路径声称接手材料齐全。

列出原AC对应的最终结果、未交付、失败、回滚、旧决定替代和其他消费者影响。它是全量专题收尾，不宣称全仓审计。需要单独跨环境传递时打包完整专题目录。

专题内各 Local Chat 同时提供完整相关来源与结构化内容，供 Main 按 [批量注入协议](LocalChatIntake.md) 读取。专题总结不能替代用户原始限定条件、失败尝试、未采纳方案和未知项的来源。

## 4. S8：完整项目交接包

沿用最近实际交接的路径与编号；以下为与原项目接近的一套 **19 份主 Markdown** 默认分组，可按事实调整。新增 15/16 两项职责必须保留。

| 文件 | 内容 |
|---|---|
| `00_START_HERE.md` | 完整项目入口、范围、基线、资料/事实缺口、阅读地图；正式 Handoff/父版本/来源批次身份及完整性 |
| `01_CURRENT_STATE_AND_VERSIONS.md` | 仓库、分支/HEAD/脏树、实例、构件、依赖、测试环境与日期 |
| `02_REQUIREMENTS_AND_DECISIONS.md` | 全部有效规范/AC、有效与延后需求的索引和状态、持续bias、替代/否决关系；归档讨论直达同版全文 |
| `03_REPOSITORY_ARCHITECTURE.md` | 当前模块/数据所有权、正式入口、跨端调用与完整共享契约 |
| `04_COMPLETE_FEATURE_INVENTORY.md` | 全项目逐行为盘点；已实现、部分、计划、过时、未知均纳入 |
| `05_DEFENSIVE_PROGRAMMING_AUDIT.md` | 逐功能 Guard、错误/skip/取消/回滚/清理/权限和实际生效链 |
| `06_TEST_COVERAGE_MATRIX.md` | 精确测试与断言，环境/替身、历史/本轮结果、未测和缺测 |
| `07_FRONTEND_UI.md` | Sidebar/Widget、UI状态、宿主生命周期、构建、主题、键盘与原型边界 |
| `08_NODES_AND_SIRIL.md` | 节点契约、路径/输出、Siril流程、Inspector、科学数据验证 |
| `09_STORAGE_ASSETS_EQUIPMENT.md` | 存储/Workspace、资产登记、缓存、文件操作、设备和光路 |
| `10_MCP_PACKAGING_AND_RELEASE.md` | MCP工具/权限/传输、打包、CI、发行状态与真实验证边界 |
| `11_HANDOFF_RECONCILIATION.md` | 所有旧条目到新包的去向、残差、跨Chat冲突与解决依据 |
| `12_GAPS_AND_RISKS.md` | 未完成、未知、失败、skip、依赖、下一步与优先级；归档后仍影响当前工作的条目保留状态/影响/阻塞和档案链接 |
| `13_NEXT_AGENT_PROMPT.md` | 新Chat/Local接手Prompt、读取路径和继续任务所需材料 |
| `14_SOURCES_AND_EVIDENCE.md` | 来源、盘点文件范围、未读/排除理由、关键证据及验证边界 |
| `15_LOCAL_CHAT_INTAKE.md` | 预期 Local Chat 清单、完整相关来源位置、覆盖区间/截止点、收到/实际读取/融合回执、逐项去向、迟到更新和缺口结论 |
| `16_ARCHIVED_ITEMS.md` | 当前 ARCHIVED 条目全文、稳定 ID、未使用复核账和当前影响；恢复项保留稳定入口直达活动全文，完整历史同包保存 |
| `FULL_HANDOFF.md` | 完整合订本，含 00–16 共17份规范化正文全文与有效内部跳转，包括完整注入登记和档案 |
| `MANIFEST.md` | 实际文件目录、版本、完整性说明、哈希清单方式与检查回执 |

`MANIFEST.sha256` 不是 Markdown，可另存；它覆盖专题、合订本、MANIFEST.md 及实际附属文件，但排除自身。必要原型或资源可同包保留，正文仍须具备全部关键语义。

### 使用结构化上下文引擎时

将同一确认快照的 `state.json`、`ACTIVE_CONTEXT.md`、`CONTEXT_INDEX.md`、`16_ARCHIVED_ITEMS.md` 放到新 Handoff 根目录，保持原相对链接；state 包含当前完整内容、旧版本、事件和轮次，不能省掉它只发两个视图。原核心 19 份加 ACTIVE/INDEX 共 21 份 Markdown；JSON 和原始附件另计。

FULL 在原 00–16 正文之外，再完整合入 ACTIVE/INDEX 并重写链接。已恢复条目无需在当前归档重复全文，原历史与业务状态继续随 state 和必要原始来源携带。`16_ARCHIVED_ITEMS.md` 可从脚本生成，人工模板只用于尚未启用引擎时的记录；不得把旧空模板覆盖已生成状态。

先预览候选并核对，再由 Main 依据实际外部完成门提交相同轮次；实际命令、候选与正式状态边界见 [StructuredContext](StructuredContext.md)。组件导出不等于全项目 S8；最终清单与 ZIP 必须覆盖整个项目交接目录，不能直接使用组件的五文件清单。

将 [注入登记模板](../templates/15_LOCAL_CHAT_INTAKE.md) 和 [档案模板](../templates/16_ARCHIVED_ITEMS.md) 用于新包；模板空白不代表当前项目没有问题或历史已复核。已有档案先完整继承再追加，不能每轮从空模板重置历史。

原始会话导出和必要附件复制到同包 `sources/local-chats/`，保留格式、来源范围及可定位的原话；它们进入清单和哈希。收集中可先放 `.artifact/HandoffInput/<batch-id>/`，最终快照不能只依赖该包外临时路径。所有独有有效语义仍须进入 00–16 对应正文，不能靠原始聊天堆积代替融合。

在入口或清单记录 `handoff_id`、`parent_handoff_id`、`source_batch_id`、完成状态和范围。同一快照的重打包沿用身份；不能用新目录/ZIP 名制造未变计数。先完成实际读取与最后更新回收，后判断候选；本轮收集与全量包检查通过时，才把本轮复核和归档事件固化到这个新快照。详见 [Archiving](Archiving.md)。

S8 从全项目目录和正式入口盘点，不仅合并本轮 Chat。每个领域记录实际读过、静态核验、历史证据继承及本轮执行范围。对生成物/依赖镜像等排除项写明理由，不能把未读业务源码归为无关。

## 5. 合订本与单独投递

1. 先完成专题正文和所有语义去向核对，再由同一版文件生成合订本。
2. 记录汇编顺序。复制完整规范化正文，保留代码块、表格、异常条件和来源；不得在合订本重新摘要。S8 的 15/16 同样全文合入，不能只放归档索引。启用引擎时 ACTIVE/INDEX 同样合入；旧内容版本保存在同包完整 state 与来源，不能声称 FULL 已逐字内含未内联 JSON 历史。
3. 为每篇正文增加带文件命名空间的锚点，例如 `p04-f-n04`，解决重复标题和同名锚点。
4. 将专题之间的链接改成合订本内部目标；外部官方 URL 保留。不能只给一个外部专题链接代替内容。
5. HTML 原型是独立可执行资产；单发 Markdown 时明确需同时携带原型文件，或说明该接手任务不涉及实际操作原型。完整 ZIP 中始终包含适用原型。
6. 在 Manifest 记录合订本来源列表与生成版本。合订本是同版全文视图，正文变更后重新生成并复验。
7. 原始对话、日志等来源附件可保留同包原文件，不要求重复逐字塞入合订本。其独有决定、限定条件、反例、尝试/失败和未知必须进入规范化正文并可反查。单发 FULL 时列明接手仍需同时携带的必要来源附件，不能声称其中逐字内含所有原始会话。

## 6. 交付前检查

### 语义与事实

- 从有效输入逐项追到输出正文，核对限定条件、反例、错误/skip、用户bias、长期需求和遗留项。
- 从输出逐项反查来源；设计、事实、历史和未知分开。
- S4 检查专题每条 AC；S8 额外检查完整仓库范围与所有模块，不漏零改动领域。
- 检查已存在与拟建函数、测试计划与执行结果；核验重要 Guard 真的在正式路径生效。
- 检查共享契约所有消费者，以及各工作树成果是否进入集成目标。
- S8 核对预期 Local Chat 是否全部实际读取并完成逐项融合、是否回收最后截止前的新内容；未提供/未读来源不能记“无变化”。完整记录的未决冲突保留其真实状态。
- 核对归档条件的五次正式复核账、旧档案全文继承、新纠偏优先和恢复事件；有效规则/AC、权限和当前阻塞不能因归档消失。失败草案不能增加计数。
- 核对事项和事件的稳定身份、新增范围、历史复制去重、间接提及映射及范围覆盖；脚本预览/正式提交、CURRENT版本和视图必须一致。新提及沿原 ID 恢复，当前归档移出正文但同包历史仍完整。
- 报告 COMPLETE/INCOMPLETE 与实际未核验范围，不用哈希代替语义验收。

### 文件与导航

- 本版规范化正文的每个相对文件存在，锚点可达，关键关系能反查；示例不冒充真实路径。原始聊天中的历史引用保持原文，在 15 登记可读映射或明确缺口，不能冒充当前导航。
- 合订本覆盖同版所有专题正文，内部导航不依赖旧包。
- 原型可离线打开；必要资源同包存在，模拟数据有标记。
- 清单覆盖最终实际文件，计算哈希后不再改正文；变更后刷新清单。
- ZIP 解压到新临时目录，检查文件清单与内容哈希一致，再运行结构检查。
- 记录包版本、日期、源码/实例状态、实际检查与缺口。

### 写入范围

- 旧包保持原样，输出仅写新目录及本轮明确允许的文档。
- 构建/测试可能改写 `js/`、数据库或宿主状态时先识别副作用；只读交接采用隔离环境或记 NOT_RUN。
- 开始与结束比对工作树；列出交付路径及非预期变化。

## 7. 机械检查工具

以 Python 3.9+ 运行技能内 `scripts/verify_bundle.py`，默认只读且不联网。下面的路径变量仅为调用示例，替换为实际完整路径。

```text
python <skill-root>/scripts/verify_bundle.py <完整包目录>
python <skill-root>/scripts/verify_bundle.py <完整包目录> --write-manifest
python <skill-root>/scripts/verify_bundle.py <完整包目录> --check-manifest
python <skill-root>/scripts/verify_bundle.py <含原始聊天的完整包目录> --raw-chat-sources --check-manifest
```

有 `MANIFEST.sha256` 时默认核验；`--check-manifest` 要求清单存在。首次生成使用 `--write-manifest`，已经存在时默认保护；明确刷新本轮新包可使用 `--write-manifest --force-manifest`。不要用刷新来掩盖不明的文件变更。

工具检查 Markdown 本地链接、锚点、引用式链接及清单哈希，拒绝越出包目录或符号链接。代码围栏内示例不当真实链接。业务源码引用用 `repo-relative-path::symbol` 代码文字，并附工作树标识；不要制造指向用户电脑的不可访问附件链接。

默认仍检查全部 Markdown 的导航。仅当 `sources/local-chats/` 保存不可改写的原始导出时，可显式使用 `--raw-chat-sources`：只跳过该固定目录中原始 Markdown 的出站链接检查，报告实际排除的文件路径与数量。原始文件依旧读取编码、建立锚点、拒绝符号链接、纳入清单和哈希；正式正文到原文/锚点的链接照常检查。生成或核验清单时均可加此开关。不得把正式正文移到来源目录逃避检查；历史引用的映射与缺口必须在 15 中核对。

工具不证明：语义无损、所有源材料已读取、五次归档资格、真实调用正确、HTML视觉/交互正确或测试实际通过。这些仍按上节和 [Records](Records.md) 核验。

## 8. 资料缺失时继续有用工作

已知全部内容仍组成一个完整当前草案，保留缺口位置、影响和下一步。缺旧包、用户决定正文、预期 Local Chat 来源、关键披露或无法盘点的项目范围时标 INCOMPLETE，不将未知写成“无此需求/功能”。来源缺口期间不固化本轮未变计数或新归档判断；原有历史照常完整保留。

补材料请求只列真正缺失的来源和具体问题。输入补齐后重做条目去向核对，再交新的完整包。不能把“用户可以自行拼接”当交付完成。
