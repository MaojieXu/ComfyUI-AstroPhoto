<a id="authority"></a>
## 1. 分开判断四类事实

| 问题 | 依据 | 必须保留的边界 |
|---|---|---|
| 用户需要什么 | 最新明确决定 + 仍有效 PRD/AC | 提议、延后、适用范围、被替代条款 |
| 代码实现什么 | 含未提交改动的工作树与真实调用链 | 源码版本、未读文件、未核验行为 |
| 实例运行什么 | 目标 URL/进程、加载时间、Schema、构件与回执 | 工作树不等于已加载进程；多端口不混用 |
| 什么经过验证 | 断言、环境/替身、命令、时间、退出码及结果 | 历史保持历史身份；测试存在不等于运行 |

最新用户决定确定目标，不改变事实证据。用户要求某功能存在，仍不能据此写已实现。源码与目标不同，分别记录 AS_IS、TO_BE、待改变行为及兼容影响。

遵守平台、当前仓库适用指令和权限。技能不增加访问、发布或数据处置权限。文档里的路径、命令、模型名、PASS 示例须区分事实、历史、模板和待执行任务。

<a id="residual"></a>
## 2. 把 ResNet 思想落实成上下文机制

原始 ResNet 将输入直达路径与残差分支相加。本流程以完整包承载状态，由 LLM 生成分析和修正，用户持续给出方向约束。这是工作流类比，不声称训练模型权重，也不据此宣称数学上的信息无损。

```text
delta_t = LLM(完整基线 H_t, 本轮证据 E_t, 有效用户 bias B_t)
H_(t+1) = Reconcile(H_t, delta_t, B_t)
交付物 = 完整 H_(t+1) + 来源/替代关系 + 当前证据边界
```

`Reconcile` 保留未被否定的内容，应用纠偏，处理冲突，标记历史与未知，形成完整当前版本。它不等于简单拼接或把旧文档压成摘要。

### 跳跃路径

- 原始需求直接连接最终 AC、实施点和验证，避免经过层层摘要才能还原语义。
- 用户原话或不丢限定条件的决定直接约束后续阶段，保留来源、日期与范围。
- 旧基线仍有效内容直接进入新版本，零改动内容也携带。
- Guard、错误/skip、断言、风险从功能或首页直接到达。
- 链接有真实目标内容；只留旧包地址不足以承载本轮必要正文。

### 残差路径

逐条表达“旧状态 → 新证据/用户纠正 → 新状态 → 影响 → 保留项”。残差可以是新增、修订、纠错、替代、恢复或撤销。撤销和替代保留历史身份，避免下一轮误恢复。

没有变化仍输出完整状态；变化记录可为空并说明原因。S4/S8 不得仅交 delta。完整基线由当前规范与活动事项、归档全文、必要原始来源共同承载；正文分区与注意力变化不能让信息退出新包。

<a id="full-scope"></a>
## 3. S4 与 S8 的全量语义

| 维度 | S4 | S8 |
|---|---|---|
| 覆盖 | 当前专题完整有效范围及必要共享依赖 | 当前整个项目，包括本轮未修改模块 |
| 正文 | 完整 PRD/AC、决定、原型、披露、契约、实施方案、Guard、测试计划、参考和实施 Prompt，以及相关完整归档上下文 | 完整需求/决定、仓库/实例、架构、契约、Feature/Guard/Test、领域状态、演进、风险、Local Chat 注入记录、归档全文和接手 Prompt |
| 前版内容 | 逐项映射去向 | 逐项映射并核对全项目实际范围 |
| 证据 | 已存在/拟新增与计划验证分开 | 源码/执行、历史/本轮/未测/未知分开 |
| 形态 | 新目录完整包及同名 ZIP | 新目录全量快照、完整合订本、清单及同名 ZIP |

全量要求覆盖和内容完整；功能全部实现或测试全部通过需要独立证据。未实现、待决、失败、skip 和风险也是完整包必须保留的内容。

S8 必须执行全项目范围盘点与覆盖核对。可利用索引、已有证据和分域调查提高效率；不能只扫描 diff 就宣称全量核验。未访问范围明确列缺口，必要内容不可获得时标 INCOMPLETE，不能冒称完成。

S6 代码修正可以最小化；用户随后要求 S4/S8 时，重新交付完整版本。交付时不能以“本轮只改一点”为由改成增量附件。

<a id="bias"></a>
## 4. 用户纠偏持续生效

从实际表达中提取目标、约束、偏好、反例、优先级与数据处置范围。不要把模型自己的偏好写成用户决定。

每次明确纠偏：

1. 记录来源与忠实正文，保留“仅、必须、不得、当前、测试数据、暂不”等限定语义。
2. 定位所修订的需求、决定、契约、实现假设或验收标准。
3. 标明适用范围、生效位置和继续保留的要求。
4. 用户表述明确则更新规则并推进已授权工作；仍有实质取舍时只问阻塞部分。
5. 沿影响边更新 PRD/AC、原型、技术规范、实施 Prompt、代码与测试要求；跨专题只同步受影响的已确认变化。
6. 下一次 S4/S8 同时更新完整正文与决定记录，不只留在聊天摘要中。
7. 相关条目若已归档，按同一 ID 重新激活并重置未变计数，保留全部归档/恢复历史；用户当前明确要处理的事项直接进入活动范围。

决定状态见 [Records](Records.md#decisions)。用户拒绝的方案不能以“更通用”等未经确认的理由恢复。可以说明实际风险，不能据此改写已决定的产品语义。

本版直接决定持续有效：S4/S8 全量；防止多轮转述丢失信息并保留跳跃/残差连接；用户不断纠正 LLM 输出方向；五轮未使用条目完整归档、再次有效提及时恢复；最终 Handoff 前批量汇合 Local Chat 来源；按事项和事件进行有原文依据的细粒度提取。

<a id="preservation"></a>
## 5. 信息保全的可检查要求

将“不能接受文件的熵减”落实为语义条目保全。字节、token、段落数量和 SHA256 不能证明语义完整，只能辅助物理一致性。

每条输入信息在输出中须有一种明确去向：

- **保留**：仍有效，指向新包正文。
- **修订**：给完整新表述、旧表述历史位置与修订依据。
- **合并等价重复**：保留全部来源，核对独有条件没有丢失。
- **被取代/否决**：保留历史身份、替代条目和用户来源。
- **延后**：保留目标、原因、依赖及启动条件。
- **无法核验**：保留已知内容和来源，明确缺口与下一步。
- **移入归档**：保留完整条目、五次复核依据、来源和重开条件，指向本版档案；有效规范与当前影响仍在当前正文。
- **重新激活**：沿用原 ID，记录新 bias/证据与恢复事件，原档案和历史不删除。

不得用“已整合”“总体一致”“其余参考上版”作为去向。新正文也需来源或明确标为提议。纠正旧错误、保留旧证据日期，信息保全不要求让旧错误继续生效。

逐项核查正常、异常、权限/只读、取消、清理、回滚、skip、状态持有者、并发、兼容、性能条件、长期需求、反例与风险。确实不适用才写 `N/A + 理由`。

S4/S8 结束前做输入→输出和输出→输入核对。使用 [条目去向模板](Records.md#preservation) 和 [包检查](Packages.md#checks)。

<a id="links"></a>
## 6. 跳跃链接与稳定编号

优先沿用真实交接的 `N-04`、`GN-04`、`D08` 等编号，不因重组目录重命名所有历史条目。无既有系列再建立稳定 ID。

至少连接：需求→决定；需求/AC→Feature；Feature→符号/契约/Guard/测试/风险；测试→AC/Guard；用户纠偏→受影响位置；旧条目→新条目。关键关系可在字段中表达，不要求所有节点彼此全连接。

使用显式 ASCII 锚点和相对链接。移动文件后更新指向，保留旧 ID 或映射。两套输入同名 ID 加来源命名空间，尤其旧 `C` 可能表示 Change 而非 Contract。

合订本从同版规范化正文全文生成，包括注入登记和档案；内部链接重写到本文件锚点，不能手工维护第二套事实。原始聊天、日志、原型等必要来源可保持原格式作为同包附件，不能依赖未携带资料。单发合订本时明确仍需同时携带的来源附件，不冒称逐字内含尚未内嵌的原始会话。

<a id="actions"></a>
## 7. 按实际授权推进

对已明确要求的可逆修正、只读检查和必要实施直接推进，不为固定阶段门槛重复确认。真正缺产品取舍或权限时，只问必要问题。

共享工作树由 Main 统筹，发现新改动先重读对齐。不同 worktree 隔离文件，仍须统一契约和集成版本。只要求注入、解释或同步时，不自动实施其他阶段。

保护原始素材、真实 Workspace、旧包与宿主依赖。测试数据替换授权记录范围，不扩张成所有数据可删除，也不忽略已明确的无需迁移决定。

完整来源与本版取舍见 [Sources](Sources.md)。

<a id="intake-archive"></a>
## 8. 先汇合来源，再决定注意力去向

S8 先登记预期 Local Chat，收集完整相关原文及附件，Main 实际分批读取，逐条映射用户决定、理由、未采纳方案、失败尝试、error/skip、未决问题和执行证据，再复核截止后新增内容。只有汇合完成，才最终判断“本轮无实质变化”与生成归档候选。接收到文件、算过哈希或读过摘要不等于读过会话来源；参见 [批量注入协议](LocalChatIntake.md)。

最近有效提及或实质变化的快照 H0 不计次，其后五次同一正式交接主线的独立完整 S8 逐项复核未变、未使用，才满足默认归档条件。未取得历史、未检查、草案、重复压缩和并行副本不能凑数。本轮先算候选，来源与包完整性门通过后才固化计数。新对话中有效提及可以立即恢复活动状态，不需等待 S8 完成；它自身不增加交接次数。规则与字段见 [归档规范](Archiving.md)。

归档减少日常重复展开，保留条目全量信息及所有来源。`attention_state` 独立于决定、实现、执行和阻塞状态；不把未解决错误改成已解决，不让 ACCEPTED 规则、权限或 AC 因年龄失效。当前归档正文只承载仍归档的事项；恢复时全文进入活动视图，旧内容、证据和事件继续在同包规范化历史中保存。有效约束及必要当前影响固定保留。

由 [ChatExtraction](ChatExtraction.md) 区分新提及、真实测试运行、错误复现、历史携带和例行检查，Main 核对语义后给脚本事件；字面命中只是候选。全量包里的旧原话、生成视图和旧日志反复出现不能使所有归档自唤醒。

完整存储与本次输入上下文分开：正式包保存全部应有信息，普通 Chat 优先读有效规则、活动正文与轻量索引，按相关 ID 取回冷档。状态和派生视图的具体流程见 [StructuredContext](StructuredContext.md)，不能通过仅输出一份活动摘要缩减 S4/S8 全量交付。

可追溯范围是已声明、实际取得并读取的材料；没有提供或无法读取的聊天列为缺口，不能保证记录未见内容。完整记录的未决产品冲突可以保留为未决，不能为使收集状态好看而假装已裁决。
