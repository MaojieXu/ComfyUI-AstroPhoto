# Phase9 / S9 · 从完整包接手下一轮

[返回入口](../SKILL.md)

目录：[职责](#role) · [输入](#inputs) · [恢复](#restore) · [执行](#continue) · [交付](#deliver) · [Prompt](#prompt)

配合 [核心原则](../references/Principles.md) 与 [记录规则](../references/Records.md) 使用；检查包完整性时读 [Packages](../references/Packages.md)。

恢复归档内容和对话来源时，按 [归档规范](../references/Archiving.md)、[对话注入规范](../references/LocalChatIntake.md) 和 [ChatExtraction](../references/ChatExtraction.md) 核对注意力状态、来源覆盖及真实新增事件；引擎状态按 [StructuredContext](../references/StructuredContext.md) 读取。

<a id="role"></a>
## 1. 职责

新 Web Chat 或 Local 从完整交接包恢复当前行为、有效用户决定、共享契约、证据边界和未完成项，然后按本轮目标继续。按需读取有链接的专题，完整基线始终保留可访问。

S9 不自动重写需求、重置编号或恢复已否决方案。不能把旧代码行号、版本、测试计数及历史结果当成本轮事实。

<a id="inputs"></a>
## 2. 输入

- 完整包的入口、当前状态/版本、需求与决定、架构/契约、风险和下一任 Prompt。
- 活动入口、归档索引、Local Chat 注入登记及来源缺口；本轮相关的归档全文与必要来源附件。
- 与本轮目标有关的完整专题正文、源码/测试定位和必要原型。
- 用户在打包后新增的明确决定及来源。
- 本轮要交付的结果、允许的操作，以及 Local 的实际仓库/实例。

单文件接手使用同版完整合订本；任务涉及原型操作时同时提供对应资产，依赖原始对话核验时同时携带必要来源附件。仅有旧包路径但无内容时，不声称已读取。

<a id="restore"></a>
## 3. 沿跳跃链接恢复

1. 从 `00_START_HERE.md` 识别包版本、范围和 COMPLETE/INCOMPLETE；确认缺口。
2. 读最新用户决定及其替代关系，保留未取消需求，理解当前可见行为与验收条件。
3. 读架构、状态所有者和共享契约，定位该专题的生产者/消费者与负责 Main。
4. 直接跳到相关 Feature、Guard/error/skip、测试断言和风险；必要时越级回到用户原始决定与关键证据。
5. 比较历史基线和打包后新决定，建立本轮明确残差，不丢旧基线。
6. 发现链接失效、正文缺失或冲突时记录具体缺口；已有内容继续处理，缺失不解释为不存在。

启用引擎时先查当前有效约束、ACTIVE_CONTEXT 与 CONTEXT_INDEX，再按本轮任务、共享依赖和恢复条件读取相关归档全文；普通任务不默认灌入 FULL 或反复翻全部归档。使用运行存储时从 CURRENT 指向的同一快照读取 state 和视图，不能按目录时间猜最新版或手改生成文件。旧包沿已有入口读取，首次导入按 v2.2 规则建立 H0，不凭空假设它含新视图。正式完整包仍须全量携带活动、归档、状态历史和来源。

归档不使有效规则失效，也不证明错误已修复；缺失或未读的 Local Chat 来源继续显式保留。S9 接手、旧文复制和例行阅读不增加 S8 次数，也不作为新的语义提及唤醒条目。

先给简短接手回执：本轮目标、当前行为、已确认决定、可复用点、共享影响、实现/验证边界及下一步。不要用长篇重述占用工作，也不能只说“已理解”掩盖未读材料。

<a id="continue"></a>
## 4. 按角色继续

### Local

核对实际仓库、适用 AGENTS/Skill、分支/HEAD/未提交改动、目标实例和相关测试。发现包与工作树不同，分别记录文档历史、当前源码和新用户目标。

用户已要求实施时，在明确范围内进入对应 S5/S6；需要共享契约或新的产品决定时，只补缺失阶段。采用目标版本官方/现有项目实现，保留其他工作。不能因接手默认运行全套测试或改真实宿主。

### Web Chat

按附件推进本专题设计、研究和规范。缺本地事实时给短定向 S3 Prompt，要求返回实际入口、函数、Guard、消费者、测试断言与证据。不猜路径和现有函数。

用户只要 Prompt 或解释时按其要求结束。涉及新界面或实质交互设计，按 S2 给可操作离线原型。需要正式完整工程包时调用 S4。

### 新的纠偏

用户任何明确新决定都更新本轮有效 bias，标明取代范围和保留项。仅因存在新决定，不需要让用户重复确认已明确部分。

真实新讨论重新提及条目，即使代码未变，也按 [S6](Phase6.md) 沿同 ID 用 touch 恢复 `ACTIVE` 或归零；新用户要求、实际测试运行、错误复现及实质证据同样记录精确来源和事件。旧日志与历史引用不冒充新发生。当前归档中的全文移回 ACTIVE_CONTEXT，档案保留稳定锚点索引；同包 state 和旧快照保留完整历史。touch 不计轮次，下一次完整 S8 建立 H0=0。

S4/S8 的全量规则延续到下一轮。对本轮局部变更的即时回执可以简短，正式交付仍需融合回完整包。

<a id="deliver"></a>
## 5. 交付与退出

接手成功意味着能具体指出：当前要做什么、已经实现什么、证据在哪、将影响谁、如何验收，以及哪些信息仍缺失。

输出本轮实际完成的工作或可独立转交的阶段 Prompt。若只要求注入，交接回执后结束；若已要求继续任务，直接推进，不停在“可以开始”。

保留需要更新的条目映射，后续 S7/S8 收尾时完整携入。不能将新的短接手回执替代原完整包。

## 6. 可复制 Prompt

```text
使用 AstroPhoto SOP v2.2 执行 S9。你接手[专题/任务]，本次交付[结果]，可执行[授权范围]。输入[完整包入口、同版state与活动/归档视图、必要原型及来源附件、最新用户决定]，Local仓库[可访问路径；Web Chat无则说明]。
先读当前约束、活动/索引和注入登记，沿链接读取相关完整正文，保留基线与替代历史；启用引擎从CURRENT取同版state及ACTIVE_CONTEXT/CONTEXT_INDEX，旧包按实际入口读取。真实新提及沿原ID touch恢复或归零，旧文复制和例行检查不唤醒；视图由state生成，不手改。分清源码、实例、历史验证、本轮执行和未知。先简述目标、复用点、共享影响及缺口，再推进已要求工作。
Local对照真实工作树和实例后实施；Web Chat根据可读材料推进设计，缺本地事实给短定向S3披露Prompt。用户新纠偏即时作用到相关条款，未取消内容保留。S4专题全量、S8项目全量的规则持续有效；禁止用本轮变化摘要替代完整包。交付实际结果、依据、验证边界与下一步。
```
