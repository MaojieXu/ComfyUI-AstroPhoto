## 1. 职责与输入

由 Local Main 实际完成本轮全部已接受的 AC，统筹共享文件、消费者、最终集成和验收结论。只读子 Agent 提供可核查事实，Main 负责最终技术选择与结果。

完整需求包限定要实现的行为；最小代码改动限定实现方式。两者同时成立：实现本轮全部范围，同时保留现有能力，避免无关重构。

输入应包含：

- S4 专题全量包的实际路径和版本，或已明确的局部任务及完整相关上下文。
- 已接受 AC、原始需求、用户最新纠偏、原型和共享契约。
- S3 披露、已有实现与拟改点，以及当前工作树。
- 本轮允许的修改、验证、宿主操作及数据处置范围。
- 多窗口负责人、各工作树和最终集成目标。

先读 [核心原则](../references/Principles.md)、[记录字段](../references/Records.md)、[项目背景与验证](../references/Project.md)。独立调研采用 [子任务规范](../references/Subagents.md)，完整文档交付采用 [包规范](../references/Packages.md)。

明确行为的局部修复可以直接进入本阶段，不强制重新审批已经接受的 PRD。用户只请求 Prompt 或解释时，按其要求返回，不擅自开始实施。

## 2. 实施前核对

### 2.1 重核实际工作树

- 读取实际仓库 `AGENTS.md`、适用 Skill、相关 task note 和完整需求包。
- 记录分支、HEAD、既有未提交改动、当前实例及涉及的依赖版本。
- 将包内披露与当前源码对照；过期路径和函数先修正定位，再实施。
- 按每条 AC 建立“用户动作 → 状态所有者 → 调用链 → 可观察结果”的对应。
- 记录需要保持的旧行为、共享消费者和未取消的长期需求。

用户已经明确的数据处置决定直接按其范围采用。例如明确授权替换的可丢弃测试数据，不额外设计无必要的迁移；该授权不能延伸到真实素材或其他数据。

### 2.2 查证官方与项目复用

遵循实际仓库中 `.agents/skills/astrophoto-reuse-reference/SKILL.md` 及相关前端复用 Skill 的适用规则。仓库存在 CodeGraph 时先查询精确符号与调用方，随后核实源码。

历史规范记载：前后端开发前独立委派只读 `gpt-6.1-terra`、`medium`、`fork_turns="none"`。执行时先读取目标仓库的现行要求；实际模型或工具不可用时如实说明替代执行者、已完成查证及缺口，不声称切换成功，也不制造无关审批。

前端核对组件表、模板原码、已有适配和目标版本官方前端；后端查真实宿主源树，排除本扩展与其参考镜像的误命中。

复用优先顺序：适用官方公开 API/现有接入 → 项目已有实现 → 最小修改或局部适配 → 必要新增。采用内部 API 时写清版本耦合、兼容影响与回退方式；移植代码保留来源、许可和必要依赖。

Main 复查只读调研的共享契约、关键 Guard 和版本结论，再确定改动。不能让子 Agent 自行改业务代码或宿主。

### 2.3 固定集成责任

共享工作树由一个 Main 统筹写入。独立工作树的成果分别记录来源、测试版本和集成状态。

共享契约发生变化时，列明生产者、消费者、旧值、新值、旧数据或旧工作流处理、验证方法和写入顺序。

既有用户授权足以覆盖的技术选择直接推进。仅对尚未决定且确实影响用户语义、不可兼容行为或新的破坏性处置提出问题，同时继续完成不依赖该决定的工作。

## 3. 实施步骤

### 3.1 先贯通正式入口

选择一个完整用户场景，沿现有正式入口实现到可观察结果。UI、API、服务、存储、Node 或外部软件按实际依赖衔接。

不能只让孤立函数通过测试，而正式界面或 Node 仍未接入；不能用静态假状态替代真实业务调用。

### 3.2 完成本轮全部 AC

按 AC 清单完成正常路径及必要的空态、加载、失败、取消、只读、并发与恢复行为。对不适用项写清理由，不机械增加功能。

落实输入校验、权限边界、错误码、skip 语义、状态刷新、重复调用与部分失败的可观察结果。

涉及文件与数据库时，核对接收、写入、发布、登记与回滚的顺序，以及失败后源文件和已生效状态是否保留。

涉及外部进程时，核对真实命令、工作目录、输出验证、错误回执和清理；仅采用已接受的 timeout/并发/文件大小策略，不擅自恢复已撤销的限制。

### 3.3 持续接收用户 bias

实施中收到新的明确纠偏，立即记录原要求、最新要求、适用范围、替代关系和影响的 AC/契约/测试，并调整后续实现。

用户的最新要求直接连接实施点及验收；没有受影响的有效要求继续保留。需求尚有实质取舍时，转入 [Phase 6](Phase6.md) 对应部分处理。

真实新增讨论重新提及某条目，即使代码和结论未变，也按 [Phase 6](Phase6.md) 沿原 ID 恢复关注或重置空闲计数；新处理要求与实质证据同样处理。保留来源与历史，不能因已归档而忽略明确用户纠偏。

新纠偏改变 S4 契约时，更新完整规范中的相关正文及残差记录。再次交付 S4 时必须输出新的专题全量包，不能只给补丁说明。

### 3.4 完成集成与生命周期

验证正式注册/挂载入口、导入导出、缓存失效、序列化、卸载清理和旧消费者的实际行为，选择与本轮改变相关的边界。

发现其他窗口已修改同一文件时，先重读差异并协调集成。保留他人改动；不能通过覆盖、reset 或 clean 简化冲突。

将独立工作树成果集成到指定目标后，重新核对组合中的接口和构件。专题测试通过不自动证明集成目标通过。

### 3.5 保存对话来源与实施经过

按 [对话注入规范](../references/LocalChatIntake.md) 保存本窗口实际可取得的相关对话导出或可访问原文，登记 Chat 标识、消息/时间范围、负责人、工作树与读取边界。持续记录公开对话中的有效用户 bias、重要尝试、失败及放弃依据、尚未裁决项和真实执行回执，保留它们到 AC、决定、代码和测试的映射。

按 [ChatExtraction](../references/ChatExtraction.md) 将稳定事项和实际发生事件分开，保留来源版本、原话范围、事件 ID 与覆盖去向。真实测试运行记 TEST_RUN，错误本次复现记 ERROR_RECURRED；清单中的测试名、复制旧日志与例行检查不算新发生。已有事件重导出保留原身份，不因导出版本改变而再次唤醒。

使用 [结构化上下文引擎](../references/StructuredContext.md) 时，新语义提及可先预览再用 `touch` 及时恢复，S8 尚未完成也可执行；touch 不增加 Handoff 次数，下一次完整 S8 才建立 H0。从 CURRENT 指向的同一快照读取状态和视图，不手改生成的 Markdown 或计数。

不能只保留最后成功结论而丢掉影响后续判断的失败条件。不可取得的原文列为来源缺口，不用事后摘要冒充原始记录；已有完整回执可以复用并保留其身份。S7/S8 收尾时交付这些来源和完整相关事实，不额外要求提供内部思考过程。

## 4. 验证与失败处理

按 AC、影响范围、仓库要求及本轮授权选择最低必要验证。先验证直接受影响行为，再补能解决具体剩余风险的回归；不为纯粹重复实现的断言或低影响变更扩大测试工作。

用户明确要求“先实现，不测试”时完成实现，逐项记录 `NOT_RUN` 和原因，不自行更改这项决定。

| 要证明的行为 | 记录方式 |
|---|---|
| 校验、配置、事务和文件恢复 | 精确测试、真实临时 SQLite/文件或替身、失败注入点和最终状态 |
| HTTP 与权限 | 请求、状态码、错误码、回执，以及哪些宿主/外部依赖被模拟 |
| React/Vue 交互 | 实际挂载组件、用户动作、前置状态、宿主/HTTP 替身及断言 |
| Siril 处理 | 真实 CLI 版本、隔离输入输出、FITS 可读性、原件完整性及下游内容 |
| ComfyUI 注册 | 目标实例的实际 Schema 查询；只证明注册 |
| ComfyUI 工作流 | prompt ID、history、完成状态、产物及下游实际收到的值 |
| MCP 与打包 | MockTransport、stdio、真实宿主、包内容或发行分别记录 |

运行前检查脚本副作用。历史命令 `pnpm -C frontend test` 会先构建并写 `js/`，当轮必须查实际脚本；只读或禁止构建时采用合适隔离方式或记未运行。

保护真实 Workspace、原始素材、共享宿主核心和已有交接。真实宿主写入按已有授权在指定隔离实例进行；不要向真实 ComfyUI 宿主执行未经授权的依赖同步。

失败时区分产品缺陷、测试配置、过期 fixture、环境失败与未运行。保留标准命令和临时探针各自结果；不得改断言掩盖需求未满足，或只报告成功的那一次探针。

实现状态、执行环境、执行结果单独记录。`PASS` 绑定具体 AC 和断言，`SKIP`、`XFAIL`、`FAIL`、`NOT_RUN` 均注明原因或预期。外部条件阻塞另记 `BLOCKED` 及所需条件。

## 5. 必须交付

交付实际代码和完整实施回执，不以建议代替实现。回执至少包括：

1. 本轮完整 AC 清单、接受的用户纠偏及各项最终状态。
2. 实际变更文件/函数、复用依据、正式入口及状态流。
3. 共享契约、消费者、兼容处理及集成到哪个工作树。
4. Guard/error/skip、取消、清理、恢复与数据副作用。
5. 精确测试、关键断言、环境/替身、命令、日期、退出码和结果。
6. 未实现、未验证、失败、阻塞、风险及下一步。
7. 工作树前后差异、文档更新与实际交付路径。
8. 本窗口 Local Chat 来源、已记录范围、重要失败尝试及供 S7/S8 回收的材料位置和缺口。

每条 AC 直接连接有效用户决定、实现符号、Guard 和测试；从测试记录也能反查行为。不要仅列“修改了哪些文件”。

用户没有要求提交、推送或发布时，交付当前工作成果与回执即可；已明确授权相应操作时按该授权执行，不重复确认。

<a id="p5-exit"></a>

## 6. 退出条件与分支

- 本轮全部已接受 AC 均有结果，任何未完成项都有具体原因。
- 正式入口与共享消费者已经接通或明确列为未完成。
- 本轮实际测试、历史证据及未测边界可以逐项追溯。
- 既有用户数据、未提交修改及仍有效需求得到保留。
- 多窗口成果的集成状态清楚，未把不同工作树的验证混为一条通过声明。

实际体验反馈进入 [Phase 6](Phase6.md)；专题收尾进入 [Phase 7](Phase7.md)；整轮移交进入 [Phase 8](Phase8.md) 的项目全量交接。
