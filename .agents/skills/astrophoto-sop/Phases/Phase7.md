## 1. 职责与输入

由所属 Web Chat 整理本专题完整、可独立接手的最终材料，Local Main 提供源码和执行证据。覆盖从最初需求到本轮最终状态的全部专题内容，包括未改变、延后、失败和未验收部分。

S7 的范围是本专题及其必要共享边界。它将完整材料交给 [S8](Phase8.md) 做全项目核对；不能将专题覆盖声称为全项目覆盖。

收尾不要求每项需求都已实现。交接必须完整呈现已实现、部分实现、计划项、过时项、未知项及其依据。

| 输入 | 核对要求 |
|---|---|
| 最初有效需求与原型 | 找出原始目标、全部 AC、边界、非目标和长期需求 |
| 本专题完整 S4 包 | 取得当前正式版本的正文、实施契约、必要源码披露和官方参考 |
| 用户全过程纠偏 | 保存已接受决定、取代关系、例外条件与尚未裁决项 |
| Local 最终回执 | 取得真实改动、工作树标识、接口、Guard 和测试断言 |
| 本专题 Local Chat 来源 | 按已登记窗口收取相关完整对话材料、消息/时间范围及读取/融合回执 |
| 本专题历史材料 | 核对旧功能、失败、风险与未完成项在本轮的去向 |
| 共享消费者 | 查清契约影响、其他窗口回执及进入集成目标的状态 |

缺少 Local 证据时，列明所缺文件、符号、测试或回执；请求针对性补充。已有材料仍可整理成完整结构的草案，但标明 `INCOMPLETE`，不能宣布最终交接已通过。

按 [对话注入规范](../references/LocalChatIntake.md) 对照本专题预期来源名单实际收取和阅读材料。已接收不等于已读，最终实施回执不替代窗口中的独有讨论；缺失来源说明影响并交给 S8。S7 回收本专题来源，不宣称已完成最终生成 Agent 的全项目批量注入。

按 [ChatExtraction](../references/ChatExtraction.md) 一并交付事项、事件与消息范围覆盖回执。稳定事项 ID 与事件发生 ID 分开；真实新提及、TEST_RUN、ERROR_RECURRED 与旧记录复制、历史引用、例行复核分别分类。原文完整保留，新增范围只用于事件判断。

## 2. 执行步骤

### 2.1 建立本专题完整范围

从原始需求、当前完整规格和历史基线列出全部有效条目。逐项标记本轮改动、保持有效、延后、明确取消、被替代或缺证据。

保持既有编号。编号冲突时保留来源与映射，不把同一个 ID 悄悄重新用于另一个功能。不要只枚举本轮修改过的文件或按钮。

### 2.2 回收每条需求与 AC

对每条 AC，记录最终用户行为、实际入口和状态所有者、输入输出、副作用、共享消费者、Guard/error/skip/恢复、测试断言、执行环境和结果。

实现状态使用 `IMPLEMENTED / PARTIAL / PLANNED / OBSOLETE / UNKNOWN`。执行结果使用 `PASS / FAIL / SKIP / XFAIL / NOT_RUN`，所需外部条件另记 `BLOCKED`。材料覆盖是否完整另记 `COMPLETE / INCOMPLETE`。

来源区分 `SOURCE / HISTORICAL_RUN / CURRENT_RUN / INFERENCE`。历史验证保留日期、命令和环境；本轮未重新执行时不能升级为 `CURRENT_RUN`。

仅有方案、原型或拟建符号时标清计划身份。用例标题、测试文件存在或 Agent 口头声称，不能替代实际断言与执行回执。

### 2.3 保存用户 bias 及设计演进

保留用户明确决定的来源、适用范围、取代关系和理由。未改变的决定继续进入本专题交接。将被取代方案标 `SUPERSEDED`，同时指出新的有效规则。

完整保留尚未取消的长期需求、先前已确认的例外和被拒绝方案的重要限制。避免后续 Agent 因只看到终态一句话而重复提出已被否决的设计。

按 [归档规范](../references/Archiving.md) 携入本专题相关活动/归档全文、稳定 ID、归档与恢复依据，活动入口保留必要定位及仍有效约束。真实新提及即使没有代码变化也先按 S6 用 touch 恢复或归零；S7/touch 不增加五轮 S8 次数，下次完整 S8 才建立 H0。不能把“已归档”当已解决。

使用 [StructuredContext](../references/StructuredContext.md) 时，从 CURRENT 指向的同一快照取得状态；恢复项全文位于 ACTIVE_CONTEXT，当前归档只留恢复索引，历史完整留在 state 及旧快照。交接携带本专题完整必要内容和相关历史，不能手改生成视图来调整状态或计数。

将原始决定直接链接到最终功能、契约和验收，允许接手者越过中间讨论找到依据。

### 2.4 核对共享契约与集成事实

记录契约提供方、消费者、旧/新行为、兼容决定、错误语义和数据处置范围。对未变的共享契约也保留本专题依赖的完整语义。

Local Main 核对各窗口的仓库、worktree、分支、HEAD、相关未提交改动和测试版本。说明改动是否进入集成目标；独立 worktree 的测试不能自动代表集成目标已通过。

共享目录中的 diff 只能证明改动存在，作者归属需要其他依据。某窗口不可读时注明缺少哪份回执，不把未确认同步写成已完成。

### 2.5 形成完整专题交接

在新目录组织本专题完整正文，保留旧版快照。可按职责拆分少量文件，但不得以文件数、字数或 token 预算删去有效信息。

必要内容可以复用已有正文后校正。不得只写“沿用旧包”或要求下一位打开未随包提供的附件才能知道关键要求。

把本专题各 Local Chat 中的用户 bias、取舍、失败尝试、错误条件、未决项和执行证据映射到正文条目，保留来源材料、消息定位、事件分类和范围覆盖。交给 S8 时同时给出预期来源清单、实际已收/已读/已融合范围和缺口，供最终生成 Agent 完成批量核对；来源缺口不能当作空闲或未提及。

保留适用的最终可交互 HTML 原型、完整原型说明和真实实现差异。原型标明模拟数据及未连接的能力；截图不能代替交互原型。

所需官方参考保留 URL、访问日期、目标版本和适用边界；必要短示例标明来源与示例身份。项目函数和外部示例分别标注。

对不能随包提供的源码，用精确仓库路径、符号、版本、必要片段和可读取前提建立证据入口；将不可读取的资料显式列为缺口，不能用空链接伪装包内自足。

### 2.6 检查信息去向与链接

建立“原来源/ID → 当前位置 → 保留、修订、替代或缺失 → 依据”的去向记录。对缺失项补全，或显式列出无法取得的材料及影响。

检查需求、用户决定、Feature、Guard、测试和风险之间的双向链接；每个链接应定位具体条目。用正文承载完整规则，用变化索引解释演进。

若按需提供合订本，从同版专题正文生成，校正内部锚点并核对等价。合订本不得成为自行维护的第二套规范。

可使用 `scripts/verify_bundle.py` 检查包内链接、锚点与文件哈希。结构检查通过仅证明其检查范围，仍需人工核对语义完整、来源覆盖和证据真实性。

## 3. 必须交付

本专题交接至少完整包含以下信息；按 [Packages](../references/Packages.md) 组织实际文件。

| 内容 | 最低要求 |
|---|---|
| 接手入口 | 专题范围、负责人、完整性状态、工作树、版本、时间、阅读路径 |
| 需求与决定 | 全部有效 AC、用户 bias、长期需求、被取代决定及其来源 |
| 当前实现 | 真实入口/函数、数据流、持久化副作用、已完成与未完成范围 |
| 共享契约 | 提供方、消费者、类型/字段/行为、兼容和集成状态 |
| Guard 与错误 | 实际触发条件、错误码、skip、清理、恢复和缺口 |
| 验证 | 精确断言、环境/替身、命令、日期、退出码和结果 |
| 原型与实施资料 | 本专题必要完整规格、适用原型、真实实现差异和参考来源 |
| 演进与剩余工作 | 旧内容去向、残差关系、风险、未决冲突和下一步 |
| 对话与归档来源 | 本专题 Local Chat 源材料、读取/融合范围、相关归档全文及缺口 |
| 交给 S8 的入口 | 完整材料位置、必须复核的共享边界、证据不足项 |

普通文本证据直接写入正文，按需要保留用户要求的日志或取证材料。跨环境交付时保证所有必需正文与资源一起可传递；不得以仅包含变化的附件代替本专题完整交接。

<a id="s7-exit"></a>

## 4. 退出条件与分支

专题原范围内每条有效需求都有结果或明确缺口；用户纠偏已传播；旧信息有去向；本包能够独立说明当前状态及其证据边界。

- 材料齐全且覆盖核对通过：标 `COMPLETE`，交给 [S8](Phase8.md)。即使有功能未实现，也应保留该事实和下一步。
- 材料仍缺失：交付当前完整结构草案并标 `INCOMPLETE`，列明最小补充材料，不假称收尾完成。
- 发现实现偏差：交给 [S6](Phase6.md)；发现规格需更新时执行 [S4](Phase4.md) 的专题全量交付。
- 用户只要求专题交接：在本阶段结束；不要自行扩大为实现、发布或全项目审计。

```text
逐项回收本专题全部有效需求与 AC，包括未改动、延后、失败、skip、未完成和未验证项。分别记录用户决定、实际实现、证据来源、环境与执行结果；保留工作树和日期。核对共享契约、消费者与实际集成目标。
保留完整基线，融合新的源码事实和用户 bias，交付可独立接手的专题完整正文与适用原型。建立旧来源/ID到新位置的去向表，以及需求、决定、函数、Guard、测试、风险的跳跃链接。变化索引不能代替完整内容；历史测试不冒充本轮执行。

```
