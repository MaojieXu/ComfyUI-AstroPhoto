<a id="role"></a>
## 1. 职责与固定范围

由 Local Main 负责全项目事实核验、跨 Chat 融合、信息保全和最终交付。可以将明确领域分给只读子 Agent，Main 对共享契约、关键 Guard、重要验证结论及完整性负责。

**S8 始终是全项目全量交接。** 包括本轮改变与没有改变的领域、原始仍有效需求、全部专题、既有能力、未完成项、失败/skip、历史决定及替代关系。不得把本阶段变成增量附件、diff 摘要或只合并本轮 Chat。

保持三项区别：

- 内容完整：项目范围、输入去向和当前事实在包内自足。
- 审计覆盖：哪些文件/入口实际读过、哪些继承历史证据、哪些尚未核验。
- 运行验证：哪些命令本轮执行、使用何种环境、结果和限制是什么。

全量覆盖不能由历史摘要冒充；全量交接也不授权无关重构、修改业务行为或破坏真实资产。

## 2. 收集输入并锁定基线

恢复以下实际可读材料；缺项说明影响并继续可做工作：

1. 当前实际仓库、适用 AGENTS/Skill、task note、分支、HEAD、暂存/未暂存/未跟踪改动。
2. 上一版完整 Local Handoff，包括全部正文和必要附件。
3. 每个 Web Chat 的完整专题终稿，以及对应 Local 实施/验证回执。
4. 原始有效 PRD/TDD、原型、需求包，以及本轮新决定和完整用户纠偏来源。
5. 当前源码、测试源码、配置/锁文件、运行实例与构件信息；历史运行证据注明来源。
6. 多窗口任务表、各工作树版本、成果进入集成目标的状态。
7. 本轮允许的安全测试、宿主和数据范围，以及交付目录/证据形式要求。
8. 每个预期 Local Chat 的完整相关原文/导出与附件、结构化条目、消息或时间范围、截止点和来源身份；包含只有讨论、失败或未改代码的窗口。
9. 上版完整活动/归档内容、稳定 ID、最近变化或真实新提及的基线、历史复核账、当前影响和重新激活条件；启用引擎时读取 CURRENT 所指同一快照的 state 与生成视图。

登记输入清单和文件身份：路径或附件名、版本/日期、来源类型、已读范围、缺失项。已提供内容不要要求用户重复。不能访问的窗口、路径或附件不能写成已经读取。

默认在 `.agent/handoff_history/ComfyUI_AstroPhoto_Handoff_<日期>_<序号>/` 新建目录。日期按用户时区，序号先检查；保留旧包。输出 ZIP 放在包目录外。

### 2.1 最终生成前的 Local Chat 批量注入

这是 S8 的必需前置工作，不新增阶段编号，也不等于已经替用户访问其他窗口。按照 [LocalChatIntake](../references/LocalChatIntake.md) 执行：

1. 从实际任务分工和用户提供范围登记预期会话名单、负责人、主题、引用、工作树与覆盖区间；不知道的来源列缺口，不能凭空宣称全部窗口已齐。
2. 在 `.artifact/HandoffInput/<batch-id>/` 收集每个来源包，保留完整相关会话及附件，同时整理用户 bias、决定及理由、未采纳方案、失败尝试、error/skip、未决问题、代码与验证收据。按 ChatExtraction 记录稳定事项 ID、事件 ID、精确来源范围、事件分类和完整覆盖去向，区分真实新提及/执行/复现与历史复制。
3. Main 实际分批读取来源正文，记录 `EXPECTED → RECEIVED → READ → RECONCILED`、已读范围与每条内容的承接位置。只收到文件或读过子 Agent 摘要不足以称为读过原始输入；不要求所有 token 同时存在上下文。
4. 完成全预期名单的收集、阅读和去向核对，回收收集期间新增的用户纠偏/运行结果，再关闭批次。若仍有缺失或不可读项，保留清单并按 INCOMPLETE 草案交付。
5. 把登记填入 `15_LOCAL_CHAT_INTAKE.md`，把必要原始导出/附件复制到新包 `sources/local-chats/`。完整记录的未决冲突保持未决，不按票数或最新文件时间戳替用户裁决。

来源收集中可以并行做全项目只读盘点；已明确的新提及可通过 touch 及时恢复，但不计 Handoff 次数。最终综合结论、空闲判定和新归档必须等实际注入完成。关闭批次后发现相关新内容，重新打开并补读、重做受影响判断。

<a id="inventory"></a>
## 3. 按全项目范围盘点

### 3.1 建立真实范围清单

列出项目实际业务源码、前后端、节点、API、存储、MCP、构建/打包与测试范围。区分本扩展、宿主源码、官方参考镜像、第三方依赖和生成物。每个目录记录纳入/排除及理由，未读业务文件不能无依据排除。

将目录/入口分派到具体负责人，返回实际阅读清单和未覆盖文件。只靠 `git diff` 不能完成全项目盘点。索引只提供定位线索，核对实际源码与变动文件。

### 3.2 从正式入口列 Feature

逐个可观察行为追踪 UI/API/Node/MCP → 业务逻辑 → 存储/外部进程/宿主 → 返回状态。记录 `path::symbol`、工作树版本、I/O、副作用、状态所有者、消费者和实现状态。

范围至少检查：存储/Workspace、资产、设备/光路、前端、科学节点/Siril、API/权限、MCP、构建与发行。按实际仓库增加或删除领域，并写明证据，不能照抄历史模块清单宣称当前存在。

### 3.3 逐 Feature 核对 Guard 与测试

根据行为检查参数/路径/格式/权限/并发/进程/只读/取消/输出/清理/回滚/skip。证明 Guard 位于正式调用链，记录触发后的用户回执和持久状态。

读取对应测试的具体断言，标明模拟边界、真实临时文件/数据库、CLI、浏览器、宿主 GET 或原生队列。缺 Guard/Test 时注明搜索范围。测试标题、文件存在、旧通过数都不能替代当前行为证据。

### 3.4 跨专题核验

对每个共享 Node 类型、API、持久字段、注册入口和宿主生命周期核对生产者与全部消费者。比较工作树实际落点、测试时版本和集成目标，不能以某窗口声称完成代替已经集成。

同一目录 diff 能证明改动存在，作者归属需要独立来源。不同工作树中通过的测试不自动代表合并后通过。

<a id="reconcile"></a>
## 4. 完整融合与证据核对

### 4.1 先保留完整基线，再融合残差

逐项建立 `输入来源/旧ID → 新文件/锚点 → 保留/修订/合并/取代/否决/延后/无法核验/移入归档/重新激活 → 依据`。覆盖上版所有内容、各专题及 Local Chat 新内容。未变化内容原样或等义完整携入当前规范或同版档案，避免重写时丢掉限定条件。

原始长期需求未被取消时保留；用户否决或替代的旧规则带历史身份。对历史实现错误先核对现源码，保留其纠正来源。不得把未知来源静默删掉。

### 4.2 把用户 bias 传播到完整结果

对每次用户明确纠正，检查决定、需求/AC、原型、契约、实现说明、Guard、测试与接手 Prompt 是否一致。记录用户原话或忠实表述、来源、适用范围、替代内容和保留项。

用户已经裁决的行为直接采用。真正未决的产品冲突列出来源、影响和最小待决问题；不要让 Agent 自行决定用户语义，也不因局部冲突停掉其他可完成工作。

### 4.3 建立可跳转的完整证据关系

从首页直接到决定、功能、错误/skip、测试和风险。原始需求可直达实施与断言；用户纠偏可直达受影响条目；Guard/Test 能反查 Feature/AC。沿用现有编号，重名保留来源映射。

正文写出完整事实及关键证据，不以“子报告已查”“见旧附件”代替。子报告独有的反例、缺口、失败条件和来源必须融入相应正文或同包可读的完整报告。

### 4.4 运行验证按本轮范围实施

运行已授权且可安全隔离的针对性验证，覆盖本轮关键判断与实际集成风险。测试可能改写构件、数据库或宿主时先识别副作用。只读任务无法安全执行则 NOT_RUN，并解释条件。

对稳定历史记录保留原日期、环境、断言与版本；源码发生相关变化时标出证据过时风险并补核验。不得批量把历史 PASS 改成当前 PASS，也不得为看似完整盲目运行破坏性命令。

### 4.5 对五次空闲事项剪枝并完整归档

先完成 2.1 的来源注入及 4.2 的新 bias 传播，再按 [Archiving](../references/Archiving.md) 逐项判断。最近变化或真实新语义提及重新建立 H0=0；后续 H1–H5 必须是同一正式主线中独立、完成且真实复核条目的全量 S8，既无变化也无新语义提及。缺轮证据、未读记录、草案、并行分支与重复 ZIP 不能累计。真实新提及即使代码未变也归零；实际 TEST_RUN、ERROR_RECURRED 与复制旧结果、例行检查分开。

使用 [StructuredContext](../references/StructuredContext.md) 时，从 CURRENT 读取当前状态，按真实提取结果生成事项、事件和本轮观察项；本轮最终 ACTIVE 的新增/恢复项同样需要复核。先用 `advance` 只读预览，或显式用 `--preview-dir` 生成候选正文；来源齐全后可用于全量组包检查。来源与包完整性门全部通过，才用 `advance --apply` 固化本轮计数及归档。草案失败不计次，重试同一正式轮次不加第二次；首次启用不盲继承 v2.1 旧未变计数。

满足 `idle_handoffs >= 5` 且未固定保留的事项，默认归档，无需逐项批准。由 state 唯一生成 ACTIVE_CONTEXT、当前档案和索引，不手工搬写视图或改计数。正式提交后从同一快照携入状态与视图，再生成 FULL、全包清单和 ZIP 并复验交付字节；预览或上下文快照自身均不等于完整 S8。

仍有效的规则、权限、AC、当前明确必办及必要阻塞说明固定保留，不能借归档隐藏失败或取消要求。真实新提及可在 S8 完成前 `touch` 恢复同 ID 并归零，下一次完整 S8 建立 H0=0；恢复项全文移回 ACTIVE_CONTEXT，当前档案保留稳定锚点与简短恢复索引。旧正文、复核账和事件完整保存在同包 state 及历史快照中，归档与恢复都不改变业务或测试状态。

<a id="deliverables"></a>
## 5. 必须交付

按 [S8 完整包结构](../references/Packages.md#s8) 形成一版独立、自足的全项目快照。沿用项目真实文件名和 ID，必要分组调整保留映射。

- 完整需求/决定、当前架构/契约、逐 Feature/Guard/Test、全部领域状态、来源与遗留。
- 输入→输出的完整去向表、残差与冲突处理记录，含未变化内容的落点。
- 实际阅读/未读/排除范围，以及 SOURCE/HISTORICAL_RUN/CURRENT_RUN/INFERENCE 区分。
- 独立可读的 `00_START_HERE.md` 和下一任 Web Chat / Local Prompt。
- 从同版全部专题全文生成的 `FULL_HANDOFF.md`，内部跳转有效。
- `15_LOCAL_CHAT_INTAKE.md`、事项/事件提取及来源覆盖回执、同包原始来源，以及本版 `16_ARCHIVED_ITEMS.md`；两份正文均全文合入 FULL。
- 启用引擎时，在新 Handoff 根目录完整携入同一快照的 `state.json`、`ACTIVE_CONTEXT.md`、`CONTEXT_INDEX.md` 和 `16_ARCHIVED_ITEMS.md`，保留生成的相对链接；ACTIVE/INDEX 也全文合入 FULL，完整状态保存全部内容版本和事件。
- `handoff_id`、`parent_handoff_id`、`source_batch_id`、完成状态和逐项复核账，使重复打包与真正下一轮可区分。
- 实际文件清单、按约定的 SHA256、完整同名 ZIP；用户要求的原始证据一并保留。
- 工作树前后差异、实际验证回执、COMPLETE/INCOMPLETE 和未完成原因。

原 `00–16 + FULL + MANIFEST` 核心结构为 19 份 Markdown；启用引擎增加 ACTIVE/INDEX 后为 21 份，再加实际原始来源。state.json 另计，所有文件如实列入清单，不凑少于 20 的旧组织目标。Local Chat 原始导出保留格式，不改扩展名或删内容。原型属于适用设计资料，必须同包或完整携入。

<a id="exit"></a>
## 6. 退出条件与缺口处理

只有以下检查全部得到真实结果，才能宣称 S8 完整交付：

1. 全项目范围清单和每域责任明确，真实阅读/核验/未知边界可查。
2. 上版和各来源每个有效条目都有新包去向；当前源码新增但旧文档遗漏的能力已登记。
3. 最新用户 bias 已传播，过时条款保留历史身份；共享消费者无静默冲突。
4. 每条重要行为有符号、Guard/缺口、测试断言/缺口及正确证据身份。
5. 新包不依赖未携带的旧附件补足必要内容，合订本与专题全文一致。
6. 链接、锚点、清单、ZIP 解压内容核验完成，原包和业务状态未被意外改写。
7. 预期 Local Chat 全部实际读取并逐项融合，必要原始来源在包内，关闭批次前最新纠偏已回收；缺口未被“无变化”掩盖。
8. 全部历史正文与事件在同包完整状态及来源中保留，新归档有五次真实空闲复核依据，最新提及/bias 先处理，固定规则和当前影响可见；本轮计数只在本版 COMPLETE 时固化。
9. 启用引擎时，来源版本与事项/事件/观察覆盖对应，重复与历史复制未误唤醒；CURRENT 指向的正式 state 和各生成视图同版，预览未冒充已提交状态，FULL 包含 ACTIVE/INDEX 全文。

缺必要来源或范围无法核验时，仍交付已经整理的全量当前草案，标 INCOMPLETE，逐项列缺什么、影响什么、谁补充。补齐后交新的完整版本，不能让接手者自行拼补丁。

通过后进入 S9。局部功能未实现或测试未运行可以明确保留，不能因此伪造完成，也不能将这些条目删去。

<a id="prompt"></a>
## 7. 可复制 Prompt

给用户转发时先填好下列短模板，通常约 600–900 个中文字。详细步骤由接收方读取本阶段和可访问完整包；不要把上面所有章节重复装进启动 Prompt。只有接收方确实无法读取规范且用户要求独立长指令时再扩展。

```text
使用 AstroPhoto SOP v2.2 执行 S8 全量全局交接。仓库[实际绝对路径]；输入[上版完整Handoff与state、所有专题终稿、有效PRD/TDD/原型、最新用户决定、预期Local Chat名单及来源]；输出[全新目录]；测试/宿主/数据范围[已授权范围]。
按LocalChatIntake和ChatExtraction收集并实际读完全部相关原文、附件，保留bias、决定理由、失败、否决方案、error/skip、未决和执行回执。登记稳定事项/事件ID、精确来源与覆盖，区分真实新提及/测试运行/错误复现和历史复制；最后补收更新，生成15及同包sources/local-chats。缺源未读则INCOMPLETE。
核对AGENTS、Skill、工作树与实例，按全项目目录和正式入口盘点所有领域，包括未改模块。逐Feature追踪函数、I/O、副作用、消费者、Guard/error/skip/恢复及测试断言，区分源码、历史、本轮与未知。分域调查由Main复核集成。
完整继承旧基线及所有条目去向，融合新证据和用户纠偏，保留未取消需求、替代历史与未完成项，建立需求/决定/Feature/Guard/Test/风险双向跳转；禁止只交变化附件。
从CURRENT读同版state；真实新提及可touch归零恢复，旧记录和例行检查不唤醒。完整注入后先preview候选，五次已完成S8无变且无新提及才归档；有效约束和当前必办固定保留。包门通过才advance apply计次；touch后下次完成S8建H0，重复打包/草案不计。状态与视图由脚本生成，不手改。
输出全项目完整正文、同根state/ACTIVE_CONTEXT/CONTEXT_INDEX/16、含15/16/ACTIVE/INDEX全文的FULL、全包清单及ZIP，核验去向、链接、哈希与解压。活动与档案合计保全全文，历史在state与原始来源。保护旧包及业务状态；缺材料交INCOMPLETE全量草案，报告覆盖、事件、未完成及S9 Prompt。
```
