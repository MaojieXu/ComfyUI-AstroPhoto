# 开发计划与实现历史

## 1. DEV：计划与当前状态

DEV 是动态的可接手路线图。每次用户确认需求后，根据实际代码和项目约束，建立或更新实施策略与任务；只描述计划、负责人 Chat、预计修改范围、依赖、状态及实际 DEV_LOG 引用。

推荐任务条目：

- ID / Created by / Owner Chat / Updated by / 时间
- 关联 FR/AC；没有产品需求变化的修复引用已有 FR，或说明具体维护目标。
- 实施目标、策略、依赖、预计 File Path/共享接口、局部验证计划。
- 状态：Planned、In Progress、Implemented、Blocked、Cancelled/Superseded（按实际范围使用）。
- 当前阻断、移交/修订说明、DEV_LOG 引用。

Owner Chat 是任务归属，Updated by 是这次实际编辑者。用户可以在新 Chat 接手明确的任务；不把复制对话视为自动移交。新增任务用公共唯一 ID，旧任务状态更新保留变更者和必要的历史。DEV 头部给出 Feature 当前阶段、活动任务及下一步即可，无需独立 INDEX 或 Chat/Role 文件。

### 策略设计

先研究现有实现、代码约定、调用关系、数据/接口/资源生命周期和已有验证。优先复用，安排可独立验证的最小有效增量。只有重大架构/跨模块契约需要时才独立记录 TECH，依据实际代码和可靠文档验证，指出尚未验证的假设；简单技术选型直接写 DEV。

预计修改范围并非硬性文件白名单；在授权目标内部可以因真实依赖调整并记录，涉及新的产品范围则先解决产品决策。并行任务先明确接口和重叠文件；避免任意扩大范围或占用其他 Chat 的计划。

## 2. 开发实际循环

1. 检查最新 PRD、DEV 和 Git/文件状态；记录本次开始时的已有修改和本 Chat 开工范围，避免错误归属其他会话的 diff。相关需求冲突按 SKILL.md 处理。
2. 依据用户授权更新任务为 In Progress，使用最新源码实施。跨层核对注册、导入、路由、调用方、数据持久化、回调、错误处理和外部依赖；删除/替换功能时检查全部适用调用点。
3. 对当前增量做少量真实验证：最贴切的单元/接口/局部集成/Smoke Test、相关 lint/typecheck/build 或人工路径检查。必要时补永久可复用的测试脚本；失败时诊断修复并复测，未能运行时记录理由。按项目实际环境验证，不能用构建成功冒充功能通过。
4. 做实际 diff 自检：目标、功能、错误处理、向后兼容、测试可用性、未授权变化、其他 Chat 修改。必要的静态检查在此完成，不强制独立 Review。
5. 更新 DEV 任务状态，追加 DEV_LOG（含无代码变化的重要决断/撤销），按 testing.md 同步 TEST_PLAN；核对 PRD，必要时标记旧正式测试失效。完成同步后再最终回复。

用户明确只让讨论、记录需求、测试或审查时，不扩展到业务代码实现。判断任务已实现与整个 Feature 已验收是两件事。

## 3. DEV_LOG：可追溯事实

对每个有意义的用户需求增量、修复、重要决断、拒绝、回滚、正式测试缺陷修复及关键用户反馈，追加一条 DEV 记录。顺序不限于严格时间并发；以唯一 ID 和真实时间定位。不要覆盖原事实、修改旧作者、把历史方案当作现行要求。

条目必需字段：

- DEV ID、Chat、真实时间、任务与 FR/AC 引用、事件类型及实际状态。
- 请求/最终决定；结果与原因；重要替代/关联 DEV。
- Changed Files：仓库相对路径、Added/Modified/Deleted/Renamed、具体变化、必要时旧路径→新路径。记录本次**所有**实际持久改动，包括代码、配置、测试、数据迁移、文档和适用证据文件。Feature 文档同步可在同条中简要列路径（含本 DEV_LOG 本身），避免递归另开条目；禁止将未修改、仅预计文件列为实际变化。无代码改动时明确写无代码变化，仍列实际文档变动。
- Local Verification：真实命令/测试选择器或可复现手动步骤、结果/关键证据、环境限制、失败原因与复测结果。保留失败和未执行，不只报告成功。不要记录完整冗长终端输出；用证据路径/摘要引用。
- Untested/Next：风险、未覆盖场景与相应 TC 或计划引用。
- 适用时附 User Feedback/Knowledge Candidate：记录用户原意、纠正和可能复用的行为/工作流、证据、适用范围；不擅自写入长期 Docs/Skills。

结合开始和结束的实际 diff/文件内容、工具改变和已知工作区状态核实归属；遇到其他 Chat 已有修改，不攫取其贡献。无法可靠区分时注明共享修改与不确定性，不声称全部由自己完成。

## 4. 最小同步与交接

实现完成时：
- PRD 核对有效需求；需求不变不重写。
- DEV 更新当前任务状态、Actual DEV 引用、真实剩余工作。
- DEV_LOG 写事实。
- TEST_PLAN 引用局部证据并更新对应覆盖、失效和缺口。
- 影响旧正式 RUN 时追加失效标记，不覆盖历史。

某个 Chat 中断或接手，按范围读当前需求、活跃任务、相关 DEV/TC 和真实代码。已有未完成任务非本 Chat 所有时，用户明确接续或协调后转移归属；不以当前 Chat 的内存覆盖新计划。任务完成后，如实列出阻断及可继续的工作，无需独立交接文档。
